\doxysubsection{Detailed Description}
Give access to the real-\/time state of the joysticks. 

{\ttfamily \doxylink{namespacesf_1_1Joystick}{sf\+::\+Joystick}} provides an interface to the state of the joysticks. Each joystick is identified by an index that is passed to the functions in this namespace.

This namespace allows users to query the state of joysticks at any time and directly, without having to deal with a window and its events. Compared to the {\ttfamily Joystick\+Moved}, {\ttfamily Joystick\+Button\+Pressed} and {\ttfamily Joystick\+Button\+Released} events, {\ttfamily \doxylink{namespacesf_1_1Joystick}{sf\+::\+Joystick}} can retrieve the state of axes and buttons of joysticks at any time (you don\textquotesingle{}t need to store and update a boolean on your side in order to know if a button is pressed or released), and you always get the real state of joysticks, even if they are moved, pressed or released when your window is out of focus and no event is triggered.

SFML supports\+: \begin{DoxyItemize}
\item 8 joysticks ({\ttfamily sf\+::\+Joystick\+::\+Count}) \item 32 buttons per joystick ({\ttfamily sf\+::\+Joystick\+::\+Button\+Count}) \item 8 axes per joystick ({\ttfamily sf\+::\+Joystick\+::\+Axis\+Count})\end{DoxyItemize}
Unlike the keyboard or mouse, the state of joysticks is sometimes not directly available (depending on the OS), therefore an {\ttfamily \doxylink{namespacesf_1_1Joystick_a097f850647333c6d4ff8190bd841c631}{update()}} function must be called in order to update the current state of joysticks. When you have a window with event handling, this is done automatically, you don\textquotesingle{}t need to call anything. But if you have no window, or if you want to check joysticks state before creating one, you must call {\ttfamily \doxylink{namespacesf_1_1Joystick_a097f850647333c6d4ff8190bd841c631}{sf\+::\+Joystick\+::update}} explicitly.
