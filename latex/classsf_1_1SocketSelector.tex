\doxysubsection{Detailed Description}
Multiplexer that allows to read from multiple sockets. 

\doxylink{classsf_1_1Socket}{Socket} selectors provide a way to wait until data can be received or sent on a set of sockets, instead of just one. This is convenient when you have multiple sockets that may possibly receive data, but you don\textquotesingle{}t know which one will be ready first. In particular, it avoids to use a thread for each socket; with selectors, a single thread can handle all the sockets. When sending large amounts of data, the socket send buffer might fill up and you will have to wait for the data to actually be sent over the network connection before attempting to send more data.

All types of sockets can be used in a selector\+: \begin{DoxyItemize}
\item {\ttfamily \doxylink{classsf_1_1TcpListener}{sf\+::\+Tcp\+Listener}} \item {\ttfamily \doxylink{classsf_1_1TcpSocket}{sf\+::\+Tcp\+Socket}} \item {\ttfamily \doxylink{classsf_1_1UdpSocket}{sf\+::\+Udp\+Socket}}\end{DoxyItemize}
A selector doesn\textquotesingle{}t store its own copies of the sockets (socket classes are not copyable anyway), it simply keeps a reference to the original sockets that you pass to the "{}add"{} function. Therefore, you can\textquotesingle{}t use the selector as a socket container, you must store them outside and make sure that they are alive as long as they are used in the selector.

Using a selector is simple\+: \begin{DoxyItemize}
\item populate the selector with all the sockets that you want to observe \item make it wait until there is data available or data can be sent on any of the sockets \item test each socket to find out which ones are ready for receiving or sending\end{DoxyItemize}
If scalability is a concern, using callbacks is also possible\+: \begin{DoxyItemize}
\item add all the sockets that you want to observe to the selector with their own ready callbacks \item make the selector wait until there is data available or data can be sent on any of the sockets \item dispatch the callbacks of the sockets that became ready during the wait\end{DoxyItemize}

Add a new socket to the selector. 

The type of readiness to wait for can be specified. Specifying {\ttfamily \doxylink{classsf_1_1SocketSelector_acad2d08699208f9e3b38e395cab4017ea6e6be95bd56ee69eb433ff542abeec6d}{Socket\+Selector\+::\+Receive}} will wait for the socket to become ready to receive data from, specifying {\ttfamily \doxylink{classsf_1_1SocketSelector_acad2d08699208f9e3b38e395cab4017ea4e2260e7259808f3e8ee56dfcf03a1a4}{Socket\+Selector\+::\+Send}} will wait for the socket to become ready to send data on. Specifying {\ttfamily \doxylink{classsf_1_1SocketSelector_acad2d08699208f9e3b38e395cab4017ea6e6be95bd56ee69eb433ff542abeec6d}{Socket\+Selector\+::\+Receive} \texorpdfstring{$\vert$}{|} \doxylink{classsf_1_1SocketSelector_acad2d08699208f9e3b38e395cab4017ea4e2260e7259808f3e8ee56dfcf03a1a4}{Socket\+Selector\+::\+Send}} will wait for the socket to become either ready to send or receive data on.

Adding a socket after it has already been added will just overwrite the existing readiness type with the new value.

This function keeps a weak reference to the socket, so you have to make sure that the socket is not destroyed while it is stored in the selector. This function does nothing if the socket is not valid.

When adding a socket to the selector you can also attach a callback along with it. The callback is called by {\ttfamily dispatch\+Ready\+Callbacks} when a socket is determined to be ready after a call to {\ttfamily wait}.

Using attached callbacks instead of having to individually call {\ttfamily is\+Ready} on every socket after every call to {\ttfamily wait} allows for scaling up to a large number of sockets. This is because the overhead of checking for socket readiness using {\ttfamily is\+Ready} grows proportionally to the total number of sockets. When using callbacks calling {\ttfamily is\+Ready} on every socket is no longer necessary.

Because a socket can be ready for receiving, sending or both, the type of readiness is passed to the attached callback as a bitwise combination of {\ttfamily \doxylink{classsf_1_1SocketSelector_acad2d08699208f9e3b38e395cab4017ea6e6be95bd56ee69eb433ff542abeec6d}{Socket\+Selector\+::\+Receive}} and/or {\ttfamily \doxylink{classsf_1_1SocketSelector_acad2d08699208f9e3b38e395cab4017ea4e2260e7259808f3e8ee56dfcf03a1a4}{Socket\+Selector\+::\+Send}} when it is called by {\ttfamily dispatch\+Ready\+Callbacks}. Some systems don\textquotesingle{}t support combined read and write notifications. On these systems, if a socket is ready to be both received from and sent to the callback will be called twice, once with {\ttfamily \doxylink{classsf_1_1SocketSelector_acad2d08699208f9e3b38e395cab4017ea6e6be95bd56ee69eb433ff542abeec6d}{Socket\+Selector\+::\+Receive}} and once with {\ttfamily \doxylink{classsf_1_1SocketSelector_acad2d08699208f9e3b38e395cab4017ea4e2260e7259808f3e8ee56dfcf03a1a4}{Socket\+Selector\+::\+Send}}.

To remove the attached callback of a socket, call {\ttfamily add} again with an empty function.

By default, no readiness callback is attached when adding a socket.

void sf\+::\+Socket\+Selector\+::dispatch\+Ready\+Callbacks (\begin{DoxyParamCaption}{}{}\end{DoxyParamCaption})}



Dispatch callbacks of ready sockets. 

After calling {\ttfamily wait} returns {\ttfamily true}, at least one socket is ready to receive or send data. Calling {\ttfamily dispatch\+Ready\+Callbacks} will call the attached ready callback for every socket that is ready to either receive or send data. Sockets that don\textquotesingle{}t have a callback attached can still be individually checked using {\ttfamily is\+Ready}.

The readiness state of each socket is maintained until the next call to {\ttfamily wait}. Calling {\ttfamily dispatch\+Ready\+Callbacks} multiple times after a single call to {\ttfamily wait} will run the exact same callbacks with the exact same passed arguments.
