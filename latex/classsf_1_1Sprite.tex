\doxysubsection{Detailed Description}
\doxylink{classsf_1_1Drawable}{Drawable} representation of a texture, with its own transformations, color, etc. 

{\ttfamily \doxylink{classsf_1_1Sprite}{sf\+::\+Sprite}} is a drawable class that allows to easily display a texture (or a part of it) on a render target.

It inherits all the functions from {\ttfamily \doxylink{classsf_1_1Transformable}{sf\+::\+Transformable}}\+: position, rotation, scale, origin. It also adds sprite-\/specific properties such as the texture to use, the part of it to display, and some convenience functions to change the overall color of the sprite, or to get its bounding rectangle.

{\ttfamily \doxylink{classsf_1_1Sprite}{sf\+::\+Sprite}} works in combination with the {\ttfamily \doxylink{classsf_1_1Texture}{sf\+::\+Texture}} class, which loads and provides the pixel data of a given texture.

The separation of {\ttfamily \doxylink{classsf_1_1Sprite}{sf\+::\+Sprite}} and {\ttfamily \doxylink{classsf_1_1Texture}{sf\+::\+Texture}} allows more flexibility and better performances\+: indeed a {\ttfamily \doxylink{classsf_1_1Texture}{sf\+::\+Texture}} is a heavy resource, and any operation on it is slow (often too slow for real-\/time applications). On the other side, a {\ttfamily \doxylink{classsf_1_1Sprite}{sf\+::\+Sprite}} is a lightweight object which can use the pixel data of a {\ttfamily \doxylink{classsf_1_1Texture}{sf\+::\+Texture}} and draw it with its own transformation/color/blending attributes.

It is important to note that the {\ttfamily \doxylink{classsf_1_1Sprite}{sf\+::\+Sprite}} instance doesn\textquotesingle{}t copy the texture that it uses, it only keeps a reference to it. Thus, a {\ttfamily \doxylink{classsf_1_1Texture}{sf\+::\+Texture}} must not be destroyed while it is used by a {\ttfamily \doxylink{classsf_1_1Sprite}{sf\+::\+Sprite}} (i.\+e. never write a function that uses a local {\ttfamily \doxylink{classsf_1_1Texture}{sf\+::\+Texture}} instance for creating a sprite).

See also the note on coordinates and undistorted rendering in {\ttfamily \doxylink{classsf_1_1Transformable}{sf\+::\+Transformable}}.

Usage example\+:

\DoxyCodeLine{}

\DoxyCodeLine{sprite.setTextureRect(\{\{10,\ 10\},\ \{50,\ 30\}\});}
\DoxyCodeLine{sprite.setColor(\{255,\ 255,\ 255,\ 200\});}
\DoxyCodeLine{sprite.setPosition(\{100.f,\ 25.f\});}
\DoxyCodeLine{}
\DoxyCodeLine{\textcolor{comment}{//\ Draw\ it}}
\DoxyCodeLine{window.draw(sprite);}

\end{DoxyCode}

Change the source texture of the sprite. 

The {\ttfamily texture} argument refers to a texture that must exist as long as the sprite uses it. Indeed, the sprite doesn\textquotesingle{}t store its own copy of the texture, but rather keeps a pointer to the one that you passed to this function. If the source texture is destroyed and the sprite tries to use it, the behavior is undefined. If {\ttfamily reset\+Rect} is {\ttfamily true}, the {\ttfamily Texture\+Rect} property of the sprite is automatically adjusted to the size of the new texture. If it is {\ttfamily false}, the texture rect is left unchanged.
