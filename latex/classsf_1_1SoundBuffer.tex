\doxysubsection{Detailed Description}
Storage for audio samples defining a sound. 

A sound buffer holds the data of a sound, which is an array of audio samples. A sample is a 16 bit signed integer that defines the amplitude of the sound at a given time. The sound is then reconstituted by playing these samples at a high rate (for example, 44100 samples per second is the standard rate used for playing CDs). In short, audio samples are like texture pixels, and a {\ttfamily \doxylink{classsf_1_1SoundBuffer}{sf\+::\+Sound\+Buffer}} is similar to a {\ttfamily \doxylink{classsf_1_1Texture}{sf\+::\+Texture}}.

A sound buffer can be loaded from a file, from memory, from a custom stream (see {\ttfamily \doxylink{classsf_1_1InputStream}{sf\+::\+Input\+Stream}}) or directly from an array of samples. It can also be saved back to a file.

\doxylink{classsf_1_1Sound}{Sound} buffers alone are not very useful\+: they hold the audio data but cannot be played. To do so, you need to use the {\ttfamily \doxylink{classsf_1_1Sound}{sf\+::\+Sound}} class, which provides functions to play/pause/stop the sound as well as changing the way it is outputted (volume, pitch, 3D position, ...). This separation allows more flexibility and better performances\+: indeed a {\ttfamily \doxylink{classsf_1_1SoundBuffer}{sf\+::\+Sound\+Buffer}} is a heavy resource, and any operation on it is slow (often too slow for real-\/time applications). On the other side, a {\ttfamily \doxylink{classsf_1_1Sound}{sf\+::\+Sound}} is a lightweight object, which can use the audio data of a sound buffer and change the way it is played without actually modifying that data. Note that it is also possible to bind several {\ttfamily \doxylink{classsf_1_1Sound}{sf\+::\+Sound}} instances to the same {\ttfamily \doxylink{classsf_1_1SoundBuffer}{sf\+::\+Sound\+Buffer}}.

It is important to note that the {\ttfamily \doxylink{classsf_1_1Sound}{sf\+::\+Sound}} instance doesn\textquotesingle{}t copy the buffer that it uses, it only keeps a reference to it. Thus, a {\ttfamily \doxylink{classsf_1_1SoundBuffer}{sf\+::\+Sound\+Buffer}} must not be destructed while it is used by a {\ttfamily \doxylink{classsf_1_1Sound}{sf\+::\+Sound}} (i.\+e. never write a function that uses a local {\ttfamily \doxylink{classsf_1_1SoundBuffer}{sf\+::\+Sound\+Buffer}} instance for loading a sound).

When loading sound samples from an array, a channel map needs to be provided, which specifies the mapping of the position in the sample frame to the sound channel. For example when you have six samples in a frame and a 5.\+1 sound system, the channel map defines how each of those samples map to which speaker channel.
