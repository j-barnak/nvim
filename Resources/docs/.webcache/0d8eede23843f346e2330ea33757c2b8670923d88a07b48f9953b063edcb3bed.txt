# drgn

## Synopsis

**drgn** \[*OPTION*…\]

**drgn** \[*OPTION*…\] *SCRIPT* \[*ARGUMENT*…\]

**drgn** \[*OPTION*…\] **-e** *CODE* \[*ARGUMENT*…\]

## Description

**drgn** (pronounced “dragon”) is a debugger with an emphasis on programmability. It provides APIs for using the types, variables, and stack traces in a program or core dump from Python, allowing for easy, expressive scripting and more complex debugging.

Full documentation is available online at [https://drgn.readthedocs.io/](https://drgn.readthedocs.io/).

For in-program documentation, try `help(drgn)`.

## Options

If no positional arguments are given (and [`-e`](#cmdoption-drgn-e) is not given), then drgn runs in *interactive mode*: commands are read from the terminal. Relevant helpers are automatically imported. An empty string is prepended to [`sys.path`](https://docs.python.org/3/library/sys.html#sys.path "(in Python v3.14)").

If positional arguments are given (and [`-e`](#cmdoption-drgn-e) is not given), then drgn runs in *script mode*: *SCRIPT* is executed with the given *ARGUMENT*s. Nothing is imported automatically. [`sys.argv[0]`](https://docs.python.org/3/library/sys.html#sys.argv "(in Python v3.14)") is set to *SCRIPT* and the remaining arguments are added to [`sys.argv`](https://docs.python.org/3/library/sys.html#sys.argv "(in Python v3.14)"). The parent directory of *SCRIPT* is prepended to [`sys.path`](https://docs.python.org/3/library/sys.html#sys.path "(in Python v3.14)").

-e *CODE*  
Evaluate the given code and exit. Relevant helpers are automatically imported. [`sys.argv[0]`](https://docs.python.org/3/library/sys.html#sys.argv "(in Python v3.14)") is set to *-e* and the remaining arguments are added to [`sys.argv`](https://docs.python.org/3/library/sys.html#sys.argv "(in Python v3.14)"). An empty string is prepended to [`sys.path`](https://docs.python.org/3/library/sys.html#sys.path "(in Python v3.14)").

### Program Selection

One of these options may be given to specify what program to debug.

-k, --kernel  
Debug the running kernel. This is the default.

&nbsp;

-c, --core *PATH*  
Debug the given core dump.

&nbsp;

-p, --pid *PID*  
Debug the running process with the given process ID.

&nbsp;

--qemu *ADDRESS*  
Debug a QEMU guest over the QEMU Machine Protocol (QMP) at the given address, which may be a Unix domain socket path or a TCP address as `host:port`.

### Debugging Symbols

-s, --symbols *PATH*  
Load debugging symbols from the given file. If the file does not correspond to a loaded executable, library, or module, then a warning is printed and it is ignored; see [`--extra-symbols`](#cmdoption-drgn-extra-symbols) for an alternative.

This option may be given more than once.

&nbsp;

--main-symbols  
Only load debugging symbols for the main executable and those added with [`-s`](#cmdoption-drgn-s) or [`--extra-symbols`](#cmdoption-drgn-extra-symbols).

&nbsp;

--no-default-symbols  
Don’t load any debugging symbols that were not explicitly added with [`-s`](#cmdoption-drgn-s) or [`--extra-symbols`](#cmdoption-drgn-extra-symbols).

&nbsp;

--extra-symbols *PATH*  
Load additional debugging symbols from the given file, which is assumed not to correspond to a loaded executable, library, or module.

This option may be given more than once.

The following options correspond to [`drgn.Program.debug_info_options`](https://drgn.readthedocs.io/en/latest/api_reference.html#drgn.Program.debug_info_options "drgn.Program.debug_info_options") in the Python API.

--try-symbols-by *METHOD\[,METHOD...\]*  
Enable loading debugging symbols using the given methods. *METHOD* may be:

- The name of a debugging information finder (`standard`, `debuginfod`, or any added by plugins).

- `module-name`: if the name of a module looks like a filesystem path, try the file at that path.

- `build-id`: search by build ID.

- `debug-link`: search by debug link (e.g., `.gnu_debuglink`).

- `procfs`: try `/proc/`*`pid`*`/exe` or `/proc/`*`pid`*`/map_files`.

- `embedded-vdso`: try vDSO data saved in a core dump.

- `reuse`: try reusing a previously used file.

- `supplementary`: try finding supplementary files (e.g., `.gnu_debugaltlink`).

- `kmod=depmod`: search using *depmod* metadata.

- `kmod=walk`: search by walking kernel directories.

- `kmod=depmod-or-walk`: search using *depmod* metadata if it is available or by walking kernel directories if *depmod* metadata does not exist.

- `kmod=depmod-and-walk`: search using *depmod* metadata if it is available, then by walking kernel directories if *depmod* metadata does not exist or does not contain the desired module.

Multiple methods may be enabled by passing a comma-separated list. This option may be given more than once, in which case the lists will be combined.

&nbsp;

--no-symbols-by *METHOD\[,METHOD...\]*  
Disable loading debugging symbols using the given methods. *METHOD* may be the name of a debugging information finder, `module-name`, `build-id`, `debug-link`, `procfs`, `embedded-vdso`, `reuse`, `supplementary`, or `kmod`.

Multiple methods may be disabled by passing a comma-separated list. This option may be given more than once, in which case the lists will be combined.

### Debugging Symbol Directories

These options correspond to [`drgn.DebugInfoOptions.directories`](https://drgn.readthedocs.io/en/latest/api_reference.html#drgn.DebugInfoOptions.directories "drgn.DebugInfoOptions.directories") in the Python API.

--debug-directory *PATH*  
Search for debugging symbols in the given directory.

By default, these directories are used for searches by build ID, debug link, for supplementary files, and for kernel files.

This option may be given more than once to search in multiple directories.

&nbsp;

--no-default-debug-directories  
Don’t search for debugging symbols in the standard directories or those added by plugins.

These options correspond to [`drgn.DebugInfoOptions.debug_link_directories`](https://drgn.readthedocs.io/en/latest/api_reference.html#drgn.DebugInfoOptions.debug_link_directories "drgn.DebugInfoOptions.debug_link_directories") in the Python API.

--debug-link-directory *PATH*  
Search for debugging symbols by debug link in the given directory.

`$ORIGIN` (or `${ORIGIN}`) is replaced with the absolute path of the directory containing the loaded file.

This option may be given more than once to search in multiple directories.

&nbsp;

--no-default-debug-link-directories  
Don’t search for debugging symbols by debug link in the standard directories or those added by plugins.

These options correspond to [`drgn.DebugInfoOptions.kernel_directories`](https://drgn.readthedocs.io/en/latest/api_reference.html#drgn.DebugInfoOptions.kernel_directories "drgn.DebugInfoOptions.kernel_directories") in the Python API.

--kernel-directory *PATH*  
Search for the kernel image and loadable kernel modules in the given directory.

This option may be given more than once to search in multiple directories.

&nbsp;

--no-default-kernel-directories  
Don’t search for the kernel image and loadable kernel modules in the standard directories or those added by plugins.

### Logging

--log-level *{debug,info,warning,error,critical,none}*  
Log messages of at least the given level to standard error. The default is *warning*.

&nbsp;

-q, --quiet  
Don’t print any logs or download progress. This is equivalent to [`--log-level`` ``none`](#cmdoption-drgn-log-level).

### Generic Information

-h, --help  
Show a help message and exit.

&nbsp;

--version  
Show **drgn**’s version information and exit.
