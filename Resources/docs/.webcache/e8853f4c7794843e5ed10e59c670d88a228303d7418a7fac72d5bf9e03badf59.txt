ⓘ *This trait cannot be implemented outside `std`.*

Available on **Unix** only.

Expand description

Unix-specific extensions to [`ExitStatus`](https://doc.rust-lang.org/std/process/struct.ExitStatus.html "struct std::process::ExitStatus") and [`ExitStatusError`](https://doc.rust-lang.org/std/process/struct.ExitStatusError.html "struct std::process::ExitStatusError").

On Unix, [`ExitStatus`](https://doc.rust-lang.org/std/process/struct.ExitStatus.html "struct std::process::ExitStatus") **does not necessarily represent an exit status**, as passed to the `_exit` system call or returned by [`ExitStatus::code()`](https://doc.rust-lang.org/std/process/struct.ExitStatus.html#method.code "method std::process::ExitStatus::code"). It represents **any wait status** as returned by one of the [`wait`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/wait.html) family of system calls.

A Unix wait status (a Rust [`ExitStatus`](https://doc.rust-lang.org/std/process/struct.ExitStatus.html "struct std::process::ExitStatus")) can represent a Unix exit status, but can also represent other kinds of process event.

## Required Methods

1.12.0 · [Source](https://doc.rust-lang.org/src/std/os/unix/process.rs.html#346)

Creates a new [`ExitStatus`](https://doc.rust-lang.org/std/process/struct.ExitStatus.html "struct std::process::ExitStatus") or [`ExitStatusError`](https://doc.rust-lang.org/std/process/struct.ExitStatusError.html "struct std::process::ExitStatusError") from the raw underlying integer status value from [`wait`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/wait.html).

The value should be a **wait status, not an exit status**.

##### Example

A signal-terminated [`wait`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/wait.html) status carries the signal number, which [`ExitStatus::signal`](https://doc.rust-lang.org/std/process/struct.ExitStatus.html#method.signal "method std::process::ExitStatus::signal") recovers using the platform’s [`WTERMSIG`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/wait.html) macro. Note that the bit layout of a wait status is **not** specified by POSIX and is platform-specific. By convention on most Unix platforms, the signal number occupies the low 7 bits with the exit-code byte left zero, so a bare signal number between 1 and 126 is treated as a signal-terminated wait status. The following example relies on that convention and is therefore not guaranteed to hold on every target:

``` rust
use std::os::unix::process::ExitStatusExt;
use std::process::ExitStatus;

let signal = 15; // SIGTERM
assert!(signal > 0 && signal < 0x7f, "not a valid Unix termination signal: {signal}");

let status = ExitStatus::from_raw(signal);
assert!(!status.success());
assert_eq!(status.code(), None);
assert_eq!(status.signal(), Some(15));
```

Generating an [`ExitStatus`](https://doc.rust-lang.org/std/process/struct.ExitStatus.html "struct std::process::ExitStatus") with a given exit code (0-255) is system-dependent. The value returned by [`ExitStatus::code`](https://doc.rust-lang.org/std/process/struct.ExitStatus.html#method.code "method std::process::ExitStatus::code") is specified to come from applying the [`WEXITSTATUS`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/wait.html) macro, but there is no POSIX-specified constructor and the bit layout is left unspecified. By near-universal convention every Unix libc stores the 8-bit exit code in bits 8..16, so a status built with `(code & 0xff) << 8` will usually round-trip back to the original exit code:

``` rust
use std::os::unix::process::ExitStatusExt;
use std::process::ExitStatus;

let code = 41;
let status = ExitStatus::from_raw((code & 0xff) << 8);
assert_eq!(status.code(), Some(41));
assert!(!status.success());
```

##### Panics

- `ExitStatusError::from_raw` panics on an attempt to make an [`ExitStatusError`](https://doc.rust-lang.org/std/process/struct.ExitStatusError.html "struct std::process::ExitStatusError") from a [`wait`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/wait.html) status of `0`.
- `ExitStatus::from_raw` always succeeds and never panics.

1.0.0 · [Source](https://doc.rust-lang.org/src/std/os/unix/process.rs.html#377)

If the process was terminated by a signal, returns that signal.

In other words, if [`WIFSIGNALED`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/wait.html), this returns [`WTERMSIG`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/wait.html). For such a status, [`ExitStatus::code`](https://doc.rust-lang.org/std/process/struct.ExitStatus.html#method.code "method std::process::ExitStatus::code") returns `None`:

``` rust
use std::os::unix::process::ExitStatusExt;
use std::process::ExitStatus;

let sigterm = 15;
let status = ExitStatus::from_raw(sigterm);
assert_eq!(status.code(), None);
assert_eq!(status.signal(), Some(sigterm));
```

A process that receives a signal may catch and handle it, then exit normally with an exit code. When that happens, `signal` returns `None`.

Rust does not pass commands through a shell, such as `bash` and `sh`, but it is possible to do so manually. When invoking a shell, the signal value indicates whether the top-level shell itself received a terminating signal. If instead a command *within* an invoked shell receives a terminating signal, many shells convert the signal number into an exit code by adding 128. For example, a command run under `sh` that receives a [`SIGTERM`](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/kill.html) canonically causes the shell to report an exit code of `15 + 128`, i.e. `143`.

If the process was stopped by a signal, returns that signal.

In other words, if [`WIFSTOPPED`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/wait.html), this returns [`WSTOPSIG`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/wait.html). This is only possible if the status came from a [`wait`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/wait.html) system call which was passed [`WUNTRACED`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/wait.html), and was then converted into an [`ExitStatus`](https://doc.rust-lang.org/std/process/struct.ExitStatus.html "struct std::process::ExitStatus").
