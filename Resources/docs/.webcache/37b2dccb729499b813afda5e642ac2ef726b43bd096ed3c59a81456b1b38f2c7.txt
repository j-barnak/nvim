- [↑](https://wiki.osdev.org/Tool_Comparison#ref_1)  using the `.intel_syntax` directive. Several opcodes will still use the AT&T name.
- [↑](https://wiki.osdev.org/Tool_Comparison#ref_2)  While GAS normally writes only "pure" 32-bit i386 code, it has [limited support](http://sourceware.org/binutils/docs/as/i386_002d16bit.html) for writing code to run in real mode or in 16-bit protected mode code segments.
- [↑](https://wiki.osdev.org/Tool_Comparison#ref_3)  You have to choose the instruction set at compile time (of the assembler). GAS can not assemble for more than one operating mode at a time, i.e. you would need one GAS for 32bit and one GAS for 64bit if you'd want to mix those two.
- [↑](https://wiki.osdev.org/Tool_Comparison#ref_4)  64-bit support is only available in NASM 2.x.
- [↑](https://wiki.osdev.org/Tool_Comparison#ref_5)  64-bit support is only available in a separate executable, named ml64.
- [↑](https://wiki.osdev.org/Tool_Comparison#ref_6)  Sol_Asm uses its own syntax, which looks like the Intel syntax.
