## The Rust Core Library

The Rust Core Library is the dependency-free^([1](#fn1)) foundation of [The Rust Standard Library](https://doc.rust-lang.org/std/index.html). It is the portable glue between the language and its libraries, defining the intrinsic and primitive building blocks of all Rust code. It links to no upstream libraries, no system libraries, and no libc.

The core library is *minimal*: it isn’t even aware of heap allocation, nor does it provide concurrency or I/O. These things require platform integration, and this library is platform-agnostic.

## How to use the core library

Please note that all of these details are currently not considered stable.

This library is built on the assumption of a few existing symbols:

- `memcpy`, `memmove`, `memset`, `memcmp`, `bcmp`, `strlen` - These are core memory routines which are generated by Rust codegen backends. Additionally, this library can make explicit calls to `strlen`. Their signatures are the same as found in C, but there are extra assumptions about their semantics: For `memcpy`, `memmove`, `memset`, `memcmp`, and `bcmp`, if the `n` parameter is 0, the function is assumed to not be UB, even if the pointers are NULL or dangling. (Note that making extra assumptions about these functions is common among compilers: [clang](https://reviews.llvm.org/D86993) and [GCC](https://gcc.gnu.org/onlinedocs/gcc/Standards.html#C-Language) do the same.) These functions are often provided by the system libc, but can also be provided by the [compiler-builtins crate](https://crates.io/crates/compiler_builtins). Note that the library does not guarantee that it will always make these assumptions, so Rust user code directly calling the C functions should follow the C specification! The advice for Rust user code is to call the functions provided by this library instead (such as `ptr::copy`).

- Panic handler - This function takes one argument, a `&panic::PanicInfo`. It is up to consumers of this core library to define this panic function; it is only required to never return. You should mark your implementation using `#[panic_handler]`.

- `rust_eh_personality` - is used by the failure mechanisms of the compiler. This is often mapped to GCC’s personality function, but crates which do not trigger a panic can be assured that this function is never called. The `lang` attribute is called `eh_personality`.

[for](https://doc.rust-lang.org/core/keyword.for.html "keyword core::for")  
Iteration with [`in`](https://doc.rust-lang.org/core/keyword.in.html), trait implementation with [`impl`](https://doc.rust-lang.org/core/keyword.impl.html), or [higher-ranked trait bounds](https://doc.rust-lang.org/reference/trait-bounds.html#higher-ranked-trait-bounds) (`for<'a>`).

[if](https://doc.rust-lang.org/core/keyword.if.html "keyword core::if")  
Evaluate a block if a condition holds.

[impl](https://doc.rust-lang.org/core/keyword.impl.html "keyword core::impl")  
Implementations of functionality for a type, or a type implementing some functionality.

[in](https://doc.rust-lang.org/core/keyword.in.html "keyword core::in")  
Iterate over a series of values with [`for`](https://doc.rust-lang.org/core/keyword.for.html).

[let](https://doc.rust-lang.org/core/keyword.let.html "keyword core::let")  
Bind a value to a variable.

[loop](https://doc.rust-lang.org/core/keyword.loop.html "keyword core::loop")  
Loop indefinitely.

[match](https://doc.rust-lang.org/core/keyword.match.html "keyword core::match")  
Control flow based on pattern matching.

[mod](https://doc.rust-lang.org/core/keyword.mod.html "keyword core::mod")  
Organize code into [modules](https://doc.rust-lang.org/reference/items/modules.html).

[move](https://doc.rust-lang.org/core/keyword.move.html "keyword core::move")  
Capture a [closure](https://doc.rust-lang.org/book/ch13-01-closures.html)’s environment by value.

[mut](https://doc.rust-lang.org/core/keyword.mut.html "keyword core::mut")  
A mutable variable, reference, or pointer.

[pub](https://doc.rust-lang.org/core/keyword.pub.html "keyword core::pub")  
Make an item visible to others.

[ref](https://doc.rust-lang.org/core/keyword.ref.html "keyword core::ref")  
Bind by reference during pattern matching.

[return](https://doc.rust-lang.org/core/keyword.return.html "keyword core::return")  
Returns a value from a function.

[self](https://doc.rust-lang.org/core/keyword.self.html "keyword core::self")  
The receiver of a method, or the current module.

[static](https://doc.rust-lang.org/core/keyword.static.html "keyword core::static")  
A static item is a value which is valid for the entire duration of your program (a `'static` lifetime).

[struct](https://doc.rust-lang.org/core/keyword.struct.html "keyword core::struct")  
A type that is composed of other types.

[super](https://doc.rust-lang.org/core/keyword.super.html "keyword core::super")  
The parent of the current [module](https://doc.rust-lang.org/reference/items/modules.html).

[trait](https://doc.rust-lang.org/core/keyword.trait.html "keyword core::trait")  
A common interface for a group of types.

[true](https://doc.rust-lang.org/core/keyword.true.html "keyword core::true")  
A value of type [`bool`](https://doc.rust-lang.org/core/primitive.bool.html "primitive bool") representing logical **true**.

[type](https://doc.rust-lang.org/core/keyword.type.html "keyword core::type")  
Define an [alias](https://doc.rust-lang.org/reference/items/type-aliases.html) for an existing type.

[union](https://doc.rust-lang.org/core/keyword.union.html "keyword core::union")  
The [Rust equivalent of a C-style union](https://doc.rust-lang.org/reference/items/unions.html).

[unsafe](https://doc.rust-lang.org/core/keyword.unsafe.html "keyword core::unsafe")  
Code or interfaces whose [memory safety](https://doc.rust-lang.org/book/ch19-01-unsafe-rust.html) cannot be verified by the type system.

[use](https://doc.rust-lang.org/core/keyword.use.html "keyword core::use")  
Import or rename items from other crates or modules, use values under ergonomic clones semantic, or specify precise capturing with `use<..>`.

[where](https://doc.rust-lang.org/core/keyword.where.html "keyword core::where")  
Add constraints that must be upheld to use an item.

[while](https://doc.rust-lang.org/core/keyword.while.html "keyword core::while")  
Loop while a condition is upheld.

## Attributes

[allow](https://doc.rust-lang.org/core/attribute.allow.html "attribute core::allow")  
The `allow` attribute suppresses lint diagnostics that would otherwise produce warnings or errors. It can be used on any lint or lint group (except those set to [`forbid`](https://doc.rust-lang.org/core/attribute.forbid.html)).

[cfg](https://doc.rust-lang.org/core/attribute.cfg.html "attribute core::cfg")  
Used for conditional compilation.

[deny](https://doc.rust-lang.org/core/attribute.deny.html "attribute core::deny")  
Emits an error, preventing the compilation from finishing, when a lint check has failed. This is useful for enforcing rules or preventing certain patterns:

[deprecated](https://doc.rust-lang.org/core/attribute.deprecated.html "attribute core::deprecated")  
Emits a warning during compilation when an item with this attribute is used. `since` and `note` are optional fields giving more detail about why the item is deprecated.

[forbid](https://doc.rust-lang.org/core/attribute.forbid.html "attribute core::forbid")  
Emits an error, preventing the compilation from finishing, when a lint check has failed.

[must_use](https://doc.rust-lang.org/core/attribute.must_use.html "attribute core::must_use")  
Warn when a value is ignored.

[warn](https://doc.rust-lang.org/core/attribute.warn.html "attribute core::warn")  
Emits a warning during compilation when a lint check failed.
