# Function sync_channel Copy item path

1.0.0 · [Source](https://doc.rust-lang.org/src/std/sync/mpsc.rs.html#572-575)

``` rust
pub fn sync_channel<T>(bound: usize) -> (SyncSender<T>, Receiver<T>)
```

Expand description

Creates a new synchronous, bounded channel.

All data sent on the [`SyncSender`](https://doc.rust-lang.org/std/sync/mpsc/struct.SyncSender.html "struct std::sync::mpsc::SyncSender") will become available on the [`Receiver`](https://doc.rust-lang.org/std/sync/mpsc/struct.Receiver.html "struct std::sync::mpsc::Receiver") in the same order as it was sent. Like asynchronous [`channel`](https://doc.rust-lang.org/std/sync/mpsc/fn.channel.html "fn std::sync::mpsc::channel")s, the [`Receiver`](https://doc.rust-lang.org/std/sync/mpsc/struct.Receiver.html "struct std::sync::mpsc::Receiver") will block until a message becomes available. `sync_channel` differs greatly in the semantics of the sender, however.

This channel has an internal buffer on which messages will be queued. `bound` specifies the buffer size. When the internal buffer becomes full, future sends will *block* waiting for the buffer to open up. Note that a buffer size of 0 is valid, in which case this becomes “rendezvous channel” where each [`send`](https://doc.rust-lang.org/std/sync/mpsc/struct.SyncSender.html#method.send "method std::sync::mpsc::SyncSender::send") will not return until a [`recv`](https://doc.rust-lang.org/std/sync/mpsc/struct.Receiver.html#method.recv "method std::sync::mpsc::Receiver::recv") is paired with it.

The [`SyncSender`](https://doc.rust-lang.org/std/sync/mpsc/struct.SyncSender.html "struct std::sync::mpsc::SyncSender") can be cloned to [`send`](https://doc.rust-lang.org/std/sync/mpsc/struct.SyncSender.html#method.send "method std::sync::mpsc::SyncSender::send") to the same channel multiple times, but only one [`Receiver`](https://doc.rust-lang.org/std/sync/mpsc/struct.Receiver.html "struct std::sync::mpsc::Receiver") is supported.

Like asynchronous channels, if the [`Receiver`](https://doc.rust-lang.org/std/sync/mpsc/struct.Receiver.html "struct std::sync::mpsc::Receiver") is disconnected while trying to [`send`](https://doc.rust-lang.org/std/sync/mpsc/struct.SyncSender.html#method.send "method std::sync::mpsc::SyncSender::send") with the [`SyncSender`](https://doc.rust-lang.org/std/sync/mpsc/struct.SyncSender.html "struct std::sync::mpsc::SyncSender"), the [`send`](https://doc.rust-lang.org/std/sync/mpsc/struct.SyncSender.html#method.send "method std::sync::mpsc::SyncSender::send") method will return a [`SendError`](https://doc.rust-lang.org/std/sync/mpsc/struct.SendError.html "struct std::sync::mpsc::SendError"). Similarly, If the [`SyncSender`](https://doc.rust-lang.org/std/sync/mpsc/struct.SyncSender.html "struct std::sync::mpsc::SyncSender") is disconnected while trying to [`recv`](https://doc.rust-lang.org/std/sync/mpsc/struct.Receiver.html#method.recv "method std::sync::mpsc::Receiver::recv"), the [`recv`](https://doc.rust-lang.org/std/sync/mpsc/struct.Receiver.html#method.recv "method std::sync::mpsc::Receiver::recv") method will return a [`RecvError`](https://doc.rust-lang.org/std/sync/mpsc/struct.RecvError.html "struct std::sync::mpsc::RecvError").

## Examples

``` rust
use std::sync::mpsc::sync_channel;
use std::thread;

let (sender, receiver) = sync_channel(1);

// this returns immediately
sender.send(1).unwrap();

thread::spawn(move || {
    // this will block until the previous message has been received
    sender.send(2).unwrap();
});

assert_eq!(receiver.recv().unwrap(), 1);
assert_eq!(receiver.recv().unwrap(), 2);
```
