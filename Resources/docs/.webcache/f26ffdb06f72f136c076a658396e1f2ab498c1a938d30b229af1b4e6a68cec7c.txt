# Types

*class *drgn.Type  
A `Type` object describes a type in a program. Each kind of type (e.g., integer, structure) has different attributes (e.g., name, size). Types can also have qualifiers (e.g., constant, atomic). Accessing an attribute which does not apply to a type raises an [`AttributeError`](https://docs.python.org/3/library/exceptions.html#AttributeError "(in Python v3.14)").

[`repr()`](https://docs.python.org/3/library/functions.html#repr "(in Python v3.14)") of a `Type` returns a Python representation of the type:

    >>> print(repr(prog.type('sector_t')))
    prog.typedef_type(name='sector_t', type=prog.int_type(name='unsigned long', size=8, is_signed=False))

[`str()`](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)") returns a representation of the type in programming language syntax:

    >>> print(prog.type('sector_t'))
    typedef unsigned long sector_t

The drgn CLI is set up so that types are displayed with `str()` instead of `repr()` by default.

This class cannot be constructed directly. Instead, use one of the [Type Constructors](#api-type-constructors).

unaliased() → [Type](#drgn.Type "drgn.Type")  
Get a copy of this type with all top-level typedefs removed.

For example, given the following typedefs:

    typedef long long __kernel_loff_t;
    typedef __kernel_loff_t loff_t;

Then:

    >>> print(prog.type("loff_t").unaliased())
    long long

But in this example:

    typedef loff_t *loffp_t;

Only `loffp_t` is at the top level, not `loff_t`:

    >>> print(prog.type("loffp_t").unaliased())
    loff_t *

Get the kind of this type with all typedefs removed.

This is a shortcut for [`Type.unaliased().kind`](#drgn.Type.unaliased "drgn.Type.unaliased").

*class *drgn.TypeEnumerator

    >>> prog.type('enum pid_type').enumerators[0].name

Note

> 1.  The argument was omitted entirely and thus defaulted to the default argument.
>
> 2.  The (specified or defaulted) argument is the same as the default argument.

Compilers are inconsistent about which interpretation they use.

GCC added this information in version 4.9. Clang added it in version 11 (and only when emitting DWARF version 5). If the program was compiled by an older version, this is always false.

This corresponds to [`offsetof()`](https://en.cppreference.com/w/c/types/offsetof) in C.

Parameters:  
- **type** – Structure, union, or class type. If given as a string, it is looked up in the [default program](#default-program).

- **member** – Name of member. May include one or more member references and zero or more array subscripts.

Raises:  
- [**TypeError**](https://docs.python.org/3/library/exceptions.html#TypeError "(in Python v3.14)") – if *type* is not a structure, union, or class type

- [**ValueError**](https://docs.python.org/3/library/exceptions.html#ValueError "(in Python v3.14)") – if the member is not byte-aligned (e.g., because it is a bit field)

- [**LookupError**](https://docs.python.org/3/library/exceptions.html#LookupError "(in Python v3.14)") – if *type* does not have a member with the given name
