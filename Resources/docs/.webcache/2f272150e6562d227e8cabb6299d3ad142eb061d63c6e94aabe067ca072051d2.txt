Hi,

In *general*, all I/O ports are either part of a legacy/[ISA](https://wiki.osdev.org/ISA "ISA") device ([serial ports](https://wiki.osdev.org/Serial_ports "Serial ports"), [parallel ports](https://wiki.osdev.org/Parallel_port "Parallel port"), [PS/2 keyboard](https://wiki.osdev.org/PS2_Keyboard "PS2 Keyboard"), [floppy](https://wiki.osdev.org/Floppy_Disk_Controller "Floppy Disk Controller"), [CMOS](https://wiki.osdev.org/CMOS "CMOS")) and/or part of the chipset, or part of a [PCI](https://wiki.osdev.org/PCI "PCI") device. Regardless of what it is you need the documentation for the specific thing (for e.g. for "XYZ ethernet card" you'd need the documentation for "XYZ ethernet card", and the documentation for "ABC ethernet card" will be useless).

##### Legacy Hardware And Backwards Compatibility

In some cases there's a legacy hardware interface for backward compatibility - for e.g. most video cards support the old [VGA](https://wiki.osdev.org/VGA "VGA") I/O ports (until you put them into "native mode" so you can actually use most of it's features). These legacy interfaces are probably worth supporting until you've got proper device drivers. In this case you need the documentation for the legacy device (rather than the documentation for the correct/actual device). For e.g. for a "top of the line" ATI video card you'd want IBM's original [VGA](https://wiki.osdev.org/VGA "VGA") documentation (or equivalent information).

##### Legacy Software Interfaces

Also, for some devices there's a legacy software interface. This is mostly limited to video cards though (the [VESA/VBE](https://wiki.osdev.org/VGA_Resources "VGA Resources") interface) because the rest is too crappy^(\[*how?*\]) (no sane person uses the BIOS for [serial ports](https://wiki.osdev.org/Serial_ports "Serial ports"), [parallel ports](https://wiki.osdev.org/Parallel_port "Parallel port"), [PS/2 keyboard](https://wiki.osdev.org/PS2_Keyboard "PS2 Keyboard"), [floppy](https://wiki.osdev.org/Floppy_Disk_Controller "Floppy Disk Controller"), or [hard drives](https://wiki.osdev.org/ATA_PIO_Mode "ATA PIO Mode")^(\[*why?*\]) even though it's possible in theory). Like the "legacy hardware interface", this is mostly just a short-term solution (basic functionality with no extra features and poor performance^(\[*how?*\])).

##### Standard Interfaces

Lastly, for some device types there's a standard interface. This includes [USB](https://wiki.osdev.org/USB "USB") controllers (AFAIK there's only 4 different standards for this - [UHCI](https://wiki.osdev.org/UHCI "UHCI"), [EHCI](https://wiki.osdev.org/EHCI "EHCI"), [XHCI](https://wiki.osdev.org/XHCI "XHCI") and [OHCI](https://wiki.osdev.org/OHCI "OHCI")) and [IDE](https://wiki.osdev.org/IDE "IDE")/[ATAPI](https://wiki.osdev.org/ATAPI "ATAPI") hard disk controllers (but not [SCSI](https://wiki.osdev.org/SCSI "SCSI") controllers), and not much else. These standard interfaces are actually good interface (not legacy interfaces).

##### Supporting Devices Is Difficult

Mostly, to support all devices properly (without using legacy interfaces) you need to read through thousands of pieces of documentation and write thousands of different device drivers (and no, there are not thousands of guides, one for each device, or any other "hand holding" - you need to find, read and understand the manufacturer's documentation).

##### Keep It Minimal

Fortunately (IMHO), for a good OS design you don't actually need to write many device drivers^(\[*according to who?*\]) (a few common drivers to get things started perhaps). You only really need to design, implement and document suitable device driver interface/s, so that other programmers can easily write the device drivers later. For example, you might write one device driver for one [ethernet](https://wiki.osdev.org/index.php?title=Ethernet&action=edit&redlink=1 "Ethernet (page does not exist)") card, and (hopefully, one day) twenty more people might use your [documentation](https://wiki.osdev.org/index.php?title=Documentation&action=edit&redlink=1 "Documentation (page does not exist)") (and your first device driver, as a reference) to implement fifty more device [drivers](https://wiki.osdev.org/index.php?title=Drivers&action=edit&redlink=1 "Drivers (page does not exist)") for fifty more [ethernet](https://wiki.osdev.org/index.php?title=Ethernet&action=edit&redlink=1 "Ethernet (page does not exist)") cards.

Basically what I'm saying is that (IMHO) sane OS developers don't actually write an OS. Instead they write [Bootloaders](https://wiki.osdev.org/Bootloader "Bootloader"), [kernels](https://wiki.osdev.org/Kernels "Kernels"), and [documentation](https://wiki.osdev.org/index.php?title=Documentation&action=edit&redlink=1 "Documentation (page does not exist)"). Only after the [kernel](https://wiki.osdev.org/Kernels "Kernels") and [documentation](https://wiki.osdev.org/index.php?title=Documentation&action=edit&redlink=1 "Documentation (page does not exist)") are entirely complete do they worry about device [drivers](https://wiki.osdev.org/index.php?title=Drivers&action=edit&redlink=1 "Drivers (page does not exist)"), [file systems](https://wiki.osdev.org/File_Systems "File Systems"), [applications](https://wiki.osdev.org/index.php?title=Applications&action=edit&redlink=1 "Applications (page does not exist)"), etc (except for some common/special case stuff that they need to test the kernel and the kernel's interfaces).

## Question: Shutdown, Graphics, Network, and Others

But, now when I want to add shutdown, graphics mode, network and other things, its getting a little painful.

##### Shutdown (APM or ACPI)

For shutdown there's 2 different "legacy software interfaces" ([APM](https://wiki.osdev.org/APM "APM") and [ACPI](https://wiki.osdev.org/ACPI "ACPI")). [APM](https://wiki.osdev.org/APM "APM") is old but simple, while [ACPI](https://wiki.osdev.org/ACPI "ACPI") is new but a huge over-complicated pain in the neck. To do it without these legacy software interfaces you'd need to see the documentation for each motherboard/chipset.

##### Video (BIOS, VESA/VBE, VGA Interface, or Native)

For video there's 2 legacy software interfaces (the original [BIOS](https://wiki.osdev.org/BIOS "BIOS") Int 0x10 interface, and the [VESA/VBE](https://wiki.osdev.org/VGA_Resources "VGA Resources") extensions), plus one legacy hardware interface (the "[VGA standard](https://wiki.osdev.org/VGA_Resources "VGA Resources")"). To do it properly you need programming information for each video card (which can be very difficult to obtain in some cases). Even if you do have good information a modern video a device driver is complex (especially if you start looking at 3D special effects and implementing a JIT compiler for shader language - e.g. similar features and performance to DirectX 10), and it could easily take over a year to implement a good device driver for one video card.

##### Network Cards

For [network cards](https://wiki.osdev.org/Category:Network_Hardware "Category:Network Hardware") there is no legacy software interface and no legacy hardware interface - to do it properly you need the manufacturer's documentation (or equivalent documentation).
