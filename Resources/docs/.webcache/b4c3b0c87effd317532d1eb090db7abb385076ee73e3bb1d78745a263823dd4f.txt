In the second [jsonic](https://beautifulracket.com/jsonic-2/) tutorial, we made the language safer to use by adding [contracts](https://beautifulracket.com/explainer/contracts.html) and [unit tests](https://beautifulracket.com/explainer/unit-tests.html). We made it easier to use by integrating the language with the DrRacket IDE.

Suppose we now want to share our [jsonic](https://beautifulracket.com/jsonic/) language with other JSON enthusiasts, who are likewise eager to be free of JSON drudgery, yet don’t have our language-making skills.

In this tutorial, we’ll learn how to do that. We’ll use a few more Racket tools to accomplish the following:

-

  We’ll add [documentation](https://beautifulracket.com/jsonic-3/documentation.html) for our language.

-

  We’ll arrange our language into a distributable [package](https://beautifulracket.com/appendix/glossary.html#package).

-

  We’ll share our language using the Racket [package server](https://beautifulracket.com/jsonic-3/the-package-server.html).

After that, we’ll really be done. Anyone who has a copy of Racket—whether on Mac OS, Linux, or Windows—will be able to install and use jsonic.

As with the second [jsonic](https://beautifulracket.com/jsonic-2/) tutorial, the tasks in this tutorial are optional. They don’t change anything about how our language operates. They just make it easier to use.

### [Setup](#setup)

We’ll start with the jsonic source as we left it at [the end of the previous](https://beautifulracket.com/jsonic-2/source-listing.html) jsonic tutorial.

For those who didn’t do it before, the jsonic directory itself needs to be installed as a package as described in the [master recipe](https://beautifulracket.com/appendix/master-recipe.html#setting-up-a-language-project).
