The `drcontainers` DynamoRIO Extension provides container data structures that use the DR API for memory allocation and synchronization.

- [Setup](https://dynamorio.org/page_drcontainers.html#sec_drcontainers_setup)
- [Hashtable](https://dynamorio.org/page_drcontainers.html#sec_drcontainers_hashtable)
- [DrVector](https://dynamorio.org/page_drcontainers.html#sec_drcontainers_vector)
- [DrTable](https://dynamorio.org/page_drcontainers.html#sec_drcontainers_table)

#  Setup

To use `drcontainers` with your client simply include this line in your client's `CMakeLists.txt` file:

use_DynamoRIO_extension(clientname drcontainers)

That will automatically set up the include path and library dependence.

#  Hashtable

The hashtable supports integer, string, and custom hash keys, and has synchronization and memory allocation and deallocation parametrized for flexible usage. See [hashtable_init_ex()](https://dynamorio.org/group__drcontainers.html#ga307d17165381371418414308b3eed803) and related functions.

#  DrVector

The `drvector` DynamoRIO Extension provides a simple resizable array (a vector).

##  Initialization

Initialize a vector with [drvector_init()](https://dynamorio.org/group__drcontainers.html#gae5206874469dc2551dad9e8f375e87df):

[drvector_t](https://dynamorio.org/struct__drvector__t.html) vec;

The `initial_capacity` can be 0, in which case the internal array is lazily allocated upon the first insertion (using an internal default initial size).

##  Operations

Entries can be added to the end of the vector using [drvector_append()](https://dynamorio.org/group__drcontainers.html#ga380b542d2b8b997ded501df7f54b6919):

[drvector_append](https://dynamorio.org/group__drcontainers.html#ga380b542d2b8b997ded501df7f54b6919)(&vec, data);

[drvector_append](https://dynamorio.org/group__drcontainers.html#ga380b542d2b8b997ded501df7f54b6919)

bool drvector_append(drvector_t \*vec, void \*data)

Entries can be retrieved or set by index:

void \*data = [drvector_get_entry](https://dynamorio.org/group__drcontainers.html#gaa578776ea720fb04c87ac04181d89f4e)(&vec, 5);

[drvector_set_entry](https://dynamorio.org/group__drcontainers.html#ga70494a642307dd41ad8b6a754fcea9c8)(&vec, 3, new_data);

[drvector_set_entry](https://dynamorio.org/group__drcontainers.html#ga70494a642307dd41ad8b6a754fcea9c8)

bool drvector_set_entry(drvector_t \*vec, uint idx, void \*data)

[drvector_get_entry](https://dynamorio.org/group__drcontainers.html#gaa578776ea720fb04c87ac04181d89f4e)

void \* drvector_get_entry(drvector_t \*vec, uint idx)

[drvector_get_entry()](https://dynamorio.org/group__drcontainers.html#gaa578776ea720fb04c87ac04181d89f4e) returns `NULL` if the index is out of bounds.

For an unsynchronized vector, the caller is free to directly access the `array` field of the `drvector_t` structure for better performance.

[drvector_set_entry()](https://dynamorio.org/group__drcontainers.html#ga70494a642307dd41ad8b6a754fcea9c8) will automatically resize the vector if the index is beyond the current capacity. It also updates the number of entries to be `idx` + 1 if the index is greater than or equal to the current number of entries. Note that entries in between the last set index and the current index are left uninitialized (unless [drvector_config_t.zero_alloc](https://dynamorio.org/struct__drvector__config__t.html#a9f725ad445b7a9daf513e084da1b875c) is set), hence clearing or deleting a vector that has a `free_callback` set can be problematic, as the `free_callback` function will be called on uninitialized entries. It's the user's responsibility to set all entries prior to the `free_callback` being called.

##  Synchronization

The vector can be initialized to automatically synchronize each operation by passing `true` for the `synch` parameter to [drvector_init()](https://dynamorio.org/group__drcontainers.html#gae5206874469dc2551dad9e8f375e87df) or [drvector_init_ex()](https://dynamorio.org/group__drcontainers.html#gafc8c2293e2712d00a4aa81668e7fdfab).

Even when `synch` is `false`, the vector's lock is initialized and can be manually acquired and released:

##  Memory Management

A callback for freeing each data item can be provided to [drvector_init()](https://dynamorio.org/group__drcontainers.html#gae5206874469dc2551dad9e8f375e87df) or [drvector_init_ex()](https://dynamorio.org/group__drcontainers.html#gafc8c2293e2712d00a4aa81668e7fdfab). This callback is called for each entry when [drvector_delete()](https://dynamorio.org/group__drcontainers.html#ga2e5949b592508c61e35ec14bfa731d62) or [drvector_clear()](https://dynamorio.org/group__drcontainers.html#ga79924fa050e3c76126eeb3865a66265a) is called.

The [drvector_config_t.zero_alloc](https://dynamorio.org/struct__drvector__config__t.html#a9f725ad445b7a9daf513e084da1b875c) field can be set to `true` to ensure that the memory allocated for the vector's internal storage is zeroed. This is typically set via [drvector_init_ex()](https://dynamorio.org/group__drcontainers.html#gafc8c2293e2712d00a4aa81668e7fdfab). When `zero_alloc` is `true`, [drvector_clear()](https://dynamorio.org/group__drcontainers.html#ga79924fa050e3c76126eeb3865a66265a) also zeros the entire storage after calling `free_callback`.

To completely free the vector's storage:

[drvector_delete](https://dynamorio.org/group__drcontainers.html#ga2e5949b592508c61e35ec14bfa731d62)(&vec);

[drvector_delete](https://dynamorio.org/group__drcontainers.html#ga2e5949b592508c61e35ec14bfa731d62)

bool drvector_delete(drvector_t \*vec)

To clear the vector without freeing its internal storage:

[drvector_clear](https://dynamorio.org/group__drcontainers.html#ga79924fa050e3c76126eeb3865a66265a)(&vec);

[drvector_clear](https://dynamorio.org/group__drcontainers.html#ga79924fa050e3c76126eeb3865a66265a)

bool drvector_clear(drvector_t \*vec)

#  DrTable

The DrTable is a resizable array that does not relocate data, enabling a user to use pointers to access array entries directly.
