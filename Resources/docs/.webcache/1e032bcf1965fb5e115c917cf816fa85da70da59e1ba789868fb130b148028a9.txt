## Required Methods

[Source](https://doc.rust-lang.org/src/std/os/linux/process.rs.html#208)

🔬This is a nightly-only experimental API. (`linux_pidfd` [\#82971](https://github.com/rust-lang/rust/issues/82971))

Sets whether a [`PidFd`](https://doc.rust-lang.org/std/os/linux/process/struct.PidFd.html "struct std::os::linux::process::PidFd") should be created for the [`Child`](https://doc.rust-lang.org/std/process/struct.Child.html "struct std::process::Child") spawned by this [`Command`](https://doc.rust-lang.org/std/process/struct.Command.html "struct std::process::Command"). By default, no pidfd will be created.

The pidfd can be retrieved from the child with [`pidfd`](https://doc.rust-lang.org/std/os/linux/process/trait.ChildExt.html#tymethod.pidfd "method std::os::linux::process::ChildExt::pidfd") or [`into_pidfd`](https://doc.rust-lang.org/std/os/linux/process/trait.ChildExt.html#tymethod.into_pidfd "method std::os::linux::process::ChildExt::into_pidfd").

A pidfd will only be created if it is possible to do so in a guaranteed race-free manner. Otherwise, [`pidfd`](https://doc.rust-lang.org/std/os/linux/process/trait.ChildExt.html#tymethod.pidfd "method std::os::linux::process::ChildExt::pidfd") will return an error.

If a pidfd has been successfully created and not been taken from the `Child` then calls to `kill()`, `wait()` and `try_wait()` will use the pidfd instead of the pid. This can prevent pid recycling races, e.g. those caused by rogue libraries in the same process prematurely reaping zombie children via `waitpid(-1, ...)` calls.
