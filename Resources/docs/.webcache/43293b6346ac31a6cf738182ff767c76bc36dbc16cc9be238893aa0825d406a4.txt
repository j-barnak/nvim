Though stacker was simple, we covered many of the foundational ideas of implementing languages in Racket. Our next tutorials will build on these:

-

  A language in Racket can be thought of as a [source-to-source compiler](https://beautifulracket.com/appendix/glossary.html#source-to-source-compiler) that converts the source code of a new language into ordinary Racket code, then runs it normally. This means that all Racket-implemented languages can use Racket’s libraries and tools.

-

  Every language has a [reader](https://beautifulracket.com/appendix/glossary.html#reader) and an [expander](https://beautifulracket.com/appendix/glossary.html#expander). The reader is responsible for the form of the code. The expander is responsible for its meaning.

-

  The [reader](https://beautifulracket.com/appendix/glossary.html#reader) converts the source code of the new language into Racket-style parenthesized forms called [S-expressions](https://beautifulracket.com/appendix/glossary.html#s-expression).

  -

    The reader must [provide](http://docs.racket-lang.org/reference/require.html#(form._((lib._racket/private/base..rkt)._provide))) a function called read-syntax. Racket passes two arguments to this function: the [path](https://beautifulracket.com/appendix/glossary.html#path) to the source file, and an input [port](https://beautifulracket.com/appendix/glossary.html#port) for reading the source code.

  -

    After converting the source to S-expressions, the function must return Racket code describing a module (packaged as a syntax object).

  -

    Back at the source file, Racket replaces the source code with this module code.

-

  The [expander](https://beautifulracket.com/appendix/glossary.html#expander) determines how the S-expressions generated by the reader correspond to real Racket expressions, by ensuring that every [identifier](https://beautifulracket.com/appendix/glossary.html#identifier) has a [binding](https://beautifulracket.com/appendix/glossary.html#binding).

  -

    The expander must [provide](http://docs.racket-lang.org/reference/require.html#(form._((lib._racket/private/base..rkt)._provide))) a [macro](https://beautifulracket.com/appendix/glossary.html#macro) called #%module-begin. Racket takes the code from inside the module expression generated by the reader and passes it to this macro.

  -

    This macro must return new Racket code, again packaged as a syntax object. Racket replaces the module expression generated by the reader with this new code.

-

  Once the expander finishes its work, the new language has been translated into ordinary Racket code. It’s [evaluated](https://beautifulracket.com/explainer/evaluation.html) as a Racket program to produce a result.

-

  Racket supports a special class of functions called [macros](https://beautifulracket.com/explainer/macros.html). Macros can copy & rewrite code at [compile time](https://beautifulracket.com/appendix/glossary.html#compile-time). All macros take a code fragment as input (packaged as a [syntax object](https://beautifulracket.com/explainer/syntax-objects.html)) and return a new code fragment as output (also packaged as a syntax object).

-

  A [syntax object](https://beautifulracket.com/explainer/syntax-objects.html) can also hold a reference to the [lexical context](https://beautifulracket.com/appendix/glossary.html#lexical-context) at a certain point in the program, so that code inside the syntax object can see all the variables defined at that point. We can use the #' prefix to turn any code into a syntax object, by converting it to a datum and capturing its lexical context.
