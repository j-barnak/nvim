Single instruction, multiple data

**Single instruction, multiple data** (**SIMD**) is a type of [parallel computing](https://en.wikipedia.org/wiki/Parallel_computing "Parallel computing") (processing) in [Flynn's taxonomy](https://en.wikipedia.org/wiki/Flynn's_taxonomy "Flynn's taxonomy"). SIMD describes computers with [multiple processing elements](https://en.wikipedia.org/wiki/Multiple_processing_elements "Multiple processing elements") that perform the same operation on multiple data points simultaneously. SIMD can be internal (part of the hardware design) and it can be directly accessible through an [instruction set architecture](https://en.wikipedia.org/wiki/Instruction_set_architecture "Instruction set architecture") (ISA), but it should not be confused with an ISA.

Such machines exploit [data level parallelism](https://en.wikipedia.org/wiki/Data_parallelism "Data parallelism"), but not [concurrency](https://en.wikipedia.org/wiki/Concurrent_computing "Concurrent computing"): there are simultaneous (parallel) computations, but each unit performs exactly the same instruction at any given moment (just with different data). A simple example is to add many pairs of numbers together, all of the SIMD units are performing an addition, but each one has different pairs of values to add. SIMD is especially applicable to common tasks such as adjusting the contrast in a [digital image](https://en.wikipedia.org/wiki/Digital_image "Digital image") or adjusting the volume of [digital audio](https://en.wikipedia.org/wiki/Digital_audio "Digital audio"). Most modern [central processing unit](https://en.wikipedia.org/wiki/Central_processing_unit "Central processing unit") (CPU) designs include SIMD instructions to improve the performance of [multimedia](https://en.wikipedia.org/wiki/Multimedia "Multimedia") use. In recent CPUs, SIMD units are tightly coupled with cache hierarchies and prefetch mechanisms, which minimize latency during large block operations. For instance, AVX-512-enabled processors can prefetch entire cache lines and apply fused multiply-add operations (FMA) in a single SIMD cycle.

## Confusion between SIMT and SIMD

[ILLIAC IV](https://en.wikipedia.org/wiki/ILLIAC_IV "ILLIAC IV") Array overview, from ARPA-funded Introductory description by Steward Denenberg, July 15, 1971

SIMD has three different subcategories in [Flynn's 1972 Taxonomy](https://en.wikipedia.org/wiki/Flynn's_taxonomy#Single_instruction_stream,_multiple_data_streams_(SIMD) "Flynn's taxonomy"), one of which is [single instruction, multiple threads](https://en.wikipedia.org/wiki/Single_instruction,_multiple_threads "Single instruction, multiple threads") (SIMT). SIMT should not be confused with [software threads](https://en.wikipedia.org/wiki/Thread_(computing) "Thread (computing)") or [hardware threads](https://en.wikipedia.org/wiki/Multithreading_(computer_architecture) "Multithreading (computer architecture)"), both of which are task time-sharing (time-slicing). SIMT is true simultaneous parallel hardware-level execution, such as in the [ILLIAC IV](https://en.wikipedia.org/wiki/ILLIAC_IV "ILLIAC IV").

SIMD should not be confused with [Vector processing](https://en.wikipedia.org/wiki/Vector_processing "Vector processing"), characterized by the [Cray 1](https://en.wikipedia.org/wiki/Cray_1 "Cray 1") and clarified in [Duncan's taxonomy](https://en.wikipedia.org/wiki/Duncan's_taxonomy "Duncan's taxonomy"). The [difference between SIMD and vector processors](https://en.wikipedia.org/wiki/Vector_processor#Difference_between_SIMD_and_vector_processors "Vector processor") is primarily the presence of a Cray-style `SET VECTOR LENGTH` instruction.

## History

The first known operational use to date of [SIMD within a register](https://en.wikipedia.org/wiki/SIMD_within_a_register "SIMD within a register") was the [TX-2](https://en.wikipedia.org/wiki/TX-2 "TX-2"), in 1958. It was capable of 36-bit operations and two 18-bit or four 9-bit sub-word operations.

The first commercial use of SIMD instructions was in the [ILLIAC IV](https://en.wikipedia.org/wiki/ILLIAC_IV "ILLIAC IV"), which was completed in 1972.

[Vector supercomputers](https://en.wikipedia.org/wiki/Vector_processor "Vector processor") of the early 1970s such as the [CDC Star-100](https://en.wikipedia.org/wiki/CDC_STAR-100 "CDC STAR-100") and the [Texas Instruments ASC](https://en.wikipedia.org/wiki/TI_Advanced_Scientific_Computer "TI Advanced Scientific Computer") could operate on a "vector" of data with a single instruction. Vector processing was especially popularized by [Cray](https://en.wikipedia.org/wiki/Cray "Cray") in the 1970s and 1980s. Vector processing architectures are now considered separate from SIMD computers: [Duncan's Taxonomy](https://en.wikipedia.org/wiki/Duncan's_Taxonomy "Duncan's Taxonomy") includes them whereas [Flynn's Taxonomy](https://en.wikipedia.org/wiki/Flynn's_Taxonomy "Flynn's Taxonomy") does not, due to Flynn's work (1966, 1972) pre-dating the [Cray-1](https://en.wikipedia.org/wiki/Cray-1 "Cray-1") (1977). The complexity of Vector processors however inspired a simpler arrangement known as [SIMD within a register](https://en.wikipedia.org/wiki/SIMD_within_a_register "SIMD within a register").

The first era of modern SIMD computers was characterized by [massively parallel processing](https://en.wikipedia.org/wiki/Massively_parallel_processing "Massively parallel processing")-style [supercomputers](https://en.wikipedia.org/wiki/Supercomputer "Supercomputer") such as the [Thinking Machines](https://en.wikipedia.org/wiki/Thinking_Machines_Corporation "Thinking Machines Corporation") [Connection Machine](https://en.wikipedia.org/wiki/Connection_Machine "Connection Machine") CM-1 and CM-2. These computers had many limited-functionality processors that would work in parallel. For example, each of 65,536 single-bit processors in a Thinking Machines CM-2 would execute the same instruction at the same time, allowing, for instance, to logically combine 65,536 pairs of bits at a time, using a hypercube-connected network or processor-dedicated RAM to find its operands. Supercomputing moved away from the SIMD approach when inexpensive scalar [multiple instruction, multiple data](https://en.wikipedia.org/wiki/Multiple_instruction,_multiple_data "Multiple instruction, multiple data") (MIMD) approaches based on commodity processors such as the [Intel i860 XP](https://en.wikipedia.org/wiki/Intel_i860 "Intel i860") became more powerful, and interest in SIMD waned.

The current era of SIMD processors grew out of the desktop-computer market rather than the supercomputer market. As desktop processors became powerful enough to support real-time gaming and audio/video processing during the 1990s, demand grew for this type of computing power, and microprocessor vendors turned to SIMD to meet the demand. This resurgence also coincided with the rise of [DirectX](https://en.wikipedia.org/wiki/DirectX "DirectX") and OpenGL shader models, which heavily leveraged SIMD under the hood. The graphics APIs encouraged programmers to adopt data-parallel programming styles, indirectly accelerating SIMD adoption in desktop software. Hewlett-Packard introduced [Multimedia Acceleration eXtensions](https://en.wikipedia.org/wiki/Multimedia_Acceleration_eXtensions "Multimedia Acceleration eXtensions") (MAX) instructions into [PA-RISC](https://en.wikipedia.org/wiki/PA-RISC "PA-RISC") 1.1 desktops in 1994 to accelerate MPEG decoding. Sun Microsystems introduced SIMD integer instructions in its "[VIS](https://en.wikipedia.org/wiki/Visual_Instruction_Set "Visual Instruction Set")" instruction set extensions in 1995, in its [UltraSPARC I](https://en.wikipedia.org/wiki/UltraSPARC "UltraSPARC") microprocessor. MIPS followed suit with their similar [MDMX](https://en.wikipedia.org/wiki/MDMX "MDMX") system.

The first widely deployed desktop SIMD was with Intel's [MMX](https://en.wikipedia.org/wiki/MMX_(instruction_set) "MMX (instruction set)") extensions to the [x86](https://en.wikipedia.org/wiki/X86 "X86") architecture in 1996. This sparked the introduction of the much more powerful [AltiVec](https://en.wikipedia.org/wiki/AltiVec "AltiVec") system in the [Motorola](https://en.wikipedia.org/wiki/Motorola "Motorola") [PowerPC](https://en.wikipedia.org/wiki/PowerPC "PowerPC") and IBM's [POWER](https://en.wikipedia.org/wiki/IBM_Power_microprocessors "IBM Power microprocessors") systems. Intel responded in 1999 by introducing the all-new [SSE](https://en.wikipedia.org/wiki/Streaming_SIMD_Extensions "Streaming SIMD Extensions") system. Since then, there have been several extensions to the SIMD instruction sets for both architectures. Advanced vector extensions AVX, [AVX2](https://en.wikipedia.org/wiki/AVX2 "AVX2") and [AVX-512](https://en.wikipedia.org/wiki/AVX-512 "AVX-512") are developed by Intel. AMD supports AVX, [AVX2](https://en.wikipedia.org/wiki/AVX2 "AVX2"), and [AVX-512](https://en.wikipedia.org/wiki/AVX-512 "AVX-512") in their current products.

## Disadvantages

With SIMD, an order of magnitude increase in code size is not uncommon, when compared to equivalent scalar or equivalent vector code, and an order of magnitude *or greater* effectiveness (work done per instruction) is achievable with Vector ISAs.

ARM's [Scalable Vector Extension](https://en.wikipedia.org/wiki/Scalable_Vector_Extension "Scalable Vector Extension") takes another approach, known in [Flynn's Taxonomy](https://en.wikipedia.org/wiki/Flynn's_taxonomy#Single_instruction_stream,_multiple_data_streams_(SIMD) "Flynn's taxonomy") more commonly known today as ["Predicated" (masked)](https://en.wikipedia.org/wiki/Predication_(computer_architecture)#SIMD,_SIMT_and_vector_predication "Predication (computer architecture)") SIMD. This approach is not as compact as [vector processing](https://en.wikipedia.org/wiki/Vector_processing "Vector processing") but is still far better than non-predicated SIMD. Detailed comparative examples are given at [Vector processor § Vector instruction example](https://en.wikipedia.org/wiki/Vector_processor#Vector_instruction_example "Vector processor").

## Hardware

### CPUs

Small-scale (64 or 128 bits) SIMD became popular on general-purpose CPUs in the early 1990s and continued through 1997 and later with Motion Video Instructions (MVI) for [Alpha](https://en.wikipedia.org/wiki/DEC_Alpha "DEC Alpha"). SIMD instructions can be found, to one degree or another, on most CPUs, including [Hewlett-Packard](https://en.wikipedia.org/wiki/Hewlett-Packard "Hewlett-Packard")'s (HP) [PA-RISC](https://en.wikipedia.org/wiki/PA-RISC "PA-RISC") [Multimedia Acceleration eXtensions](https://en.wikipedia.org/wiki/Multimedia_Acceleration_eXtensions "Multimedia Acceleration eXtensions") (MAX), [IBM](https://en.wikipedia.org/wiki/IBM "IBM")'s [AltiVec](https://en.wikipedia.org/wiki/AltiVec "AltiVec") and Signal Processing Engine (SPE) for [PowerPC](https://en.wikipedia.org/wiki/PowerPC "PowerPC"), [Intel](https://en.wikipedia.org/wiki/Intel "Intel")'s [MMX and iwMMXt](https://en.wikipedia.org/wiki/MMX_(instruction_set) "MMX (instruction set)"), [Streaming SIMD Extensions](https://en.wikipedia.org/wiki/Streaming_SIMD_Extensions "Streaming SIMD Extensions") (SSE), [SSE2](https://en.wikipedia.org/wiki/SSE2 "SSE2"), [SSE3](https://en.wikipedia.org/wiki/SSE3 "SSE3") [SSSE3](https://en.wikipedia.org/wiki/SSSE3 "SSSE3") and [SSE4](https://en.wikipedia.org/wiki/SSE4 "SSE4").x, [AMD](https://en.wikipedia.org/wiki/Advanced_Micro_Devices "Advanced Micro Devices")'s [3DNow!](https://en.wikipedia.org/wiki/3DNow! "3DNow!"), [ARC's](https://en.wikipedia.org/wiki/ARC_(processor) "ARC (processor)") ARC Video subsystem, [SPARC](https://en.wikipedia.org/wiki/SPARC "SPARC")'s [VIS](https://en.wikipedia.org/wiki/Visual_Instruction_Set "Visual Instruction Set") and VIS2, [Sun](https://en.wikipedia.org/wiki/Sun_Microsystems "Sun Microsystems")'s [MAJC](https://en.wikipedia.org/wiki/MAJC "MAJC"), [ARM's](https://en.wikipedia.org/wiki/ARM_Holdings "ARM Holdings") [Neon](https://en.wikipedia.org/wiki/ARM_architecture#Advanced_SIMD_(Neon) "ARM architecture") technology, [MIPS](https://en.wikipedia.org/wiki/MIPS_architecture "MIPS architecture")' [MDMX](https://en.wikipedia.org/wiki/MDMX "MDMX") (MaDMaX) and [MIPS-3D](https://en.wikipedia.org/wiki/MIPS-3D "MIPS-3D").

Intel's [AVX-512](https://en.wikipedia.org/wiki/AVX-512 "AVX-512") SIMD instructions process 512 bits of data at once.

### Coprocessors

The IBM, Sony, Toshiba co-developed [Cell processor's](https://en.wikipedia.org/wiki/Cell_(processor) "Cell (processor)") [Synergistic Processing Element's](https://en.wikipedia.org/wiki/Cell_(processor)#Synergistic_Processing_Element_(SPE) "Cell (processor)") (SPE's) instruction set is heavily SIMD based.

Some, but not all, GPUs are SIMD-based. AMD GPUs since the [TeraScale (microarchitecture)](https://en.wikipedia.org/wiki/TeraScale_(microarchitecture) "TeraScale (microarchitecture)") are SIMD-based, a feature that has remained in the 2020s microartectures RDNA and CDNA, with a layer of [single instruction, multiple threads](https://en.wikipedia.org/wiki/Single_instruction,_multiple_threads "Single instruction, multiple threads") (SIMT) above. On the other hand, Nvidia's CUDA architectures use scalar cores with SIMT.

[Philips](https://en.wikipedia.org/wiki/Philips "Philips"), now [NXP](https://en.wikipedia.org/wiki/NXP_Semiconductors "NXP Semiconductors"), developed several SIMD processors named [Xetal](https://en.wikipedia.org/wiki/Xetal "Xetal"). The Xetal has 320 16-bit processor elements especially designed for vision tasks.

Apple's M1 and M2 chips also incorporate SIMD units deeply integrated with their GPU and Neural Engine, using Apple-designed SIMD pipelines optimized for image filtering, convolution, and matrix multiplication. This unified memory architecture helps SIMD instructions operate on shared memory pools more efficiently. (The CPU part implements ordinary NEON).

## Software

The ordinary tripling of four 8-bit numbers. The CPU loads one 8-bit number into R1, multiplies it with R2, and then saves the answer from R3 back to RAM. This process is repeated for each number.

The SIMD tripling of four 8-bit numbers. The CPU loads 4 numbers at once, multiplies them all in one SIMD-multiplication, and saves them all at once back to RAM. In theory, the speed can be multiplied by 4.

SIMD instructions are widely used to process 3D graphics, although modern [graphics cards](https://en.wikipedia.org/wiki/Video_card "Video card") with embedded SIMD have largely taken over this task from the CPU. Some systems also include permute functions that re-pack elements inside vectors, making them especially useful for data processing and compression. They are also used in cryptography. The trend of general-purpose computing on GPUs ([GPGPU](https://en.wikipedia.org/wiki/GPGPU "GPGPU")) may lead to wider use of SIMD in the future. Recent compilers such as [LLVM](https://en.wikipedia.org/wiki/LLVM "LLVM"), [GNU Compiler Collection](https://en.wikipedia.org/wiki/GNU_Compiler_Collection "GNU Compiler Collection") (GCC), and Intel's ICC offer aggressive auto-vectoring options. Developers can often enable these with flags like `-O3` or `-ftree-vectorize`, which guide the compiler to restructure loops for SIMD compatibility.

Adoption of SIMD systems in [personal computer](https://en.wikipedia.org/wiki/Personal_computer "Personal computer") software was at first slow, due to a number of problems. One was that many of the early SIMD instruction sets tended to slow overall performance of the system due to the re-use of existing floating point registers. Other systems, like [MMX](https://en.wikipedia.org/wiki/MMX_(instruction_set) "MMX (instruction set)") and [3DNow!](https://en.wikipedia.org/wiki/3DNow! "3DNow!"), offered support for data types that were not interesting to a wide audience and had expensive context switching instructions to switch between using the [FPU](https://en.wikipedia.org/wiki/Floating-point_unit "Floating-point unit") and MMX [registers](https://en.wikipedia.org/wiki/Processor_register "Processor register"). Compilers also often lacked support, requiring programmers to resort to [assembly language](https://en.wikipedia.org/wiki/Assembly_language "Assembly language") coding.

SIMD on [x86](https://en.wikipedia.org/wiki/X86 "X86") had a slow start. The introduction of [3DNow!](https://en.wikipedia.org/wiki/3DNow! "3DNow!") by [AMD](https://en.wikipedia.org/wiki/Advanced_Micro_Devices "Advanced Micro Devices") and [SSE](https://en.wikipedia.org/wiki/Streaming_SIMD_Extensions "Streaming SIMD Extensions") by [Intel](https://en.wikipedia.org/wiki/Intel "Intel") confused matters somewhat, but today the system seems to have settled down (after AMD adopted SSE) and newer compilers should result in more SIMD-enabled software. Intel and AMD now both provide optimized math [libraries](https://en.wikipedia.org/wiki/Library_(computing) "Library (computing)") that use SIMD instructions, and open source alternatives like libSIMD, SIMDx86 and SLEEF have started to appear (see also [libm](https://en.wikipedia.org/wiki/Libm "Libm")).

[Apple Computer](https://en.wikipedia.org/wiki/Apple_Inc. "Apple Inc.") had somewhat more success, even though they entered the SIMD market later than the rest. [AltiVec](https://en.wikipedia.org/wiki/AltiVec "AltiVec") offered a rich system and can be programmed using increasingly sophisticated compilers from [Motorola](https://en.wikipedia.org/wiki/Motorola "Motorola"), [IBM](https://en.wikipedia.org/wiki/IBM "IBM") and [GNU](https://en.wikipedia.org/wiki/GNU "GNU"), therefore assembly language programming is rarely needed. Additionally, many of the systems that would benefit from SIMD were supplied by Apple itself, for example [iTunes](https://en.wikipedia.org/wiki/ITunes "ITunes") and [QuickTime](https://en.wikipedia.org/wiki/QuickTime "QuickTime"). However, in 2006, Apple computers moved to Intel x86 processors. Apple's [APIs](https://en.wikipedia.org/wiki/Application_programming_interface "Application programming interface") and [development tools](https://en.wikipedia.org/wiki/Integrated_development_environment "Integrated development environment") ([XCode](https://en.wikipedia.org/wiki/Xcode "Xcode")) were modified to support [SSE2](https://en.wikipedia.org/wiki/SSE2 "SSE2") and [SSE3](https://en.wikipedia.org/wiki/SSE3 "SSE3") as well as AltiVec. Apple was the dominant purchaser of PowerPC chips from IBM and [Freescale Semiconductor](https://en.wikipedia.org/wiki/Freescale_Semiconductor "Freescale Semiconductor"). Even though Apple has stopped using PowerPC processors in their products, further development of AltiVec is continued in several PowerPC and [Power ISA](https://en.wikipedia.org/wiki/Power_ISA "Power ISA") designs from Freescale and IBM.

*SIMD within a register*, or [SWAR](https://en.wikipedia.org/wiki/SWAR "SWAR"), is a range of techniques and tricks used for performing SIMD in general-purpose registers on hardware that does not provide any direct support for SIMD instructions. This can be used to exploit parallelism in certain algorithms even on hardware that does not support SIMD directly.

### Programmer interface

It is common for publishers of the SIMD instruction sets to make their own [C](https://en.wikipedia.org/wiki/C_(programming_language) "C (programming language)") and [C++](https://en.wikipedia.org/wiki/C++ "C++") language extensions with [intrinsic functions](https://en.wikipedia.org/wiki/Intrinsic_function "Intrinsic function") or special datatypes (with [operator overloading](https://en.wikipedia.org/wiki/Operator_overloading "Operator overloading")) guaranteeing the generation of vector code. Intel, AltiVec, and ARM NEON provide extensions widely adopted by the compilers targeting their CPUs. (More complex operations are the task of vector math libraries.)

#### Generic datatypes

The [GNU C Compiler](https://en.wikipedia.org/wiki/GNU_C_Compiler "GNU C Compiler") takes the extensions a step further by abstracting them into a universal interface that can be used on any platform by providing a way of defining SIMD datatypes. The [LLVM](https://en.wikipedia.org/wiki/LLVM "LLVM") Clang compiler also implements the feature, with an analogous interface defined in the IR. [Rust](https://en.wikipedia.org/wiki/Rust_(programming_language) "Rust (programming language)")'s `std::simd` uses this interface, and so does [Swift](https://en.wikipedia.org/wiki/Swift_(programming_language) "Swift (programming language)") 2.0+.

C++ added `std::simd::vec<T, Abi>` (a data-parallel vector type) and `std::simd::mask<T, Abi>` (a data-parallel type with `bool` elements) in [C++26](https://en.wikipedia.org/wiki/C++26 "C++26"), where the [template parameters](https://en.wikipedia.org/wiki/Type_variable "Type variable") `T` is the vectorizable type and `Abi` is the ABI tag, specifying its width and storage.

[Microsoft](https://en.wikipedia.org/wiki/Microsoft_Corporation "Microsoft Corporation") added SIMD to [.NET](https://en.wikipedia.org/wiki/.NET_Core ".NET Core") in RyuJIT. The `System.Numerics.Vector<T>` class implements SIMD datatypes. Java also has a new proposed API for SIMD instructions available in [OpenJDK](https://en.wikipedia.org/wiki/OpenJDK "OpenJDK") 17 in an incubator [module](https://en.wikipedia.org/wiki/Java_Platform_Module_System "Java Platform Module System"), in the [standard library](https://en.wikipedia.org/wiki/Java_Class_Library "Java Class Library") as `jdk.incubator.vector.Vector<E>`. It also has a safe fallback mechanism on unsupported CPUs to simple loops.

Rust has an experimental `std::simd::Simd<T, N>` (a SIMD vector) and `std::simd::Mask<T, N>` (a SIMD vector mask) types, where `T` is the vectorizable type and `N` is the size, for portable SIMD; it also has a target-specific `std::arch` module, but this API is unsafe.

#### Vectorization hints

Instead of providing an SIMD datatype, compilers can also be hinted to [auto-vectorize](https://en.wikipedia.org/wiki/Automatic_vectorization "Automatic vectorization") some loops, potentially taking some assertions about the lack of data dependency. This is not as flexible as manipulating SIMD variables directly, but is easier to use. [OpenMP](https://en.wikipedia.org/wiki/OpenMP "OpenMP") 4.0+ has a `#pragma omp simd` hint. This OpenMP interface has replaced a wide set of nonstandard extensions, including [Cilk](https://en.wikipedia.org/wiki/Cilk "Cilk")'s `#pragma simd`, GCC's `#pragma GCC ivdep`, and many more.

"SIMD everywhere", a collection of C/C++ headers implementing platform-specific intrinsics for other platforms (e.g. SSE intrinsics for ARM NEON), includes the use of platform-specific intrinsics, generic vector interfaces, and vectorization hints. It can be used as a "Rosetta Stone" for comparing these different SIMD programming paradigms.

#### SPMD-on-SIMD

Another approach is [SPMD](https://en.wikipedia.org/wiki/Single_program,_multiple_data "Single program, multiple data"): write a program that looks as if it operates only one element on the time, then have a compiler widen it to match the SIMD vector width. This is the approach used by graphics [shaders](https://en.wikipedia.org/wiki/Shader "Shader") and more recently adopted by CPU-oriented tools such as Intel IPSC.

### SIMD multi-versioning

Consumer software is typically expected to work on a range of CPUs covering multiple generations, which could limit the programmer's ability to use new SIMD instructions to improve the computational performance of a program. The solution is to include multiple versions of the same code that uses either older or newer SIMD technologies, and pick one that best fits the user's CPU at run-time ([dynamic dispatch](https://en.wikipedia.org/wiki/Dynamic_dispatch "Dynamic dispatch")). There are two main camps of solutions:

- Function multi-versioning (FMV): a [subroutine](https://en.wikipedia.org/wiki/Subroutine "Subroutine") in the program or a library is duplicated and compiled for many instruction set extensions, and the program decides which one to use at run-time.
- Library multi-versioning (LMV): the entire [programming library](https://en.wikipedia.org/wiki/Library_(computing) "Library (computing)") is duplicated for many instruction set extensions, and the operating system or the program decides which one to load at run-time.

FMV, manually coded in assembly language, is quite commonly used in a number of performance-critical libraries such as glibc and libjpeg-turbo. [Intel C++ Compiler](https://en.wikipedia.org/wiki/Intel_C++_Compiler "Intel C++ Compiler"), [GNU Compiler Collection](https://en.wikipedia.org/wiki/GNU_Compiler_Collection "GNU Compiler Collection") since GCC 6, and [Clang](https://en.wikipedia.org/wiki/Clang "Clang") since clang 7 allow for a simplified approach, with the compiler taking care of function duplication and selection. GCC and clang requires explicit `target_clones` labels in the code to "clone" functions, while ICC does so automatically (under the command-line option `/Qax`). Rust also supports FMV. The setup is similar to GCC and Clang in that the code defines what instruction sets to compile for, but cloning is manually done via inlining.

As using FMV requires code modification on GCC and Clang, vendors more commonly use library multi-versioning: this is easier to achieve as only compiler switches need to be changed. [Glibc](https://en.wikipedia.org/wiki/Glibc "Glibc") supports LMV and this functionality is adopted by the Intel-backed Clear Linux project.

### SIMD on the web

In 2013 John McCutchan announced that he had created a high-performance interface to SIMD instruction sets for the [Dart](https://en.wikipedia.org/wiki/Dart_(programming_language) "Dart (programming language)") programming language, bringing the benefits of SIMD to web programs for the first time. The interface consists of two types:

- Float32x4, 4 single precision floating point values.
- Int32x4, 4 32-bit integer values.

Instances of these types are immutable and in optimized code are mapped directly to SIMD registers. Operations expressed in Dart typically are compiled into a single instruction without any overhead. This is similar to C and C++ intrinsics. Benchmarks for [4×4](https://en.wikipedia.org/wiki/4×4_matrix "4×4 matrix") [matrix multiplication](https://en.wikipedia.org/wiki/Matrix_multiplication "Matrix multiplication"), [3D vertex transformation](https://en.wikipedia.org/wiki/3D_vertex_transformation "3D vertex transformation"), and [Mandelbrot set](https://en.wikipedia.org/wiki/Mandelbrot_set "Mandelbrot set") visualization show near 400% speedup compared to scalar code written in Dart.

Intel announced at IDF 2013 that they were implementing McCutchan's specification for both [V8](https://en.wikipedia.org/wiki/V8_(JavaScript_engine) "V8 (JavaScript engine)") and [SpiderMonkey](https://en.wikipedia.org/wiki/SpiderMonkey "SpiderMonkey"). However, by 2017, SIMD.js was taken out of the [ECMAScript](https://en.wikipedia.org/wiki/ECMAScript "ECMAScript") standard queue in favor of pursuing a similar interface in [WebAssembly](https://en.wikipedia.org/wiki/WebAssembly "WebAssembly").

Support for SIMD was added to the [WebAssembly](https://en.wikipedia.org/wiki/WebAssembly "WebAssembly") 2.0 specification, which was finished on 2022 and became official in December 2024. LLVM's autovectoring, when compiling C or C++ to WebAssembly, can target WebAssembly SIMD to automatically make use of SIMD, while SIMD intrinsic are also available.

## Commercial applications

It has generally proven difficult to find sustainable commercial applications for SIMD-only processors in general-purpose computing.

One that has had some measure of success is the [GAPP](https://en.wikipedia.org/wiki/Geometric-Arithmetic_Parallel_Processor "Geometric-Arithmetic Parallel Processor"), which was developed by [Lockheed Martin](https://en.wikipedia.org/wiki/Lockheed_Martin "Lockheed Martin") and taken to the commercial sector by their spin-off Teranex. The GAPP's recent incarnations have become a powerful tool in real-time [video processing](https://en.wikipedia.org/wiki/Digital_image_processing "Digital image processing") applications like conversion between various video standards and frame rates ([NTSC](https://en.wikipedia.org/wiki/NTSC "NTSC") to/from [PAL](https://en.wikipedia.org/wiki/PAL "PAL"), NTSC to/from [high-definition television](https://en.wikipedia.org/wiki/High-definition_television "High-definition television") (HDTV) formats, etc.), [deinterlacing](https://en.wikipedia.org/wiki/Deinterlacing "Deinterlacing"), image [noise reduction](https://en.wikipedia.org/wiki/Noise_reduction "Noise reduction"), adaptive [video compression](https://en.wikipedia.org/wiki/Video_compression "Video compression"), and image enhancement.

A more ubiquitous application for SIMD is found in [video games](https://en.wikipedia.org/wiki/Video_game "Video game"): nearly every modern [video game console](https://en.wikipedia.org/wiki/Video_game_console "Video game console") since [1998](https://en.wikipedia.org/wiki/History_of_video_game_consoles_(sixth_generation) "History of video game consoles (sixth generation)") has incorporated a SIMD processor somewhere in its architecture. The [PlayStation 2](https://en.wikipedia.org/wiki/PlayStation_2 "PlayStation 2") was unusual in that one of its vector-float units could function as an autonomous [digital signal processor](https://en.wikipedia.org/wiki/Digital_signal_processor "Digital signal processor") (DSP) executing its own instruction stream, or as a coprocessor driven by ordinary CPU instructions. 3D graphics applications tend to lend themselves well to SIMD processing as they rely heavily on operations with 4-dimensional vectors. [Microsoft](https://en.wikipedia.org/wiki/Microsoft "Microsoft")'s [Direct3D](https://en.wikipedia.org/wiki/Direct3D "Direct3D") 9.0 now chooses at runtime processor-specific implementations of its own math operations, including the use of SIMD-capable instructions.

A later processor that used vector processing is the [Cell processor](https://en.wikipedia.org/wiki/Cell_(processor) "Cell (processor)") used in the PlayStation 3, which was developed by [IBM](https://en.wikipedia.org/wiki/IBM "IBM") in cooperation with [Toshiba](https://en.wikipedia.org/wiki/Toshiba "Toshiba") and [Sony](https://en.wikipedia.org/wiki/Sony "Sony"). It uses a number of SIMD processors (a [non-uniform memory access](https://en.wikipedia.org/wiki/Non-uniform_memory_access "Non-uniform memory access") (NUMA) architecture, each with independent [local store](https://en.wikipedia.org/wiki/Cache_memory "Cache memory") and controlled by a general purpose CPU) and is geared towards the huge datasets required by 3D and video processing applications. It differs from traditional ISAs by being SIMD from the ground up with no separate scalar registers.

Ziilabs produced an SIMD type processor for use on mobile devices, such as media players and mobile phones.

Larger scale commercial SIMD processors are available from ClearSpeed Technology, Ltd. and Stream Processors, Inc. [ClearSpeed](https://en.wikipedia.org/wiki/ClearSpeed "ClearSpeed")'s CSX600 (2004) has 96 cores each with two double-precision floating point units while the CSX700 (2008) has 192. Stream Processors is headed by computer architect [Bill Dally](https://en.wikipedia.org/wiki/Bill_Dally "Bill Dally"). Their Storm-1 processor (2007) contains 80 SIMD cores controlled by a [MIPS](https://en.wikipedia.org/wiki/MIPS_architecture "MIPS architecture") CPU.
