Expand description

A [`u64`](https://doc.rust-lang.org/std/primitive.u64.html "primitive u64") that is known not to equal zero.

This enables some memory layout optimization. For example, `Option<NonZeroU64>` is the same size as `u64`:

``` rust
assert_eq!(size_of::<Option<core::num::NonZeroU64>>(), size_of::<u64>());
```

## Layout

`NonZeroU64` is guaranteed to have the same layout and bit validity as `u64` with the exception that `0` is not a valid instance. `Option<NonZeroU64>` is guaranteed to be compatible with `u64`, including in FFI.

Thanks to the [null pointer optimization](https://doc.rust-lang.org/std/option/index.html#representation "mod std::option"), `NonZeroU64` and `Option<NonZeroU64>` are guaranteed to have the same size and alignment:

``` rust
use std::num::NonZeroU64;

assert_eq!(size_of::<NonZeroU64>(), size_of::<Option<NonZeroU64>>());
assert_eq!(align_of::<NonZeroU64>(), align_of::<Option<NonZeroU64>>());
```

## Compile-time creation

Since both [`Option::unwrap()`](https://doc.rust-lang.org/std/option/enum.Option.html#method.unwrap "method std::option::Option::unwrap") and [`Option::expect()`](https://doc.rust-lang.org/std/option/enum.Option.html#method.expect "method std::option::Option::expect") are `const`, it is possible to define a new `NonZeroU64` at compile time via:

``` rust
use std::num::NonZeroU64;

const TEN: NonZeroU64 = NonZeroU64::new(10).expect("ten is non-zero");
```
