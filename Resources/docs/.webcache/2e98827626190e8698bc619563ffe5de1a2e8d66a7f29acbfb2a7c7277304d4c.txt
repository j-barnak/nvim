# Devices & Drivers

How the kernel discovers hardware, binds drivers to it, and exposes the big device classes — buses, peripherals, and the frameworks that make them look uniform to user space.

- [Drivers (drivers/)](https://kernel-internals.org/drivers/) — the device model and how drivers bind to hardware (buses, PCI, device tree, platform, I2C/SPI)
- [USB (usb/)](https://kernel-internals.org/usb/) — the host-scheduled, hot-pluggable peripheral bus: descriptors, endpoints, and URBs
- [GPU / DRM (drm/)](https://kernel-internals.org/drm/) — the graphics and display stack: KMS modesetting, GEM buffers, and command submission
- [Audio / ALSA (alsa/)](https://kernel-internals.org/alsa/) — the sound subsystem: the card/PCM/control object model, the ring-buffer data path, and ASoC for embedded audio
- [Input / HID (input/)](https://kernel-internals.org/input/) — the input core, evdev, and the self-describing HID report-descriptor protocol
- [TTY / Serial (tty/)](https://kernel-internals.org/tty/) — the teletypewriter-derived terminal model: line disciplines, serial core/UART drivers, and pseudo-terminals
