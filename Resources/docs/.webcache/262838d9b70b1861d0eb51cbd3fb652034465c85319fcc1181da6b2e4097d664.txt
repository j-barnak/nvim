# Interposition points

During the [expansion](https://beautifulracket.com/appendix/glossary.html#expansion) phase of program [evaluation](https://beautifulracket.com/explainer/evaluation.html), Racket wraps certain operations in an extra macro that acts as a hook for providing default behavior. These macros are known as *interposition points*. We can recognize them by their names, which are prefixed with #%.

For instance, [#%module-begin](http://docs.racket-lang.org/reference/module.html#(form._((lib._racket/private/base..rkt)._~23~25module-begin))). When Racket expands a [module](https://beautifulracket.com/explainer/modules.html) expression, it starts by wrapping the body of the expression in #%module-begin. So this:

> The stacker tutorial introduces #%module-begin .

    (module name lang/expander
      body-exprs ···)

Becomes this:

    (#%module-begin ;; imported from `lang/expander`
      body-exprs ···)

Evaluation continues from here, with #%module-begin taking the body-exprs ··· as input and returning a result.

If a needed interposition point isn’t available in the language, then the operation fails. This is why in our language tutorials, we always export a #%module-begin. Under the hood, every source file becomes a module expression. So every language also needs a #%module-begin, or evaluation will always fail.

In most language implementations, it suffices to export the default interposition points, because they give us the vanilla behavior we usually want. But they can be modified if we want to achieve certain special effects, as demonstrated below.

### [Common interposition points](#common-interposition-points)

The easiest way to understand interposition points is to see how they affect the evaluation of a language. In particular, it’s useful to be able to recognize the errors that arise when they’re missing.

Suppose we start making a language in a source file called "lang.rkt":

lang.rkt

    #lang br

Don’t panic—it’s blank, except for the first line. In the same directory, we create a source file that invokes this language:

lang-test.rkt

    #lang reader "lang.rkt"

Don’t panic—it’s blank too. When we run this test file, we get an error:

    read-syntax: cannot find reader for `#lang reader "lang.rkt"'

Though [read-syntax](http://docs.racket-lang.org/reference/Reading.html#(def._((quote._~23~25kernel)._read-syntax))) is not an interposition point, it operates by a similar principle. When Racket runs the language, it automatically looks for the read-syntax function, and passes the source code as input, so it can be turned into a module expression.

> The stacker tutorial introduces read-syntax .

Thus, we can fix this error by adding a simple read-syntax function:

lang.rkt

    #lang br
    (provide read-syntax)
    (define (read-syntax path port)
      (datum->syntax #f
                     `(module lang-mod "lang.rkt"
                        ,@(for/list ([datum (in-port read port)])
                            datum))))

This time, when we run our test file:

lang-test.rkt

    #lang reader "lang.rkt"

We get two new errors:

    module: no #%module-begin binding in the module's language in: (module lang-mod "lang.rkt")

    Interactions disabled: "lang.rkt" does not support a REPL (no #%top-interaction)

Strictly speaking, the first error is being reported by Racket itself (as it tries to run our tiny language), and the second by DrRacket (as it tries to create a [REPL](https://beautifulracket.com/explainer/repl.html) prompt). Notice that both errors arise from a missing interposition point: the first from [#%module-begin](http://docs.racket-lang.org/reference/module.html#(form._((lib._racket/private/base..rkt)._~23~25module-begin))), and the second from [#%top-interaction](http://docs.racket-lang.org/reference/__top-interaction.html#(form._((lib._racket/private/base..rkt)._~23~25top-interaction))).

We can fix these errors the same way we fixed the missing read-syntax: by exporting these identifiers from our language. We can write our own version of each missing macro. Or we can also just export an existing one.

For #%module-begin, let’s do it that way:

lang.rkt

    #lang br
    (provide read-syntax)
    (define (read-syntax path port)
      (datum->syntax #f
                     `(module lang-mod "lang.rkt"
                        ,@(for/list ([datum (in-port read port)])
                            datum))))

    (provide #%module-begin)

When we run our test file again, we only get one error:

    Interactions disabled: "lang.rkt" does not support a REPL (no #%top-interaction)

### [#%top-interaction](#top-interaction)

[#%top-interaction](http://docs.racket-lang.org/reference/__top-interaction.html#(form._((lib._racket/private/base..rkt)._~23~25top-interaction))) implicitly wraps every expression that’s entered at the REPL. Therefore, if we want the REPL to be available in our language, we need to export #%top-interaction. As before, it suffices to reuse the #%top-interaction already available:

lang.rkt

    #lang br
    (provide read-syntax)
    (define (read-syntax path port)
      (datum->syntax #f
                     `(module lang-mod "lang.rkt"
                        ,@(for/list ([datum (in-port read port)])
                            datum))))

    (provide #%module-begin #%top-interaction)

This time, when we run our test file:

lang-test.rkt

    #lang reader "lang.rkt"

We don’t get an error.

Unlike #%module-begin, there’s rarely a useful reason to write a special #%top-interaction. If we want to customize the REPL for a language, we use other tools. (See the [third BASIC tutorial](https://beautifulracket.com/basic-3/the-repl.html) for an example.) But #%top-interaction is still a prerequisite for booting the REPL.

### [#%datum](#datum)

Now let’s put a value in our test file:

lang-test.rkt

    #lang reader "lang.rkt"
    42.0

When we run this file, we get a new error:

    ?: literal data is not allowed;
     no #%datum syntax transformer is bound in: 42.0

[#%datum](http://docs.racket-lang.org/reference/quote.html#(form._((quote._~23~25kernel)._~23~25datum))) is the interposition point that wraps every instance of literal data in a program, like numbers and strings. So 42.0 becomes (#%datum . 42.0), and "str" becomes (#%datum . "str").

If we want to be able to use literal data in a program, we need to export #%datum:

lang.rkt

    #lang br
    (provide read-syntax)
    (define (read-syntax path port)
      (datum->syntax #f
                     `(module lang-mod "lang.rkt"
                        ,@(for/list ([datum (in-port read port)])
                            datum))))

    (provide #%module-begin #%top-interaction #%datum)

With this change, our test file no longer raises an error, and instead prints our value as usual:

    42.0

We can customize #%datum if we want to affect the evaluation of literal values. For example, in the BASIC tutorial, we [converted inexact integers to exact integers](https://beautifulracket.com/basic/the-expander.html#the-stragglers) in the expander. We could move that housekeeping into #%datum:

lang.rkt

    #lang br
    (provide read-syntax)
    (define (read-syntax path port)
      (datum->syntax #f
                     `(module lang-mod "lang.rkt"
                        ,@(for/list ([datum (in-port read port)])
                            datum))))

    (provide #%module-begin  #%top-interaction)

    (provide (rename-out [new-datum #%datum]))
    (define-macro (new-datum . D)
      (with-pattern ([NEW-D (let ([val (syntax->datum #'D)])
                              (if (and (integer? val)
                                       (inexact? val))
                                  (inexact->exact val)
                                  val))])
        #'(#%datum . NEW-D)))

Notice that we use the same basic technique as when we [customize #%module-begin](https://beautifulracket.com/stacker/the-expander.html#programming-our-expander-output). First, we write our new macro with a different name. Second, we pass our customized result to the default #%datum. Third, when we export our macro, we use [rename-out](http://docs.racket-lang.org/reference/require.html#(form._((lib._racket/private/base..rkt)._rename-out))) to change its name to the expected #%datum.

This time, when we run our test file:

lang-test.rkt

    #lang reader "lang.rkt"
    42.0

The literal value 42.0 gets converted to an exact integer:

    42

### [#%app](#app)

Now suppose we want to accomplish the epic feat of subtracting two integers:

lang-test.rkt

    #lang reader "lang.rkt"
    (- 42 10)

Unfortunately, it doesn’t work:

    -: unbound identifier;
     also, no #%app syntax transformer is bound in: -

The “unbound identifier” part of the error can be fixed by exporting [-](http://docs.racket-lang.org/reference/generic-numbers.html#(def._((quote._~23~25kernel)._-))) from our language (we also reset #%datum to its vanilla meaning):

lang.rkt

    #lang br
    (provide read-syntax)
    (define (read-syntax path port)
      (datum->syntax #f
                     `(module lang-mod "lang.rkt"
                        ,@(for/list ([datum (in-port read port)])
                            datum))))

    (provide #%module-begin  #%top-interaction #%datum -)

With that change, we get a more descriptive error:

    -: function application is not allowed;
     no #%app syntax transformer is bound in: (- 42 10)

Just as [#%datum](http://docs.racket-lang.org/reference/quote.html#(form._((quote._~23~25kernel)._~23~25datum))) is the interposition point that wraps every instance of literal data, [#%app](http://docs.racket-lang.org/reference/application.html#(form._((lib._racket/private/base..rkt)._~23~25app))) is the form that wraps every function application. So (- 42 10) becomes (#%app - 42 10). Of course, in this example, the integers are still wrapped by #%datum, so the transformation ends up looking like this:

    (- 42 10)
    (#%app - (#%datum . 42) (#%datum . 10))

We can customize #%app if we want to affect how functions are applied to their arguments. For instance, by default function arguments are evaluated from left to right. We can reverse this behavior by customizing #%app:

lang.rkt

    #lang br
    (provide read-syntax)
    (define (read-syntax path port)
      (datum->syntax #f
                     `(module lang-mod "lang.rkt"
                        ,@(for/list ([datum (in-port read port)])
                            datum))))

    (provide #%module-begin  #%top-interaction #%datum -)

    (provide (rename-out [new-app #%app]))
    (define-macro (new-app ID . ARGS)
      (with-pattern ([SGRA (reverse (syntax->list #'ARGS))])
        #'(#%app ID . SGRA)))

This version of #%app reverses the order of arguments, and then calls the default #%app. With this change, (- 42 10) instead behaves like (- 10 42):

lang-test.rkt

    #lang reader "lang.rkt"
    (- 42 10)

    -32

Alternatively, if we edit our language to use the default #%app:

lang.rkt

    #lang br
    (provide read-syntax)
    (define (read-syntax path port)
      (datum->syntax #f
                     `(module lang-mod "lang.rkt"
                        ,@(for/list ([datum (in-port read port)])
                            datum))))

    (provide #%module-begin  #%top-interaction #%datum - #%app)

We get the usual result:

    32

### [#%top](#top)

To complete our tour of interposition points, let’s swap a variable into our math expression:

lang-test.rkt

    #lang reader "lang.rkt"
    (- 42 x)

This time, we get a new error:

    x: unbound identifier;
     also, no #%top syntax transformer is bound in: x

Every identifier in a program without a local binding (e.g., from [let](http://docs.racket-lang.org/reference/let.html#(form._((lib._racket/private/letstx-scheme..rkt)._let)))) gets wrapped with [#%top](http://docs.racket-lang.org/reference/__top.html#(form._((quote._~23~25kernel)._~23~25top))), which signals “this identifier uses the current top-level binding”. #%top doesn’t know or care whether that binding exists.

It’s true, however, that every unbound identifier gets wrapped with #%top. So we can use #%top to do something about unbound identifiers:

> This stands to reason: if the identifier had some local binding, it wouldn’t be unbound.

lang.rkt

    #lang br
    (provide read-syntax)
    (define (read-syntax path port)
      (datum->syntax #f
                     `(module lang-mod "lang.rkt"
                        ,@(for/list ([datum (in-port read port)])
                            datum))))

    (provide #%module-begin  #%top-interaction #%datum - #%app)

    (provide define (rename-out [my-top #%top]))
    (define-macro (my-top . ID)
      (if (identifier-binding #'ID) #'ID #'25))

In this case, we redefine #%top to check if the identifier is bound (with [identifier-binding](http://docs.racket-lang.org/reference/stxcmp.html#(def._((quote._~23~25kernel)._identifier-binding)))). If it’s bound, we pass it through. If not, we substitute the value 25.

When run our test file again, the undefined x is converted to 25:

lang-test.rkt

    #lang reader "lang.rkt"
    (- 42 x)

    17

Suppose we insert an explicit binding for x with [define](http://docs.racket-lang.org/reference/define.html#(form._((lib._racket/private/base..rkt)._define))):

lang-test.rkt

    #lang reader "lang.rkt"
    (define x 18)
    (- 42 x)

Because x is no longer unbound, the result changes:

    24

But as with our other interposition points, if we just want the usual behavior of #%top, we can export the existing version:

lang.rkt

    #lang br
    (provide read-syntax)
    (define (read-syntax path port)
      (datum->syntax #f
                     `(module lang-mod "lang.rkt"
                        ,@(for/list ([datum (in-port read port)])
                            datum))))

    (provide #%module-begin  #%top-interaction #%datum - #%app #%top)

Finally, if we revert to our original test case:

lang-test.rkt

    #lang reader "lang.rkt"
    (- 42 x)

We get the usual error:

    x: unbound identifier in module in: x

### [Interposition points in br/quicklang](#interposition-points-in-br-quicklang)

The br/quicklang dialect automatically exports the default versions of [#%top](http://docs.racket-lang.org/reference/__top.html#(form._((quote._~23~25kernel)._~23~25top))), [#%app](http://docs.racket-lang.org/reference/application.html#(form._((lib._racket/private/base..rkt)._~23~25app))), [#%datum](http://docs.racket-lang.org/reference/quote.html#(form._((quote._~23~25kernel)._~23~25datum))), and [#%top-interaction](http://docs.racket-lang.org/reference/__top-interaction.html#(form._((lib._racket/private/base..rkt)._~23~25top-interaction))). Why? Because in practice, these forms are rarely customized. But if you’re implementing a language starting from something other than br/quicklang (say, racket/base) then you’ll need to handle this housekeeping yourself.
