# Linux Kernel Internals

A community hub for understanding the Linux kernel — documentation and discussions about design decisions, internals, and the journey of contributing.

## What This Is

**Documentation**: Deep dives into kernel subsystems, explaining *why* things work the way they do, not just the APIs.

**Discussion**: A place to ask questions, share discoveries, and help each other understand the kernel.

## Why?

The kernel has extensive API documentation, but understanding the *rationale* requires digging through mailing list archives, scattered articles, and tribal knowledge. We're building a more accessible resource.

## Documentation

### General

- [Linux Evolution](https://kernel-internals.org/linux-evolution/) — from hobby project to world infrastructure

### Subsystems

**Foundations**

- [Kernel Internals (kernel/)](https://kernel-internals.org/kernel/) — the glue that holds every subsystem together: boot, logging, parameters, panics, and module init
- [Architecture (arch/)](https://kernel-internals.org/arch/arm64/) — where the kernel meets the hardware: boot, CPU features, exceptions, and per-arch specifics (x86, arm64)
- [System Calls (syscalls/)](https://kernel-internals.org/syscalls/) — how user space crosses into the kernel and back
- [Modules (modules/)](https://kernel-internals.org/modules/) — loading, linking, and unloading kernel code at runtime
- [Time (time/)](https://kernel-internals.org/time/) — clocks, timers, ticks, and how the kernel keeps and measures time

**Memory**

- [Memory Management (mm/)](https://kernel-internals.org/mm/) — how the kernel allocates, maps, and reclaims physical and virtual memory
- [IOMMU (iommu/)](https://kernel-internals.org/iommu/) — address translation and isolation between devices and memory

**Scheduling & Concurrency**

- [Scheduler (sched/)](https://kernel-internals.org/sched/) — how the kernel decides which task runs next, and when
- [Locking (locking/)](https://kernel-internals.org/locking/) — the primitives that keep concurrent code correct: spinlocks, mutexes, RCU
- [Interrupts (interrupts/)](https://kernel-internals.org/interrupts/) — handling hardware events and safely deferring work
- [IPC (ipc/)](https://kernel-internals.org/ipc/) — how processes communicate: pipes, signals, shared memory, message queues

**Storage & I/O**

- [VFS (vfs/)](https://kernel-internals.org/vfs/) — the abstraction that lets one API drive every filesystem
- [Filesystems (filesystems/)](https://kernel-internals.org/filesystems/) — how on-disk formats and the page cache turn bytes into files
- [Block Layer (block/)](https://kernel-internals.org/block/) — the path from a filesystem request to a physical device
- [I/O Patterns (io/)](https://kernel-internals.org/io/) — buffered vs. direct, sync vs. async, and the tradeoffs between them
- [io_uring (io-uring/)](https://kernel-internals.org/io-uring/) — the ring-based interface for high-performance asynchronous I/O

**Devices & Drivers**

- [Drivers (drivers/)](https://kernel-internals.org/drivers/) — the device model and how drivers bind to hardware
- [USB (usb/)](https://kernel-internals.org/usb/) — the host-scheduled, hot-pluggable peripheral bus: descriptors, endpoints, and URBs
- [GPU / DRM (drm/)](https://kernel-internals.org/drm/) — the graphics and display stack: KMS modesetting, GEM buffers, and command submission

**Networking & BPF**

- [Networking (net/)](https://kernel-internals.org/net/network-stack-overview/) — the journey of a packet through the stack, from socket to wire
- [BPF (bpf/)](https://kernel-internals.org/bpf/) — running sandboxed programs in the kernel for tracing, networking, and security

**Isolation & Security**

- [Cgroups (cgroups/)](https://kernel-internals.org/cgroups/) — accounting for and limiting resources per group of processes; the basis of containers
- [Security (security/)](https://kernel-internals.org/security/) — LSMs, capabilities, seccomp, and the kernel's access-control machinery
- [Virtualization (virtualization/)](https://kernel-internals.org/virtualization/) — KVM and how the kernel runs guest machines
- [Crypto (crypto/)](https://kernel-internals.org/crypto/) — the kernel's cryptographic API and hardware acceleration
- [Livepatch (livepatch/)](https://kernel-internals.org/livepatch/) — patching a running kernel without rebooting

**Observability**

- [Tracing (tracing/)](https://kernel-internals.org/tracing/) — ftrace, tracepoints, and perf: seeing what the kernel is doing
- [Debugging (debugging/)](https://kernel-internals.org/debugging/) — tools and techniques for diagnosing kernel problems
- [Power Management (power/)](https://kernel-internals.org/power/) — suspend, resume, cpufreq, and idle states

## Disclaimer

This is a community learning resource, not a definitive reference. The Linux kernel is complex and constantly evolving. While we strive for accuracy and link to primary sources (commits, LKML), errors may exist. When in doubt, consult the [official kernel documentation](https://docs.kernel.org/) and source code. Contributions and corrections are welcome.
