# Enum IntErrorKind Copy item path

1.55.0 · [Source](https://doc.rust-lang.org/src/core/num/error.rs.html#93)

``` rust
#[non_exhaustive]pub enum IntErrorKind {
    Empty,
    InvalidDigit,
    PosOverflow,
    NegOverflow,
    Zero,
    NotAPowerOfTwo,
}
```

Expand description

Enum to store the various types of errors that can cause parsing or converting an integer to fail.

## Example

``` rust
if let Err(e) = i32::from_str_radix("a12", 10) {
    println!("Failed conversion to i32: {:?}", e.kind());
}
```

## Variants (Non-exhaustive)

This enum is marked as non-exhaustive

Non-exhaustive enums could have additional variants added in future. Therefore, when matching against variants of non-exhaustive enums, an extra wildcard arm must be added to account for any future variants.

1.55.0

Value being parsed is empty.

This variant will be constructed when parsing an empty string.

1.55.0

Contains an invalid digit in its context.

Among other causes, this variant will be constructed when parsing a string that contains a non-ASCII char.

This variant is also constructed when a `+` or `-` is misplaced within a string either on its own or in the middle of a number.

1.55.0

Integer is too large to store in target integer type.

1.55.0

Integer is too small to store in target integer type.

1.55.0

Value was Zero

This variant will be emitted when the parsing string or the converting integer has a value of zero, which would be illegal for non-zero types.

🔬This is a nightly-only experimental API. (`try_from_int_error_kind` [\#153978](https://github.com/rust-lang/rust/issues/153978))

Value is not a power of two.

This variant will be emitted when converting an integer that is not a power of two. This is required in some cases such as constructing an [`Alignment`](https://doc.rust-lang.org/std/mem/struct.Alignment.html "mem::Alignment").
