- Read [GCC Cross-Compiler](https://wiki.osdev.org/GCC_Cross-Compiler "GCC Cross-Compiler").
- Make a [OS Specific Toolchain](https://wiki.osdev.org/OS_Specific_Toolchain "OS Specific Toolchain").
- Read [Hosted GCC Cross-Compiler](https://wiki.osdev.org/Hosted_GCC_Cross-Compiler "Hosted GCC Cross-Compiler").
- Have a sufficient [C Library](https://wiki.osdev.org/C_Library "C Library"). GCC is fairly portable and needs the C standard library, and some extensions from POSIX. It needs fork and exec, for instance, to run the assembler and linker. You will need a C++ standard library (such as libstdc++) as GCC is now written in [C++](https://wiki.osdev.org/C++ "C++").
- Cross-compile libgmp, libmpc, libmpfr and other dependencies with instructions in [Cross-Porting Software](https://wiki.osdev.org/Cross-Porting_Software "Cross-Porting Software").
- Likewise cross-compile [Binutils](https://wiki.osdev.org/Binutils "Binutils") and [GCC](https://wiki.osdev.org/GCC "GCC"), but pass the special configure options `--with-build-sysroot=/your/sysroot` and `--with-sysroot=/`. The option `--with-build-sysroot` option uses that [sysroot](https://wiki.osdev.org/Sysroot "Sysroot") for the duration of the build, but the final program does not remember it. `--with-sysroot=/` should not be needed or should be set to the empty string, but some binutils/gcc versions are buggy and require it, which has the disadvantage the final toolchain might use `//foo` instead of `/foo`. You should *only* pass these options to the Binutils and GCC builds, some other packages also have a `--with-sysroot` option, but it instead means a libtool feature you should *not* use.
- Become self-hosting and complete [Bare Bones II](https://wiki.osdev.org/Bare_Bones#Bare_Bones_II "Bare Bones"). Congratulations.
