Multitasking Systems are operating systems (or even system extensions) which share available processor time between multiple tasks automatically.

## Types of Multitasking Systems

There are many ways multitasking can be achieved.

### Cooperative Multitasking

For [cooperative multitasking](https://wiki.osdev.org/Cooperative_Multitasking "Cooperative Multitasking"), a task uses the CPU until it voluntarily gives up the CPU (e.g. yields or exits). Examples of cooperative multitasking systems are pre-X MacOS, or Windows 3.x.

In some single language cooperative multitasking systems, such as Oberon and ruby, the compiler/interpreter automatically ensures that the code will periodically yield control; it allows such program to run multiple threads on operating systems such as DOS.

### Preemptive Multitasking

[Preemptive multitasking](https://wiki.osdev.org/index.php?title=Preemptive_Multitasking&action=edit&redlink=1 "Preemptive Multitasking (page does not exist)") system is an extension of cooperative multitasking, where some task switches are becoming involuntary, and are done for one or more reasons (including when the task consumed the time it was given and/or when a higher priority task needed the CPU). It is important to emphasize here that the involuntary preemption is usually a last resort for the kernel, and in a well-designed system, most of the task switches are/should still be voluntary (as in a purely cooperatively multitasked system).

Examples include almost all modern operating systems - e.g. Linux, \*BSD, post-3.x Windows, BeOS, AmigaOS.

You can further subdivide these systems into those who can preempt tasks, and those who can preempt *the kernel itself*. Linux (pre-2.6 kernel) is an example of the former, while e.g. AmigaOS is an example for the latter. This is a major concern for multimedia applications or any "soft" \[Real-Time Systems\] because a non-preemptive kernel introduces latencies that can ruin such "near real-time" performance.

### Real-Time Multitasking

In a Real-Time Operating System (RTOS), the scheduler works in a specific kind of [preemptive multitasking](https://wiki.osdev.org/index.php?title=Preemptive_Multitasking&action=edit&redlink=1 "Preemptive Multitasking (page does not exist)") system. It is designed for applications requiring responses within a fixed time window and tight time constraints. These systems are crucial in fields where delay can result in failure of the application.

However, a Real-Time OS can also be slow. The main goal of a RTOS is to complete tasks within the scheduled timeframe. This means that it isn't any slower or any faster. A RTOS guarantees not speed, but reliability. It is crucial for applications that cannot tolerate delays, such as avionics and aerospace systems, embedded medical devices or automotive controls.
