# Control Flow Analysis

*Cited in the Decompilation Wiki: Overview; Structuring Overview; Loop Reduction*

Frances E. Allen, "Control Flow Analysis," *SIGPLAN Notices*, Vol. 5, No. 7 (July 1970), pp. 1-19. IBM Corporation.

## Introduction

Allen opens by observing that any static, global analysis of the expression and data relationships in a program depends on knowing the program's control flow. Because a primary reason for such analysis in a compiler is to produce optimized programs, control flow analysis had already been embedded in many compilers and described in the literature. She credits an early paper by Prosser with using Boolean matrices (specifically connectivity matrices) for flow analysis, notes that Prosser introduced "dominance" relationships (much expanded by Lowry and Medlock), and points to other compilers and recent developments using flow analysis for optimization.

The common motivation across these techniques is the need to codify the flow relationships of a program, whether as connectivity matrices, predecessor-successor tables, dominance lists, or otherwise. Whatever the form, the purpose is to make it easy to answer questions such as: is this an inner loop?, where can an expression removed from a loop be correctly and profitably placed?, and which variable definitions can affect a given use?

The paper's approach is to express the basic control flow relationships as a **directed graph**, then find graph constructs that codify interesting global relationships. Allen lays out the paper's structure: "Basic Concepts" catalogs directed-graph terminology; "Dominance Relationships" defines back and forward dominance; "Intervals" introduces a construct due to Dr. John Cocke, with a construction procedure and properties given as assertions; "Partitioning Graphs by Intervals" describes a hierarchical sequence of graph partitions; and a final section illustrates using intervals in global analysis.

## Basic Concepts

A directed graph is written *G = (B, E)*, where *B* is the set of nodes (blocks) *{b₁, b₂, ..., bₙ}* and *E* is the set of directed edges, each an ordered pair *(bᵢ, bⱼ)*. A **successor function** *F<sub>G</sub>* maps a node to its set of immediate successors, *F<sub>G</sub>(bᵢ) = {bⱼ | (bᵢ, bⱼ) ∈ E}*; its inverse *F<sub>G</sub>⁻¹* gives the immediate predecessors. Either set may be empty. A graph is **connected** if any node can be reached from any other by successive applications of *F<sub>G</sub>* and/or *F<sub>G</sub>⁻¹*; the paper assumes throughout that graphs are both directed and connected.

Allen then ties graphs to programs. A **basic block** is "a linear sequence of program instructions having one entry point (the first instruction executed) and one exit point (the last instruction executed)." A **control flow graph** is a directed graph whose nodes are basic blocks and whose edges are control flow paths; everything said about directed graphs applies to control flow graphs. A **subgraph** *G' = (B', E')* has *B' ⊆ B*, *E' ⊆ E*, and a successor function that "stays within" *G'*.

A **path** is a directed subgraph of ordered nodes and edges obtained by successive applications of the successor function, expressed as a sequence *(b₁, b₂, ..., bₙ)* with *bᵢ₊₁ ∈ F<sub>G</sub>(bᵢ)*; nodes and edges need not be unique. Node *q* is a **successor** of *p* (and *p* a **predecessor** of *q*) if some path runs from *p* to *q*. A **closed path** or **circuit** has *bₙ = b₁*; it is **simple** if its nodes (except the endpoint) are distinct, otherwise **composite**. The **length** of a path is its number of edges, defined via a distance function *δ(P) = n − 1*, and *δ<sub>min</sub>(p, q)* is the shortest-path distance.

A **strongly connected region** is a directed subgraph in which a path exists from any node to any other; every node therefore lies on a closed path and is its own predecessor and successor. A strongly connected region is **maximal** if no larger one contains it. Allen describes a construct *D*, a set of disjoint sets of properly nested strongly connected regions (each set *d* partially ordered, *D* itself unordered), citing her own earlier work as the first suggestion of using such nested sets for optimization. She notes its limitations: *D* does not necessarily cover the whole graph, does not impose an ordering on the total graph, and imposes no ordering within a region beyond immediate successor-predecessor relationships.

## Dominance Relationships

To define dominance, two special node kinds are introduced. A **terminal** or **exit node** *x* has no successors, *F<sub>G</sub>(x) = ∅*. An **entry node** contains a program entry point; because an entry may also lie on a closed path (and thus have a predecessor), Allen introduces a single artificial initial node *e₀* as the immediate predecessor of all entry nodes, with no predecessors of its own. Every subsequent graph is a connected directed graph with one entry node *e₀* and a set of exit nodes *X*.

Node *bᵢ* **back dominates** (predominates) node *bₖ* if *bᵢ* lies on every path from *e₀* to *bₖ*. The set of back dominators is *BD(bₖ) = {bᵢ | bᵢ ≠ bₖ and bᵢ is on every path from e₀ to bₖ}*. The **immediate back dominator** is the back dominator "closest" to *bₖ* by *δ<sub>min</sub>*. Allen shows there is exactly one immediate back dominator for any *bₖ ≠ e₀*, and that the back dominators of a node are strictly ordered by the minimum distance function, forming a list *BD(bₖ) = (b₁, b₂, ..., bⱼ)* with *b₁ = e₀*, each the immediate back dominator of the next.

Symmetrically, *bᵢ* **forward dominates** (post dominates) *bₖ* if it lies on every path from *bₖ* to all exit nodes. By adding a node *x₀* whose predecessors are all exit nodes *X*, the forward-dominance development parallels back dominance exactly and yields a forward-dominator list *FD(bₖ)*. Finally, an **articulation node** lies on every entry-exit path; for a graph with single entry *e₀*, the forward dominators of *e₀*, together with *e₀* itself, are the articulation nodes of the graph.

## Intervals

The interval is the paper's central original construct, attributed to Dr. John Cocke. Given a node *h*, an **interval I(h)** is "the maximal, single entry subgraph for which h is the entry node and in which all closed paths contain h." The unique node *h* is the **interval head** or **header node**. By choosing the proper header nodes, a graph can be partitioned into a unique set of intervals (a partition being a set of disjoint subgraphs that together cover the graph).

**Procedure A** partitions *G* into intervals: initialize a header list *H* to *e₀*; for each *h ∈ H*, build *I(h)* by adding *h*, then repeatedly adding any node all of whose immediate predecessors are already in *I(h)*, until no more can be added; then add to *H* any node not yet in *H*, not in *I(h)*, but having an immediate predecessor in *I(h)*; add *I(h)* to the interval set; and process the next unprocessed node in *H*. A node is added to an interval only when **all** of its immediate predecessors are in it, and becomes a header the first time **some but not all** of its predecessors are in an interval. Allen notes her implementation kept per-node counts so an edge is never traversed more than once, making the procedure's execution time directly proportional to the number of edges in the graph.

She then proves the construct's properties through a series of **assertions**. Assertions 1-3 establish that *I(h)* has only one possible entry node *h*, that all closed paths in *I(h)* contain *h*, and that *I(h)* is maximal. Assertions 4-11 develop further properties using a **local successor function** *L<sub>I</sub>* (immediate successors within the interval, excluding the header) and the notion of a **forward path**: Assertion 4, the header back dominates every interval node; Assertion 5, interval nodes are partially ordered by the local successor function; Assertion 6, the relative ordering of nodes in a back-dominator list matches their order in the interval; Assertion 8, any strongly connected region in an interval must contain the interval head (so an interval cannot contain disjoint strongly connected regions); and Assertions 10-11, the header (with the interval-member forward dominators of the header) are the articulation nodes of the interval. A **two-terminal subgraph** is defined as an interval with a single exit node.

Allen gives concrete procedures, embeddable in Procedure A so that intervals and their relationships are found in "one pass" through the graph's edges, and notes a **bit vector** representation (one bit per interval position) that lets Boolean operations replace set operations while automatically preserving node order. **Procedure B** finds each node's back dominators by intersecting, across all of a node's immediate predecessors, each predecessor unioned with that predecessor's own back-dominator set (that is, *BD(bⱼ) = ⋂ (bᵢ ∪ BD(bᵢ))* over the immediate predecessors *bᵢ*); **Procedure C** finds interval articulation nodes by intersecting, over the interval exits, each exit unioned with its back dominators; **Procedure D** finds local predecessors; and **Procedure E** (with an alternative marking variant E′) finds the interval's strongly connected region from its **latching nodes** (nodes having the header as an immediate successor). Worked examples on a six-node interval *I(h) = (1,2,5,3,4,6)* illustrate each procedure.

## Partitioning Graphs by Intervals

Allen proves (Assertions 12-14) that the set of intervals ℐ produced by Procedure A forms a **unique partition** of *G*: ℐ covers *G* (Assertion 12), its intervals are pairwise disjoint (Assertion 13, with sub-parts showing header nodes are distinct, a header cannot belong to another interval, and any two intervals intersect in the empty set), and ℐ is unique regardless of the order in which *H* is processed (Assertion 14).

She then builds a hierarchy. The intervals formed from the graph's basic blocks are the **first order** (basic) intervals of the **first order graph**. A **second order graph** is derived by collapsing each first order interval into a single node, with predecessors and successors inherited from the original header's external predecessors and the exit nodes' external successors. Repeating yields successively higher order graphs until the *n*-th order graph is a single node or is irreducible. A **reducible** graph is one "whose n-th order derived graph is a single node"; an **irreducible** graph is one for which no such single-node derived graph exists, which happens when every interval is a single node with no internal flow paths. Allen reports a notable empirical result: a program she wrote to analyze FORTRAN control flow "found that over 90% of the control flow graphs were reducible," over a dataset of 75 real programs, and cites a Cocke-Miller node-splitting method for turning an irreducible graph into an equivalent reducible one.

Assuming reduction to a single node, she draws three observations: every basic block lies in exactly one interval at each order, giving each block a unique strictly ordered chain of membership *bᵢ ∈ I¹(h₁) ⊆ I²(h₂) ⊆ ... ⊆ Iⁿ(hₙ)*; and because nodes within each interval are partially ordered by the local successor function, the nodes of the entire graph are ordered by that function.

## The Use of the Interval Construct in Global Analysis

The final section sketches how intervals drive global analysis, via **Procedure F (Skeletal)**. Information of global interest is first collected at each basic block's entry and exit. Then, order by order, the analysis proceeds through each *k*-order interval in interval order, modifying each block's information to reflect interval predecessors and promulgating it to successors, with a second pass to handle information from latching nodes (loops). The information collected for each interval is associated with the node representing it in the next higher order graph, and the process repeats up to the *n*-th order graph. A backward sweep (steps 4-7) then propagates the information deposited at each level back down to the basic blocks, so that global information is finally available at every block.

Allen illustrates this with a **reaching-definitions** example ("which basic blocks each definition can reach") on the graph of Figure 4, tracing definitions of variables *A*, *B*, and *C* through the interval hierarchy up and back down (Figures 5-14). She notes in passing an omitted but easily collected piece of information (whether a definition reaching a node's entry can also reach its exit) and comments that **bit vector techniques**, using simple Boolean operations on vectors encoding multiple definitions, exist to carry the information efficiently through the graph.

## Summary

The interval construct has many properties that facilitate global analysis and are of particular interest in optimization: the partial ordering of nodes within an interval provides a natural processing order; partitioning a graph into a hierarchy of partially ordered intervals lets information propagate rapidly through the graph; dominance relationships are easily discovered; and nests of strongly connected regions can be detected. Allen notes the paper only hints at the use of intervals in optimization proper, referring the reader to Cocke's companion paper on global common subexpression elimination.

## Acknowledgements and References

Allen credits the interval concept to Dr. John Cocke, a major contributor to many of the paper's other ideas, and Dr. J. T. Schwartz for first formalizing many aspects of intervals. The references include Prosser's Boolean-matrix flow-diagram analysis, Lowry and Medlock's object code optimization, Berge's *The Theory of Graphs*, Cocke and Schwartz's compiler notes, Cocke's companion paper in the same proceedings, and Cocke and Miller's node-splitting analysis techniques.

SUMMARY
The interval construct described in this paper has many properties which facilitate global analysis and which are of particular
interest in optimization.
The partial ordering relationships
between nodes in an interval provide a natural processing order; the
ability to partition a graph into a hierarchy of intervals each of
which is partially ordered lets us propagate information rapidly
through the graph; the dominance relationships in a graph are easily
discovered; nests of strongly connected regions can be detected.
Although this paper has not shown how all of these constructs can be
found most of them should be apparent. The use of intervals in
optimization has only been hinted at; for a good explanation the
reader is referred to reference [3].
