Expand description

A type storing a `usize` which is a power of two, and thus represents a possible alignment in the Rust abstract machine.

Note that particularly large alignments, while representable in this type, are likely not to be supported by actual allocators and linkers.

🔬This is a nightly-only experimental API. (`ptr_alignment_type` [\#102070](https://github.com/rust-lang/rust/issues/102070))

Returns the [ABI](https://en.wikipedia.org/wiki/Application_binary_interface)-required minimum alignment of the type of the value that `val` points to.

This function is identical to [`Alignment::of::<T>()`](https://doc.rust-lang.org/std/mem/struct.Alignment.html#method.of "associated function std::mem::Alignment::of") whenever `T: `[`Sized`](https://doc.rust-lang.org/std/marker/trait.Sized.html "trait std::marker::Sized"), but also supports determining the alignment required by a `dyn Trait` value, which is the alignment of the underlying concrete type.

This provides the same numerical value as [`align_of_val`](https://doc.rust-lang.org/std/mem/fn.align_of_val.html "fn std::mem::align_of_val"), but in an `Alignment` instead of a `usize`.

##### Examples

``` rust
#![feature(ptr_alignment_type)]
use std::mem::Alignment;

assert_eq!(Alignment::of_val(&5i32).as_usize(), 4);
```

(Caution: [it is not guaranteed](https://doc.rust-lang.org/reference/type-layout.html#r-layout.primitive) that the alignment of `i32` is `4`; that is, the above assertion does not pass on all platforms.)

`dyn` types may have different alignments for different values; `Alignment::of_val()` can be used to learn those alignments:

``` rust
#![feature(ptr_alignment_type)]
use std::mem::Alignment;

let a: &dyn ToString = &1234u16;
let b: &dyn ToString = &String::from("abcd");

assert_eq!(Alignment::of_val(a), Alignment::of::<u16>());
assert_eq!(Alignment::of_val(b), Alignment::of::<String>());
```

🔬This is a nightly-only experimental API. (`ptr_alignment_type` [\#102070](https://github.com/rust-lang/rust/issues/102070))

Returns the [ABI](https://en.wikipedia.org/wiki/Application_binary_interface)-required minimum alignment of the type of the value that `val` points to.

This function is identical to [`Alignment::of_val()`](https://doc.rust-lang.org/std/mem/struct.Alignment.html#method.of_val "associated function std::mem::Alignment::of_val"), except that it can be used with raw pointers in situations where it would be unsound or undesirable to convert them to [`&` references](https://doc.rust-lang.org/std/primitive.reference.html "primitive reference") and impose the aliasing rules that come with that.

##### Safety

This function is only safe to call if the following conditions hold:

- If `T` is `Sized`, this function is always safe to call.
- If the unsized tail of `T` is:
  - a [slice](https://doc.rust-lang.org/std/primitive.slice.html "primitive slice"), then the length of the slice tail must be an initialized integer, and the size of the *entire value* (dynamic tail length + statically sized prefix) must fit in `isize`. For the special case where the dynamic tail length is 0, this function is safe to call.
  - a [trait object](https://doc.rust-lang.org/book/ch17-02-trait-objects.html), then the vtable part of the pointer must point to a valid vtable acquired by an unsizing coercion, and the size of the *entire value* (dynamic tail length + statically sized prefix) must fit in `isize`.
  - an (unstable) [extern type](https://doc.rust-lang.org/unstable-book/language-features/extern-types.html), then this function is always safe to call, but may panic or otherwise return the wrong value, as the extern type’s layout is not known. This is the same behavior as [`Alignment::of_val`](https://doc.rust-lang.org/std/mem/struct.Alignment.html#method.of_val "associated function std::mem::Alignment::of_val") on a reference to a type with an extern type tail.
  - otherwise, it is conservatively not allowed to call this function.

##### Examples

``` rust
#![feature(ptr_alignment_type)]
use std::mem::Alignment;

assert_eq!(unsafe { Alignment::of_val_raw(&5i32) }.as_usize(), 4);
```

(Caution: [it is not guaranteed](https://doc.rust-lang.org/reference/type-layout.html#r-layout.primitive) that the alignment of `i32` is `4`; that is, the above assertion does not pass on all platforms.)

`align` must be a power of two.

🔬This is a nightly-only experimental API. (`ptr_alignment_type` [\#102070](https://github.com/rust-lang/rust/issues/102070))

Returns a bit mask that can be used to match this alignment.

This is equivalent to `!(self.as_usize() - 1)`.

##### Examples

``` rust
#![feature(ptr_mask)]
#![feature(ptr_alignment_type)]
use std::mem::Alignment;
use std::ptr::NonNull;

#[repr(align(1))] struct Align1(u8);
#[repr(align(2))] struct Align2(u16);
#[repr(align(4))] struct Align4(u32);
let one = <NonNull<Align1>>::dangling().as_ptr();
let two = <NonNull<Align2>>::dangling().as_ptr();
let four = <NonNull<Align4>>::dangling().as_ptr();

assert_eq!(four.mask(Alignment::of::<Align1>().mask()), four);
assert_eq!(four.mask(Alignment::of::<Align2>().mask()), four);
assert_eq!(four.mask(Alignment::of::<Align4>().mask()), four);
assert_ne!(one.mask(Alignment::of::<Align4>().mask()), one);
```
