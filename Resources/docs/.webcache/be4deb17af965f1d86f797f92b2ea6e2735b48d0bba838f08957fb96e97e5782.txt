# Programs

*class *drgn.Program  
A `Program` represents a crashed or running program. It can be used to lookup type definitions, access variables, and read arbitrary memory.

The main functionality of a `Program` is looking up objects (i.e., variables, constants, or functions). This is usually done with the [`[]`](#drgn.Program.__getitem__ "drgn.Program.__getitem__") operator.

Parameters:  
- **platform** – The platform of the program, or `None` if it should be determined automatically when a core dump or symbol file is added.

- **vmcoreinfo** – Optionally provide the `VMCOREINFO` note data for Linux kernel core dumps, which will override any detected data. When not provided or `None`, automatically detect the info.

flags*: [ProgramFlags](#drgn.ProgramFlags "drgn.ProgramFlags")*  
Flags which apply to this program.

platform*: [Optional](https://docs.python.org/3/library/typing.html#typing.Optional "(in Python v3.14)")\[[Platform](#drgn.Platform "drgn.Platform")\]*  
Platform that this program runs on, or `None` if it has not been determined yet.

core_dump_path*: [Optional](https://docs.python.org/3/library/typing.html#typing.Optional "(in Python v3.14)")\[[str](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)")\]*  
Path of the core dump that this program was created from, or `None` if it was not created from a core dump.

language*: [Language](#drgn.Language "drgn.Language")*  
Default programming language of the program.

This is used for interpreting the type name given to [`type()`](#drgn.Program.type "drgn.Program.type") and when creating an [`Object`](#drgn.Object "drgn.Object") without an explicit type.

For the Linux kernel, this defaults to [`Language.C`](#drgn.Language.C "drgn.Language.C"). For userspace programs, this defaults to the language of `main` in the program, falling back to [`Language.C`](#drgn.Language.C "drgn.Language.C"). This heuristic may change in the future.

This can be explicitly set to a different language (e.g., if the heuristic was incorrect).

\_\_getitem\_\_(*name: [str](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)")*) → [Object](#drgn.Object "drgn.Object")  
Implement `self[name]`. Get the object (variable, constant, or function) with the given name.

This is equivalent to `prog.object(name)`.

If there are multiple objects with the same name, one is returned arbitrarily. In this case, the [`variable()`](#drgn.Program.variable "drgn.Program.variable"), [`constant()`](#drgn.Program.constant "drgn.Program.constant"), [`function()`](#drgn.Program.function "drgn.Program.function"), or [`object()`](#drgn.Program.object "drgn.Program.object") methods can be used instead.

    >>> prog['jiffies']
    Object(prog, 'volatile unsigned long', address=0xffffffff94c05000)

Parameters:  
**name** – Object name.

symbol(*address_or_name: [Union](https://docs.python.org/3/library/typing.html#typing.Union "(in Python v3.14)")\[[IntegerLike](#drgn.IntegerLike "drgn.IntegerLike"), [str](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)")\]*, */*) → [Symbol](#drgn.Symbol "drgn.Symbol")  
Get a symbol containing the given address, or a symbol with the given name.

If there are multiple symbols containing a given address, then this will attempt to find the closest match.

If searching by name or if there is a tie, global symbols are preferred over weak symbols, and weak symbols are preferred over other symbols. In other words: if a matching [`SymbolBinding.GLOBAL`](#drgn.SymbolBinding.GLOBAL "drgn.SymbolBinding.GLOBAL") or [`SymbolBinding.UNIQUE`](#drgn.SymbolBinding.UNIQUE "drgn.SymbolBinding.UNIQUE") symbol is found, it is returned. Otherwise, if a matching [`SymbolBinding.WEAK`](#drgn.SymbolBinding.WEAK "drgn.SymbolBinding.WEAK") symbol is found, it is returned. Otherwise, any matching symbol (e.g., [`SymbolBinding.LOCAL`](#drgn.SymbolBinding.LOCAL "drgn.SymbolBinding.LOCAL")) is returned. If there is still a tie, one is returned arbitrarily. To retrieve all matching symbols, use [`symbols()`](#drgn.Program.symbols "drgn.Program.symbols").

Parameters:  
**address_or_name** – Address or name to search for.

Raises:  
[**LookupError**](https://docs.python.org/3/library/exceptions.html#LookupError "(in Python v3.14)") – if no symbol contains the given address or matches the given name

symbols(*address_or_name: [Union](https://docs.python.org/3/library/typing.html#typing.Union "(in Python v3.14)")\[[None](https://docs.python.org/3/library/constants.html#None "(in Python v3.14)"), [IntegerLike](#drgn.IntegerLike "drgn.IntegerLike"), [str](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)")\] = None*, */*) → [List](https://docs.python.org/3/library/typing.html#typing.List "(in Python v3.14)")\[[Symbol](#drgn.Symbol "drgn.Symbol")\]  
Get a list of global and local symbols, optionally matching a name or address.

If a string argument is given, this returns all symbols matching that name. If an integer-like argument given, this returns a list of all symbols containing that address. If no argument is given, all symbols in the program are returned. In all cases, the symbols are returned in an unspecified order.

Parameters:  
**address_or_name** – Address or name to search for.

stack_trace(*thread: [Union](https://docs.python.org/3/library/typing.html#typing.Union "(in Python v3.14)")\[[Object](#drgn.Object "drgn.Object"), [IntegerLike](#drgn.IntegerLike "drgn.IntegerLike")\]*) → [StackTrace](#drgn.StackTrace "drgn.StackTrace")  
Get the stack trace for the given thread in the program.

`thread` may be a thread ID (as defined by *[gettid(2)](http://man7.org/linux/man-pages/man2/gettid.2.html)*), in which case this will unwind the stack for the thread with that ID. The ID may be a Python `int` or an integer [`Object`](#drgn.Object "drgn.Object")

`thread` may also be a `struct`` ``pt_regs` or `struct`` ``pt_regs`` ``*` object, in which case the initial register values will be fetched from that object.

Finally, if debugging the Linux kernel, `thread` may be a `struct`` ``task_struct`` ``*` object, in which case this will unwind the stack for that task. See [`drgn.helpers.linux.pid.find_task()`](https://drgn.readthedocs.io/en/latest/helpers.html#drgn.helpers.linux.pid.find_task "drgn.helpers.linux.pid.find_task").

This is implemented for the Linux kernel (both live and core dumps) as well as userspace core dumps; it is not yet implemented for live userspace processes.

Parameters:  
**thread** – Thread ID, `struct`` ``pt_regs` object, or `struct`` ``task_struct`` ``*` object.

stack_trace_from_pcs(*pcs: [Sequence](https://docs.python.org/3/library/typing.html#typing.Sequence "(in Python v3.14)")\[[IntegerLike](#drgn.IntegerLike "drgn.IntegerLike")\]*) → [StackTrace](#drgn.StackTrace "drgn.StackTrace")

source_location(*address: [Union](https://docs.python.org/3/library/typing.html#typing.Union "(in Python v3.14)")\[[IntegerLike](#drgn.IntegerLike "drgn.IntegerLike"), [str](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)")\]*, */*) → [SourceLocationList](#drgn.SourceLocationList "drgn.SourceLocationList")  
Find the source code location containing a code address.

The address may be given as an integer or a string. A string argument must be a symbol name or hexadecimal address, optionally followed by a `+` character and a decimal or hexadecimal offset. Hexadecimal numbers must be prefixed with “0x” or “0X”. Whitespace between tokens is ignored.

    >>> prog.source_location("__schedule")
    __schedule at kernel/sched/core.c:6646:1
    >>> prog.source_location("__schedule+0x2b6")
    #0  context_switch at kernel/sched/core.c:5381:9
    #1  __schedule at kernel/sched/core.c:6765:8
    >>> prog.source_location(0xffffffffb64d70a6)
    #0  context_switch at kernel/sched/core.c:5381:9
    #1  __schedule at kernel/sched/core.c:6765:8

Because of function inlining, a code address may actually correspond to multiple source code locations. So, this returns a sequence of locations, where the first item corresponds to the innermost inlined function, the second item is its caller, etc.

Note

This is similar to *[addr2line(1)](http://man7.org/linux/man-pages/man1/addr2line.1.html)*.

Parameters:  
**address** – Code address.

Raises:  
[**LookupError**](https://docs.python.org/3/library/exceptions.html#LookupError "(in Python v3.14)") – if the source code location is not found

type(*type: [Type](#drgn.Type "drgn.Type")*, */*) → [Type](#drgn.Type "drgn.Type")  
Return the given type.

This is mainly useful so that helpers can use `prog.type()` to get a [`Type`](#drgn.Type "drgn.Type") regardless of whether they were given a [`str`](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)") or a [`Type`](#drgn.Type "drgn.Type"). For example:

    def my_helper(obj: Object, type: Union[str, Type]) -> bool:
        # type may be str or Type.
        type = obj.prog_.type(type)
        # type is now always Type.
        return sizeof(obj) > sizeof(type)

Parameters:  
**type** – Type.

Returns:  
The exact same type.

crashed_thread() → [Thread](#drgn.Thread "drgn.Thread")  
Get the thread that caused the program to crash.

For userspace programs, this is the thread that received the fatal signal (e.g., `SIGSEGV` or `SIGQUIT`).

For the kernel, this is the thread that panicked (either directly or as a result of an oops, `BUG_ON()`, etc.).

Raises:  
- [**ValueError**](https://docs.python.org/3/library/exceptions.html#ValueError "(in Python v3.14)") – if the program is live (i.e., not a core dump)

- [**LookupError**](https://docs.python.org/3/library/exceptions.html#LookupError "(in Python v3.14)") – if the crashed thread was not found

read(*address: [IntegerLike](#drgn.IntegerLike "drgn.IntegerLike")*, *size: [IntegerLike](#drgn.IntegerLike "drgn.IntegerLike")*, *physical: [bool](https://docs.python.org/3/library/functions.html#bool "(in Python v3.14)") = False*) → [bytes](https://docs.python.org/3/library/stdtypes.html#bytes "(in Python v3.14)")  
Read *size* bytes of memory starting at *address* in the program.

The address may be virtual (the default) or physical if the program supports it.

    >>> prog.read(0xffffffffbe012b40, 16)
    b'swapper/0\x00\x00\x00\x00\x00\x00\x00'

Parameters:  
- **address** – Starting address.

- **size** – Number of bytes to read.

- **physical** – Whether *address* is a physical memory address. If `False`, then it is a virtual memory address. Physical memory can usually only be read when the program is an operating system kernel.

Raises:  
- [**FaultError**](#drgn.FaultError "drgn.FaultError") – if the address range is invalid or the type of address (physical or virtual) is not supported by the program

- [**ValueError**](https://docs.python.org/3/library/exceptions.html#ValueError "(in Python v3.14)") – if *size* is negative

read_c_string(*address: [IntegerLike](#drgn.IntegerLike "drgn.IntegerLike")*, *physical: [bool](https://docs.python.org/3/library/functions.html#bool "(in Python v3.14)") = False*, *\**, *max_size: [IntegerLike](#drgn.IntegerLike "drgn.IntegerLike") = ...*) → [bytes](https://docs.python.org/3/library/stdtypes.html#bytes "(in Python v3.14)")

    >>> prog.read_c_string(0xffffffffbe012b40, max_size=4)
    b'swap'
    >>> prog.read_c_string(0xffffffffbe012b40, max_size=10)

Parameters:

Raises:  
- [**FaultError**](#drgn.FaultError "drgn.FaultError") – if an invalid address is accessed before finding a null terminator, or if the type of address (physical or virtual) is not supported by the program

- [**ValueError**](https://docs.python.org/3/library/exceptions.html#ValueError "(in Python v3.14)") – if *max_size* is negative

Register a callback for finding symbols in the program.

The callback should take four arguments: the program, a *name*, an *address*, and a boolean flag *one*. It should return a list of symbols or an empty list if no matches are found.

Set the program to a QEMU guest over the QEMU Machine Protocol (QMP).

This does not load any debugging symbols; see [`load_default_debug_info()`](#drgn.Program.load_default_debug_info "drgn.Program.load_default_debug_info").

Tip

Prefer using a Unix domain socket (e.g., run QEMU with `-qmp`` ``unix:/path/to/sock,server=on,wait=off`). When connected over a Unix domain socket, drgn can read memory much faster (as long as it has `PTRACE_MODE_ATTACH_REALCREDS` access to the QEMU process).

When connected over a Unix domain socket, drgn can also automatically identify Linux kernel guests, provided that you also:

1.  Use a Linux kernel version \>= 4.17 in the guest.

2.  Run QEMU with `-device`` ``vmcoreinfo`.

3.  Set `CONFIG_KEXEC=y` and `CONFIG_FW_CFG_SYSFS=y` in the guest kernel’s configuration. (Alternatively, you can use `CONFIG_FW_CFG_SYSFS=m` and ensure that the `qemu_fw_cfg` kernel module is loaded.)

Otherwise, you may need to pass *vmcoreinfo* explicitly to [`Program()`](#drgn.Program "drgn.Program").

Parameters:  
**address** –

QMP socket address or file descriptor. If the address is in the format `host:port`, where `host` is a hostname, IP address, or empty (for localhost) and `port` is a valid port number (decimal integer 1-65535), then it is interpreted as a TCP address. Otherwise, it is interpreted as a Unix domain socket path.

Note that hostnames may not begin with `/` or `.`, so a Unix domain socket path containing `:` may be prefixed with one of those to disambiguate it.

*class *drgn.KmodSearchMethod  
Bases: [`enum.Enum`](https://docs.python.org/3/library/enum.html#enum.Enum "(in Python v3.14)")

Methods of searching for loadable kernel module debugging information.

In addition to searching by build ID, there are currently two methods of searching for debugging information specific to loadable kernel modules:

1.  Using *[depmod(8)](http://man7.org/linux/man-pages/man8/depmod.8.html)* metadata. This looks for **depmod** metadata (specifically, `modules.dep.bin`) at the top level of each directory in [`DebugInfoOptions.kernel_directories`](#drgn.DebugInfoOptions.kernel_directories "drgn.DebugInfoOptions.kernel_directories") (an empty path means `/lib/modules/`*`release`*). The metadata is used to quickly find the path of each module, which is then checked relative to each directory specified by [`DebugInfoOptions.kernel_directories`](#drgn.DebugInfoOptions.kernel_directories "drgn.DebugInfoOptions.kernel_directories").

    This method is faster but typically only applicable to installed kernels.

2.  Walking kernel directories. This traverses each directory specified by [`DebugInfoOptions.kernel_directories`](#drgn.DebugInfoOptions.kernel_directories "drgn.DebugInfoOptions.kernel_directories") looking for `.ko` files. Module names are matched to filenames before the `.ko` extension and with dashes (`-`) replaced with underscores (`_`).

    This method is slower but not limited to installed kernels.

Debugging information searches can be configured to use one, both, or neither method.

NONE  
Don’t search using kernel module-specific methods.

DEPMOD  
Search using **depmod** metadata.

WALK  
Search by walking kernel directories.

DEPMOD_OR_WALK  
Search using **depmod** metadata, falling back to walking kernel directories only if no **depmod** metadata is found.

Since **depmod** metadata is expected to be reliable if present, this is the default.

DEPMOD_AND_WALK  
Search using **depmod** metadata and by walking kernel directories.

Unlike [`DEPMOD_OR_WALK`](#drgn.KmodSearchMethod.DEPMOD_OR_WALK "drgn.KmodSearchMethod.DEPMOD_OR_WALK"), if **depmod** metadata is found but doesn’t result in the desired debugging information, this will still walk kernel directories.

### Filenames

The [`Program.type()`](#drgn.Program.type "drgn.Program.type"), [`Program.object()`](#drgn.Program.object "drgn.Program.object"), [`Program.variable()`](#drgn.Program.variable "drgn.Program.variable"), [`Program.constant()`](#drgn.Program.constant "drgn.Program.constant"), and [`Program.function()`](#drgn.Program.function "drgn.Program.function") methods all take a *filename* parameter to distinguish between multiple definitions with the same name. The filename refers to the source code file that contains the definition. It is matched with [`filename_matches()`](#drgn.filename_matches "drgn.filename_matches"). If multiple definitions match, one is returned arbitrarily.

drgn.filename_matches(*haystack: [Optional](https://docs.python.org/3/library/typing.html#typing.Optional "(in Python v3.14)")\[[str](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)")\]*, *needle: [Optional](https://docs.python.org/3/library/typing.html#typing.Optional "(in Python v3.14)")\[[str](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)")\]*) → [bool](https://docs.python.org/3/library/functions.html#bool "(in Python v3.14)")  
Return whether a filename containing a definition (*haystack*) matches a filename being searched for (*needle*).

The filename is matched from right to left, so `'stdio.h'`, `'include/stdio.h'`, `'usr/include/stdio.h'`, and `'/usr/include/stdio.h'` would all match a definition in `/usr/include/stdio.h`. If *needle* is `None` or empty, it matches any definition. If *haystack* is `None` or empty, it only matches if *needle* is also `None` or empty.

Parameters:  
- **haystack** – Path of file containing definition.

- **needle** – Filename to match.

### Default Program

Most functions that take a [`Program`](#drgn.Program "drgn.Program") can be called without the *prog* argument. In that case, the *default program argument* is used, which is determined by the rules below.

Note

In the drgn CLI, you probably don’t need to care about these details. Simply omit *prog*:

    # Equivalent in the CLI.
    find_task(pid)
    find_task(prog, pid)
    find_task(prog["init_pid_ns"].address_of_(), pid)

1.  If *prog* is given explicitly, either as a positional or keyword argument, then it is used.

2.  Otherwise, if the first argument is an [`Object`](#drgn.Object "drgn.Object"), then [`Object.prog_`](#drgn.Object.prog_ "drgn.Object.prog_") is used.

3.  Otherwise, the *default program* is used.

The default program is set automatically in the CLI. Library users can get and set it manually. The default program is a per-thread setting. See [Thread Safety](#thread-safety).

### Platforms

*class *drgn.Platform  
A `Platform` represents the environment (i.e., architecture and ABI) that a program runs on.

Platform(*arch: [Architecture](#drgn.Architecture "drgn.Architecture")*, *flags: [Optional](https://docs.python.org/3/library/typing.html#typing.Optional "(in Python v3.14)")\[[PlatformFlags](#drgn.PlatformFlags "drgn.PlatformFlags")\] = None*)  
Create a `Platform`.

Parameters:  
- **arch** – [`Platform.arch`](#drgn.Platform.arch "drgn.Platform.arch")

- **flags** – [`Platform.flags`](#drgn.Platform.flags "drgn.Platform.flags"); if `None`, default flags for the architecture are used.

arch*: [Final](https://docs.python.org/3/library/typing.html#typing.Final "(in Python v3.14)")\[[Architecture](#drgn.Architecture "drgn.Architecture")\]*  
Instruction set architecture of this platform.

flags*: [Final](https://docs.python.org/3/library/typing.html#typing.Final "(in Python v3.14)")\[[PlatformFlags](#drgn.PlatformFlags "drgn.PlatformFlags")\]*  
Flags which apply to this platform.

registers*: [Final](https://docs.python.org/3/library/typing.html#typing.Final "(in Python v3.14)")\[[Sequence](https://docs.python.org/3/library/typing.html#typing.Sequence "(in Python v3.14)")\[[Register](#drgn.Register "drgn.Register")\]\]*  
Processor registers on this platform.

*class *drgn.Architecture  
Bases: [`enum.Enum`](https://docs.python.org/3/library/enum.html#enum.Enum "(in Python v3.14)")

An `Architecture` represents an instruction set architecture.

X86_64  
The x86-64 architecture, a.k.a. AMD64 or Intel 64.

I386  
The 32-bit x86 architecture, a.k.a. i386 or IA-32.

AARCH64  
The AArch64 architecture, a.k.a. ARM64.

ARM  
The 32-bit Arm architecture.

PPC64  
The 64-bit PowerPC architecture.

RISCV64  
The 64-bit RISC-V architecture.

RISCV32  
The 32-bit RISC-V architecture.

S390X  
The s390x architecture, a.k.a. IBM Z or z/Architecture.

S390  
The 32-bit s390 architecture, a.k.a. System/390.

LOONGARCH64  
The 64-bit LoongArch architecture.

UNKNOWN  
An architecture which is not known to drgn. Certain features are not available when the architecture is unknown, but most of drgn will still work.

### Languages
