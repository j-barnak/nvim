**NVM Express** (**NVMe**, **Non-Volatile Memory Express**) or **Non-Volatile Memory Host Controller Interface Specification** (**NVMHCIS**) is an [open](https://en.wikipedia.org/wiki/Open_standard "Open standard"), [logical-device](https://en.wikipedia.org/wiki/Logical_device "Logical device") [interface](https://en.wikipedia.org/wiki/Interface_(computing) "Interface (computing)") [specification](https://en.wikipedia.org/wiki/Functional_specification "Functional specification") for accessing a computer's [non-volatile storage](https://en.wikipedia.org/wiki/Non-volatile_storage "Non-volatile storage") media usually attached via the [PCI Express](https://en.wikipedia.org/wiki/PCI_Express "PCI Express") bus. The initial *NVM* stands for *[non-volatile memory](https://en.wikipedia.org/wiki/Non-volatile_memory "Non-volatile memory")*, which is often NAND [flash memory](https://en.wikipedia.org/wiki/Flash_memory "Flash memory") that comes in several physical form factors, including [solid-state drives](https://en.wikipedia.org/wiki/Solid-state_drive "Solid-state drive") (SSDs), PCIe add-in cards, and [M.2](https://en.wikipedia.org/wiki/M.2 "M.2") cards, the successor to [mSATA](https://en.wikipedia.org/wiki/MSATA "MSATA") cards. NVM Express, as a logical-device interface, has been designed to capitalize on the low [latency](https://en.wikipedia.org/wiki/Hard_disk_drive_performance_characteristics#Access_time "Hard disk drive performance characteristics") and internal parallelism of solid-state storage devices.^([\[1\]](#cite_note-1))

Architecturally, the logic for NVMe is physically stored within and executed by the NVMe controller chip that is physically co-located with the storage media, usually an SSD. Version changes for NVMe, e.g., 1.3 to 1.4, are incorporated within the storage media, and do not affect PCIe-compatible components such as motherboards and CPUs.^([\[2\]](#cite_note-2))

By its design, NVM Express allows host hardware and software to fully exploit the levels of [parallelism](https://en.wikipedia.org/wiki/Parallel_computing "Parallel computing") possible in modern SSDs. As a result, NVM Express reduces [I/O](https://en.wikipedia.org/wiki/Input/output "Input/output") overhead and brings various performance improvements relative to previous logical-device interfaces, including multiple long command queues, and reduced latency. The previous interface protocols like [AHCI](https://en.wikipedia.org/wiki/Advanced_Host_Controller_Interface "Advanced Host Controller Interface") were developed for use with far slower [hard disk drives](https://en.wikipedia.org/wiki/Hard_disk_drive "Hard disk drive") (HDD) where a very lengthy delay (relative to CPU operations) exists between a request and data transfer, where data speeds are much slower than RAM speeds, and where disk rotation and [seek time](https://en.wikipedia.org/wiki/Seek_time "Seek time") give rise to further optimization requirements.

NVM Express devices are chiefly available in the miniature [M.2](https://en.wikipedia.org/wiki/M.2 "M.2") form factor, while standard-sized PCI Express [expansion cards](https://en.wikipedia.org/wiki/Expansion_card "Expansion card")^([\[3\]](#cite_note-3)) and 2.5-inch form-factor devices that provide a four-lane PCI Express interface through the [U.2](https://en.wikipedia.org/wiki/U.2 "U.2") connector (formerly known as SFF-8639) are also available.^([\[4\]](#cite_note-4)[\[5\]](#cite_note-5))

## Specifications

\[[edit](https://en.wikipedia.org/w/index.php?title=NVM_Express&action=edit&section=1 "Edit section: Specifications")\]

Specifications for NVMe released to date include:^([\[6\]](#cite_note-6))

- 1.0e (January 2013)
- 1.1b (July 2014) that adds standardized *Command Sets* to achieve better compatibility across different NVMe devices, *Management Interface* that provides standardized tools for managing NVMe devices, simplifying administration and *Transport Specifications* that defines how NVMe commands are transported over various physical interfaces, enhancing interoperability.^([\[7\]](#cite_note-7))
- 1.2 (November 2014)
  - 1.2a (October 2015)
  - 1.2b (June 2016)
  - 1.2.1 (June 2016) that introduces the following new features over version 1.1b: *Multi-Queue* to supports multiple I/O queues, enhancing data throughput and performance, *Namespace Management* that allows for dynamic creation, deletion, and resizing of namespaces, providing greater flexibility, and *Endurance Management* to monitor and manage SSD wear levels, optimizing performance and extending drive life.^([\[8\]](#cite_note-8))
- 1.3 (May 2017)
  - 1.3a (October 2017)
  - 1.3b (May 2018)
  - 1.3c (May 2018)
  - 1.3d (March 2019) that since version 1.2.1 added *Namespace Sharing* to allow multiple hosts accessing a single namespace, facilitating shared storage environments, *Namespace Reservation* to provides mechanisms for hosts to reserve namespaces, preventing conflicts and ensuring data integrity, and *Namespace Priority* that sets priority levels for different namespaces, optimizing performance for critical workloads.^([\[9\]](#cite_note-9)[\[10\]](#cite_note-10))
- 1.4 (June 2019)
  - 1.4a (March 2020)
  - 1.4b (September 2020)
  - 1.4c (June 2021), that has the following new features compared to 1.3d: *IO Determinism* to ensure consistent latency and performance by isolating workloads, *Namespace Write Protect* for preventing data corruption or unauthorized modifications, *Persistent Event Log* that stores event logs in non-volatile memory, aiding in diagnostics and troubleshooting, and *Verify Command* that checks the integrity of data.^([\[11\]](#cite_note-11)[\[12\]](#cite_note-12))
- 2.0 (May 2021)^([\[13\]](#cite_note-13))
  - 2.0a (July 2021)
  - 2.0b (January 2022)
  - 2.0c (October 2022)
  - 2.0d (January 2024),^([\[14\]](#cite_note-v20d-14)) that, compared to 1.4c, introduces *Zoned Namespaces (ZNS)* to organize data into zones for efficient write operations, reducing write amplification and improving SSD longevity, *Key Value (KV)* for efficient storage and retrieval of key-value pairs directly on the NVMe device, bypassing traditional file systems, *Endurance Group Management* to manages groups of SSDs based on their endurance, optimizing usage and extending lifespan,^([\[15\]](#cite_note-15)[\[14\]](#cite_note-v20d-14)[\[16\]](#cite_note-16)) *Flexible Data Placement* makes software can marks hot data ranges and [cold data](https://en.wikipedia.org/wiki/Cold_data "Cold data") ranges.^([\[17\]](#cite_note-17))
  - 2.0e (July 2024)
- 2.1 (August 2024)^([\[18\]](#cite_note-v21-18)) that introduces *Live Migration* to maintaining service availability during migration, *Key Per I/O* for applying encryption keys at a per-operation level, *NVMe-MI High Availability Out of Band Management* for managing NVMe devices outside of regular data paths, and *NVMe Network Boot / UEFI* for booting NVMe devices over a network.^([\[19\]](#cite_note-19))
- 2.2 (March 2025)
- 2.3 (August 5, 2025)
- 2.4 (August 4, 2026). The August 2026 NVMe specification update added support for [post-quantum cryptography](https://en.wikipedia.org/wiki/Post-quantum_cryptography "Post-quantum cryptography") and PCIe Exported NVM Subsystem Migration, extending virtualization to locally attached PCIe SSDs. It also added controller-based rate limiting for bandwidth and [IOPS](https://en.wikipedia.org/wiki/IOPS "IOPS"), along with voltage monitoring.^([\[20\]](#cite_note-20))

## Background

\[[edit](https://en.wikipedia.org/w/index.php?title=NVM_Express&action=edit&section=2 "Edit section: Background")\]

[![](https://thumb.wikimedia.org/wikipedia/commons/thumb/e/e3/Intel_SSD_750_series%2C_400_GB_add-in_card_model%2C_top_view.jpg/330px-Intel_SSD_750_series%2C_400_GB_add-in_card_model%2C_top_view.jpg?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](https://en.wikipedia.org/wiki/File:Intel_SSD_750_series,_400_GB_add-in_card_model,_top_view.jpg)

[![](https://thumb.wikimedia.org/wikipedia/commons/thumb/8/81/Intel_SSD_750_series%2C_400_GB_add-in_card_model%2C_bottom_view.jpg/330px-Intel_SSD_750_series%2C_400_GB_add-in_card_model%2C_bottom_view.jpg?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](https://en.wikipedia.org/wiki/File:Intel_SSD_750_series,_400_GB_add-in_card_model,_bottom_view.jpg)

Intel SSD 750 series, an SSD that uses NVM Express, in form of a [PCI Express 3.0](https://en.wikipedia.org/wiki/PCI_Express_3.0 "PCI Express 3.0") ×4 [expansion card](https://en.wikipedia.org/wiki/Expansion_card "Expansion card") (front and rear views)

Historically, most SSDs used [buses](https://en.wikipedia.org/wiki/Bus_(computing) "Bus (computing)") such as [SATA](https://en.wikipedia.org/wiki/SATA "SATA"),^([\[21\]](#cite_note-21)) [SAS](https://en.wikipedia.org/wiki/Serial_Attached_SCSI "Serial Attached SCSI"),^([\[22\]](#cite_note-22)[\[23\]](#cite_note-23)) or [Fibre Channel](https://en.wikipedia.org/wiki/Fibre_Channel "Fibre Channel") for interfacing with the rest of a computer system. Since SSDs became available in mass markets, SATA has become the most typical way for connecting SSDs in [personal computers](https://en.wikipedia.org/wiki/Personal_computer "Personal computer"); however, SATA was designed primarily for interfacing with mechanical [hard disk drives](https://en.wikipedia.org/wiki/Hard_disk_drive "Hard disk drive") (HDDs), and it became increasingly inadequate for SSDs, which improved in speed over time.^([\[24\]](#cite_note-24)) For example, within about five years of mass market mainstream adoption (2005–2010) many SSDs were already held back by the comparatively slow data rates available for hard drives—unlike hard disk drives, some SSDs are limited by the maximum [throughput](https://en.wikipedia.org/wiki/Throughput "Throughput") of SATA.

High-end SSDs had been made using the [PCI Express](https://en.wikipedia.org/wiki/PCI_Express "PCI Express") bus before NVMe, but using non-standard specification interfaces, using a SAS to PCIe bridge^([\[25\]](#cite_note-25)) or by emulating a hardware RAID controller.^([\[26\]](#cite_note-26)) By standardizing the interface of SSDs, [operating systems](https://en.wikipedia.org/wiki/Operating_system "Operating system") only need one common [device driver](https://en.wikipedia.org/wiki/Device_driver "Device driver") to work with all SSDs adhering to the specification. It also means that each SSD manufacturer does not have to design specific interface drivers. This is similar to how [USB mass storage](https://en.wikipedia.org/wiki/USB_mass_storage "USB mass storage") devices are built to follow the [USB](https://en.wikipedia.org/wiki/USB "USB") mass-storage device class specification and work with all computers, with no per-device drivers needed.^([\[27\]](#cite_note-whitepaper-27))

NVM Express devices are also used as the building block of the [burst buffer](https://en.wikipedia.org/wiki/Burst_buffer "Burst buffer") storage in many leading supercomputers, such as [Fugaku Supercomputer](https://en.wikipedia.org/wiki/Fugaku_(supercomputer) "Fugaku (supercomputer)"), [Summit Supercomputer](https://en.wikipedia.org/wiki/Summit_(supercomputer) "Summit (supercomputer)") and [Sierra Supercomputer](https://en.wikipedia.org/wiki/Sierra_(supercomputer) "Sierra (supercomputer)"), etc.^([\[28\]](#cite_note-28)[\[29\]](#cite_note-29))

## History

\[[edit](https://en.wikipedia.org/w/index.php?title=NVM_Express&action=edit&section=3 "Edit section: History")\]

The first details of a new standard for accessing non-volatile memory emerged at the [Intel Developer Forum](https://en.wikipedia.org/wiki/Intel_Developer_Forum "Intel Developer Forum") 2007, when NVMHCI was shown as the host-side protocol of a proposed architectural design that had [Open NAND Flash Interface Working Group](https://en.wikipedia.org/wiki/Open_NAND_Flash_Interface_Working_Group "Open NAND Flash Interface Working Group") (ONFI) on the memory (flash) chips side.^([\[30\]](#cite_note-30)) A NVMHCI working group led by Intel was formed that year. The NVMHCI 1.0 specification was completed in April 2008 and released on Intel's web site.^([\[31\]](#cite_note-31)[\[32\]](#cite_note-32)[\[33\]](#cite_note-33))

Technical work on NVMe began in the second half of 2009.^([\[34\]](#cite_note-Onufryk-34)) The NVMe specifications were developed by the NVM Express Workgroup, which consists of more than 90 companies; Amber Huffman of [Intel](https://en.wikipedia.org/wiki/Intel_Corporation "Intel Corporation") was the working group's chair. Version 1.0 of the specification was released on 1 March 2011,^([\[35\]](#cite_note-35)) while version 1.1 of the specification was released on 11 October 2012.^([\[36\]](#cite_note-36)) Major features added in version 1.1 are multi-path I/O (with namespace sharing) and arbitrary-length [scatter-gather](https://en.wikipedia.org/wiki/Scatter-gather "Scatter-gather") I/O. It is expected that future revisions will significantly enhance namespace management.^([\[34\]](#cite_note-Onufryk-34)) Because of its feature focus, NVMe 1.1 was initially called "Enterprise NVMHCI".^([\[37\]](#cite_note-37)) An update for the base NVMe specification, called version 1.0e, was released in January 2013.^([\[38\]](#cite_note-38)) In June 2011, a Promoter Group led by seven companies was formed.

The first commercially available NVMe chipsets were released by [Integrated Device Technology](https://en.wikipedia.org/wiki/Integrated_Device_Technology "Integrated Device Technology") (89HF16P04AG3 and 89HF32P08AG3) in August 2012.^([\[39\]](#cite_note-39)[\[40\]](#cite_note-40)) The first NVMe drive, [Samsung](https://en.wikipedia.org/wiki/Samsung "Samsung")'s XS1715 [enterprise drive](https://en.wikipedia.org/wiki/Enterprise_storage "Enterprise storage"), was announced in July 2013; according to Samsung, this drive supported 3 GB/s read speeds, six times faster than their previous enterprise offerings.^([\[41\]](#cite_note-41)) The LSI [SandForce](https://en.wikipedia.org/wiki/SandForce "SandForce") SF3700 controller family, released in November 2013, also supports NVMe.^([\[42\]](#cite_note-42)[\[43\]](#cite_note-43)) A Kingston [HyperX](https://en.wikipedia.org/wiki/HyperX "HyperX") "[prosumer](https://en.wiktionary.org/wiki/prosumer#Etymology_2 "wikt:prosumer")" product using this controller was showcased at the [Consumer Electronics Show](https://en.wikipedia.org/wiki/Consumer_Electronics_Show "Consumer Electronics Show") 2014 and promised similar performance.^([\[44\]](#cite_note-44)[\[45\]](#cite_note-45)) In June 2014, Intel announced their first NVM Express products, the Intel SSD data center family that interfaces with the host through PCI Express bus, which includes the DC P3700 series, the DC P3600 series, and the DC P3500 series.^([\[46\]](#cite_note-46)) As of November 2014^([\[update\]](https://en.wikipedia.org/w/index.php?title=NVM_Express&action=edit)), NVMe drives are commercially available.

In March 2014, the group incorporated to become NVM Express, Inc., which as of November 2014^([\[update\]](https://en.wikipedia.org/w/index.php?title=NVM_Express&action=edit)) consists of more than 65 companies from across the industry. NVM Express specifications are owned and maintained by NVM Express, Inc., which also promotes industry awareness of NVM Express as an industry-wide standard. NVM Express, Inc. is directed by a thirteen-member board of directors selected from the Promoter Group, which includes Cisco, Dell, EMC, HGST, Intel, Micron, Microsoft, NetApp, Oracle, PMC, Samsung, SanDisk and Seagate.^([\[47\]](#cite_note-47))

In September 2016, the CompactFlash Association announced that it would be releasing a new memory card specification, [CFexpress](https://en.wikipedia.org/wiki/CFexpress "CFexpress"), which uses NVMe.^(\[*[citation needed](https://en.wikipedia.org/wiki/Wikipedia:Citation_needed "Wikipedia:Citation needed")*\])

NVMe **Host Memory Buffer** (HMB) feature added in version 1.2 of the NVMe specification.^([\[48\]](#cite_note-anandtech.com-48)) HMB allows SSDs to use the host's [DRAM](https://en.wikipedia.org/wiki/Dynamic_random-access_memory "Dynamic random-access memory"), which can improve the I/O performance for DRAM-less SSDs.^([\[49\]](#cite_note-49)) For example, HMB can cache the [FTL](https://en.wikipedia.org/wiki/Flash_Translation_Layer "Flash Translation Layer") table by the SSD controller, and HMB can temporarily hold data while it is being written to the flash memory.^([\[50\]](#cite_note-50)) NVMe 2.0 added optional **Zoned Namespaces** (ZNS) feature and **Key-Value** (KV) feature, and support for rotating media such as [hard disk drives](https://en.wikipedia.org/wiki/Hard_disk_drive "Hard disk drive"). ZNS and KV allows data to be mapped directly to its physical location in flash memory to directly access data on an SSD.^([\[51\]](#cite_note-51)) ZNS and KV can also decrease [write amplification](https://en.wikipedia.org/wiki/Write_amplification "Write amplification") of flash media.

## Form factors

\[[edit](https://en.wikipedia.org/w/index.php?title=NVM_Express&action=edit&section=4 "Edit section: Form factors")\]

There are many form factors of NVMe solid-state drive, such as AIC, U.2, U.3, M.2 etc.

### AIC (Add-in Card)

\[[edit](https://en.wikipedia.org/w/index.php?title=NVM_Express&action=edit&section=5 "Edit section: AIC (Add-in Card)")\]

Almost all early NVMe solid-state drives are HHHL (half height, half length) or FHHL (full height, half length) [PCI Express](https://en.wikipedia.org/wiki/PCI_Express "PCI Express") cards, with a PCIe 2.0 or 3.0 interface. A HHHL NVMe solid-state drive card is easy to insert into a PCIe slot of a server.

### SATA Express, U.2 and U.3 (SFF-8639)

\[[edit](https://en.wikipedia.org/w/index.php?title=NVM_Express&action=edit&section=6 "Edit section: SATA Express, U.2 and U.3 (SFF-8639)")\]

Main articles: [SATA Express](https://en.wikipedia.org/wiki/SATA_Express "SATA Express") and [U.2](https://en.wikipedia.org/wiki/U.2 "U.2")

[SATA Express](https://en.wikipedia.org/wiki/SATA_Express "SATA Express") allows the use of two PCI Express 2.0 or 3.0 lanes and two SATA 3.0 (6 Gbit/s) ports through the same host-side SATA Express connector (but not both at the same time). SATA Express supports NVMe as the logical device interface for attached PCI Express storage devices. It is electrically compatible with [MultiLink SAS](https://en.wikipedia.org/wiki/MultiLink_SAS "MultiLink SAS"), so a backplane can support both at the same time.

U.2, formerly known as **SFF-8639**, uses the same physical port as SATA Express but allows up to four PCI Express lanes. Available servers can combine up to 48 U.2 NVMe solid-state drives.^([\[52\]](#cite_note-52))

U.3 (SFF-TA-1001) is built on the U.2 spec and uses the same SFF-8639 connector. Unlike in U.2, a single "tri-mode" (PCIe/SATA/SAS) backplane receptacle can handle all three types of connections; the controller automatically detects the type of connection used. This is unlike U.2, where users need to use separate controllers for SATA/SAS and NVMe. U.3 devices are required to be backwards-compatible with U.2 hosts, but U.2 drives are not compatible with U.3 hosts.^([\[53\]](#cite_note-53)[\[54\]](#cite_note-54))

### M.2

\[[edit](https://en.wikipedia.org/w/index.php?title=NVM_Express&action=edit&section=7 "Edit section: M.2")\]

Main article: [M.2](https://en.wikipedia.org/wiki/M.2 "M.2")

M.2, formerly known as the **Next Generation Form Factor** (**NGFF**), uses a M.2 NVMe solid-state drive [computer bus](https://en.wikipedia.org/wiki/Computer_bus "Computer bus"). Interfaces provided through the M.2 connector are [PCI Express 3.0](https://en.wikipedia.org/wiki/PCI_Express_3.0 "PCI Express 3.0") or higher (up to four [lanes](https://en.wikipedia.org/wiki/PCI_Express_lane "PCI Express lane")). The connector is small compared to typical AICs. Most SSDs are 22 mm wide and can range from 30, 42, 60, 80 and 110 mm. However, the M.2 standard allows for widths of 12 16, 22 and 30 mm and lengths of 16, 26, 30, 38, 42, 60, 80 and 110 mm.^([\[55\]](#cite_note-55))

## NVMe-oF

\[[edit](https://en.wikipedia.org/w/index.php?title=NVM_Express&action=edit&section=12 "Edit section: NVMe-oF")\]

**NVM Express over Fabrics** (**NVMe-oF**) is the concept of using a [transport protocol](https://en.wikipedia.org/wiki/Transport_layer "Transport layer") over a network to connect remote NVMe devices, contrary to regular NVMe where physical NVMe devices are connected to a [PCIe bus](https://en.wikipedia.org/wiki/PCI_Express#Serial_bus "PCI Express") either directly or over a [PCIe switch](https://en.wikipedia.org/wiki/PCI_Express#SWITCH "PCI Express") to a PCIe bus. In August 2017, a standard for using NVMe over [Fibre Channel](https://en.wikipedia.org/wiki/Fibre_Channel "Fibre Channel") (FC) was submitted by the standards organization [International Committee for Information Technology Standards](https://en.wikipedia.org/wiki/International_Committee_for_Information_Technology_Standards "International Committee for Information Technology Standards") (ICITS), and this combination is often referred to as FC-NVMe or sometimes NVMe/FC.^([\[56\]](#cite_note-tech1-56))

As of May 2021, supported NVMe transport protocols are:

- [FC](https://en.wikipedia.org/wiki/Fibre_Channel "Fibre Channel"), FC-NVMe^([\[56\]](#cite_note-tech1-56)[\[57\]](#cite_note-57))
- [TCP](https://en.wikipedia.org/wiki/Transmission_Control_Protocol "Transmission Control Protocol"), [NVMe/TCP](https://en.wikipedia.org/wiki/NVMe_over_TCP "NVMe over TCP")^([\[58\]](#cite_note-58))
- [Ethernet](https://en.wikipedia.org/wiki/Ethernet "Ethernet"), [RoCE](https://en.wikipedia.org/wiki/RDMA_over_Converged_Ethernet "RDMA over Converged Ethernet") v1/v2 ([RDMA](https://en.wikipedia.org/wiki/Remote_direct_memory_access "Remote direct memory access") over [converged Ethernet](https://en.wikipedia.org/wiki/Data_center_bridging "Data center bridging"))^([\[59\]](#cite_note-59))
- [InfiniBand](https://en.wikipedia.org/wiki/InfiniBand "InfiniBand"), NVMe over InfiniBand or NVMe/IB^([\[60\]](#cite_note-60))

The standard for NVMe over Fabrics was published by NVM Express, Inc. in 2016.^([\[61\]](#cite_note-61)[\[62\]](#cite_note-62))

The following software implements the NVMe-oF protocol:

- Linux NVMe-oF [initiator and target](https://en.wikipedia.org/wiki/SCSI_initiator_and_target "SCSI initiator and target").^([\[63\]](#cite_note-63)) RoCE transport was supported initially, and with [Linux kernel](https://en.wikipedia.org/wiki/Linux_kernel "Linux kernel") 5.x, native support for TCP was added.^([\[64\]](#cite_note-64))
- Storage Performance Development Kit (SPDK) NVMe-oF initiator and target drivers.^([\[65\]](#cite_note-65)) Both RoCE and TCP transports are supported.^([\[66\]](#cite_note-66)[\[67\]](#cite_note-67))
- [StarWind](https://en.wikipedia.org/wiki/StarWind_Software "StarWind Software") NVMe-oF initiator^([\[68\]](#cite_note-sw_initiator-68)) and target for [Linux](https://en.wikipedia.org/wiki/Linux "Linux") and [Microsoft Windows](https://en.wikipedia.org/wiki/Microsoft_Windows "Microsoft Windows"), supporting both [RoCE](https://en.wikipedia.org/wiki/RDMA_over_Converged_Ethernet "RDMA over Converged Ethernet") & [TCP](https://en.wikipedia.org/wiki/Transmission_Control_Protocol "Transmission Control Protocol"), and [Fibre Channel](https://en.wikipedia.org/wiki/Fibre_Channel "Fibre Channel") transports.^([\[69\]](#cite_note-sw_target-69))
- [Lightbits Labs](https://www.lightbitslabs.com/nvme-over-tcp/) [NVMe over TCP](https://en.wikipedia.org/wiki/NVMe_over_TCP "NVMe over TCP") target^([\[70\]](#cite_note-lbl_target-70)) for various [Linux](https://en.wikipedia.org/wiki/Linux "Linux") distributions^([\[71\]](#cite_note-lbl_target2-71)) & public clouds.
- [Bloombase](https://www.bloombase.com) StoreSafe Intelligent Storage Firewall supports NVMe over [RoCE](https://en.wikipedia.org/wiki/RDMA_over_Converged_Ethernet "RDMA over Converged Ethernet"), [TCP](https://en.wikipedia.org/wiki/Transmission_Control_Protocol "Transmission Control Protocol"), [Fibre Channel](https://en.wikipedia.org/wiki/Fibre_Channel "Fibre Channel") and [InfiniBand](https://en.wikipedia.org/wiki/InfiniBand "InfiniBand") for transparent storage security protection.
- [NetApp ONTAP](https://www.netapp.com/data-management/ontap-data-management-software/) supports iSCSI and [NVMe over TCP](https://en.wikipedia.org/wiki/NVMe_over_TCP "NVMe over TCP")^([\[72\]](#cite_note-72)) targets.
- [Simplyblock](https://www.simplyblock.io/our-technology/) storage platform with NVMe over Fabrics support.^([\[73\]](#cite_note-73))

## Comparison with AHCI

\[[edit](https://en.wikipedia.org/w/index.php?title=NVM_Express&action=edit&section=13 "Edit section: Comparison with AHCI")\]

[![](https://thumb.wikimedia.org/wikipedia/commons/thumb/b/ba/A-MSATA_M-MKNSSDAT240GB_S-MKN1308A0000169997.jpg/250px-A-MSATA_M-MKNSSDAT240GB_S-MKN1308A0000169997.jpg?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](https://en.wikipedia.org/wiki/File:A-MSATA_M-MKNSSDAT240GB_S-MKN1308A0000169997.jpg)

A [Mushkin](https://en.wikipedia.org/wiki/Mushkin "Mushkin") Atlas 240GB [mSATA](https://en.wikipedia.org/wiki/MSATA "MSATA") Solid-state drive

The [Advanced Host Controller Interface](https://en.wikipedia.org/wiki/Advanced_Host_Controller_Interface "Advanced Host Controller Interface") (AHCI) has the benefit of wide software compatibility, but has the downside of not delivering optimal performance when used with [SSDs](https://en.wikipedia.org/wiki/Solid-state_drive "Solid-state drive") connected via the [PCI Express](https://en.wikipedia.org/wiki/PCI_Express "PCI Express") bus. As a logical-device interface, AHCI was developed when the purpose of a [host bus adapter](https://en.wikipedia.org/wiki/Host_bus_adapter "Host bus adapter") (HBA) in a system was to connect the CPU/memory subsystem with a much slower storage subsystem based on rotating [magnetic media](https://en.wikipedia.org/wiki/Magnetic_storage "Magnetic storage"). As a result, AHCI introduces certain inefficiencies when used with SSD devices, which behave much more like [RAM](https://en.wikipedia.org/wiki/Random-access_memory "Random-access memory") than like spinning media.^([\[74\]](#cite_note-ahci-nvme-74))

The NVMe device interface has been designed from the ground up, capitalizing on the lower latency and [parallelism](https://en.wikipedia.org/wiki/Parallel_computing "Parallel computing") of PCI Express SSDs, and complementing the parallelism of contemporary CPUs, platforms and applications. At a high level, the basic advantages of NVMe over AHCI relate to its ability to exploit parallelism in host hardware and software, manifested by the differences in [command queue](https://en.wikipedia.org/wiki/Command_queue "Command queue") depths, efficiency of [interrupt](https://en.wikipedia.org/wiki/Interrupt "Interrupt") processing, the number of uncacheable [register](https://en.wikipedia.org/wiki/Processor_register "Processor register") accesses, etc., resulting in various performance improvements.^([\[74\]](#cite_note-ahci-nvme-74)[\[75\]](#cite_note-snia-windows-75): 17–18 )

NVMe uses Autonomous Power State Transition (APST) power management mechanism, which allows multiple PSx states; PS0 state and PS1 state are mandatory.^([\[76\]](#cite_note-76)) AHCI uses [Aggressive Link Power Management](https://en.wikipedia.org/wiki/Aggressive_Link_Power_Management "Aggressive Link Power Management") (ALPM) mechanism.

The table below summarizes high-level differences between the NVMe and AHCI logical-device interfaces.

**High-level comparison of AHCI and NVMe \[ 74 \]**

|                                                  | [AHCI](https://en.wikipedia.org/wiki/Advanced_Host_Controller_Interface) | NVMe                                                                             |
|--------------------------------------------------|--------------------------------------------------------------------------|----------------------------------------------------------------------------------|
| Queue depth                                      | One command queue; Maximum 32 commands per queue                         | Maximum 65535 queues; [\[ 77 \]](#cite_note-77) Maximum 65536 commands per queue |
| Uncacheable register accesses (2000 cycles each) | Maximum six per non-queued command; Maximum nine per queued command      | Maximum two per command                                                          |
| Interrupt                                        | A single interrupt                                                       | Maximum 2048 [MSI-X](https://en.wikipedia.org/wiki/MSI-X) interrupts             |
| Parallelism and multiple threads                 | Requires synchronization lock to issue a command                         | No locking                                                                       |
| Efficiency for 4 KB commands                     | Command parameters require two serialized host DRAM fetches              | Gets command parameters in one 64-byte fetch                                     |
| Data transmission                                | Usually half-duplex                                                      | Full-duplex                                                                      |
| Host Memory Buffer (HMB)                         | No                                                                       | Yes                                                                              |

## Operating system support

\[[edit](https://en.wikipedia.org/w/index.php?title=NVM_Express&action=edit&section=14 "Edit section: Operating system support")\]

[![](https://thumb.wikimedia.org/wikipedia/commons/thumb/f/fb/The_Linux_Storage_Stack_Diagram.svg/500px-The_Linux_Storage_Stack_Diagram.svg.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](https://en.wikipedia.org/wiki/File:The_Linux_Storage_Stack_Diagram.svg)

The position of NVMe data paths and multiple internal queues within various layers of the [Linux kernel](https://en.wikipedia.org/wiki/Linux_kernel "Linux kernel")'s storage stack^([\[78\]](#cite_note-78))

[ChromeOS](https://en.wikipedia.org/wiki/ChromeOS "ChromeOS")  
On February 24, 2015, support for booting from NVM Express devices was added to [ChromeOS](https://en.wikipedia.org/wiki/ChromeOS "ChromeOS").^([\[79\]](#cite_note-79)[\[80\]](#cite_note-80))

&nbsp;

[DragonFly BSD](https://en.wikipedia.org/wiki/DragonFly_BSD "DragonFly BSD")  
The first release of [DragonFly BSD](https://en.wikipedia.org/wiki/DragonFly_BSD "DragonFly BSD") with NVMe support is version 4.6.^([\[81\]](#cite_note-81))

&nbsp;

[FreeBSD](https://en.wikipedia.org/wiki/FreeBSD "FreeBSD")  
Intel sponsored a NVM Express driver for [FreeBSD](https://en.wikipedia.org/wiki/FreeBSD "FreeBSD")'s head and stable/9 branches.^([\[82\]](#cite_note-82)[\[83\]](#cite_note-83)) The nvd(4) and nvme(4) drivers are included in the GENERIC kernel configuration by default since FreeBSD version 10.2 in 2015.^([\[84\]](#cite_note-84))

&nbsp;

[Genode](https://en.wikipedia.org/wiki/Genode "Genode")  
Support for consumer-grade NVMe was added to the Genode framework as part of the 18.05^([\[85\]](#cite_note-85)) release.

&nbsp;

[Haiku](https://en.wikipedia.org/wiki/Haiku_(operating_system) "Haiku (operating system)")  
[Haiku](https://en.wikipedia.org/wiki/Haiku_(operating_system) "Haiku (operating system)") gained support for NVMe on April 18, 2019.^([\[86\]](#cite_note-86)[\[87\]](#cite_note-87))

&nbsp;

[illumos](https://en.wikipedia.org/wiki/Illumos "Illumos")  
[illumos](https://en.wikipedia.org/wiki/Illumos "Illumos") received support for NVMe on October 15, 2014.^([\[88\]](#cite_note-88))

&nbsp;

[iOS](https://en.wikipedia.org/wiki/IOS "IOS")  
With the release of the [iPhone 6S](https://en.wikipedia.org/wiki/IPhone_6S "IPhone 6S") and [6S Plus](https://en.wikipedia.org/wiki/IPhone_6S_Plus "IPhone 6S Plus"), [Apple](https://en.wikipedia.org/wiki/Apple_Inc. "Apple Inc.") introduced the first mobile deployment of NVMe over [PCIe](https://en.wikipedia.org/wiki/PCI_Express "PCI Express") in smartphones.^([\[89\]](#cite_note-89)) Apple followed these releases with the release of the first-generation [iPad Pro](https://en.wikipedia.org/wiki/IPad_Pro "IPad Pro") and [first-generation iPhone SE](https://en.wikipedia.org/wiki/IPhone_SE_(1st_generation) "IPhone SE (1st generation)") that also use NVMe over PCIe.^([\[90\]](#cite_note-90))

&nbsp;

[Linux](https://en.wikipedia.org/wiki/Linux "Linux")  
Intel published an NVM Express driver for [Linux](https://en.wikipedia.org/wiki/Linux "Linux") on 3 March 2011,^([\[91\]](#cite_note-91)[\[92\]](#cite_note-92)[\[93\]](#cite_note-93)) which was merged into the [Linux kernel](https://en.wikipedia.org/wiki/Linux_kernel "Linux kernel") mainline on 18 January 2012 and released as part of version 3.3 of the Linux kernel on 19 March 2012.^([\[94\]](#cite_note-94)) Linux kernel supports NVMe Host Memory Buffer^([\[95\]](#cite_note-95)) from version 4.13.1^([\[96\]](#cite_note-96)) with default maximum size 128 MB.^([\[97\]](#cite_note-97)) Linux kernel supports NVMe Zoned Namespaces start from version 5.9.

&nbsp;

[macOS](https://en.wikipedia.org/wiki/MacOS "MacOS")  
Apple introduced software support for NVM Express in [Yosemite](https://en.wikipedia.org/wiki/OS_X_Yosemite "OS X Yosemite") 10.10.3. The NVMe hardware interface was introduced in the 2016 [MacBook](https://en.wikipedia.org/wiki/MacBook "MacBook") and [MacBook Pro](https://en.wikipedia.org/wiki/MacBook_Pro "MacBook Pro").^([\[98\]](#cite_note-98))

&nbsp;

[NetBSD](https://en.wikipedia.org/wiki/NetBSD "NetBSD")  
[NetBSD](https://en.wikipedia.org/wiki/NetBSD "NetBSD") added support for NVMe in NetBSD 8.0.^([\[99\]](#cite_note-99)) The implementation is derived from OpenBSD 6.0.

&nbsp;

[OpenBSD](https://en.wikipedia.org/wiki/OpenBSD "OpenBSD")  
Development work required to support NVMe in [OpenBSD](https://en.wikipedia.org/wiki/OpenBSD "OpenBSD") has been started in April 2014 by a senior developer formerly responsible for [USB 2.0](https://en.wikipedia.org/wiki/USB_2.0 "USB 2.0") and [AHCI](https://en.wikipedia.org/wiki/Advanced_Host_Controller_Interface "Advanced Host Controller Interface") support.^([\[100\]](#cite_note-100)) Support for NVMe has been enabled in the OpenBSD 6.0 release.^([\[101\]](#cite_note-101))

&nbsp;

[OS/2](https://en.wikipedia.org/wiki/OS/2 "OS/2")  
Arca Noae provides an NVMe driver for [ArcaOS](https://en.wikipedia.org/wiki/ArcaOS "ArcaOS"), as of April, 2021. The driver requires advanced interrupts as provided by the ACPI PSD running in advanced interrupt mode (mode 2), thus requiring the SMP kernel, as well.^([\[102\]](#cite_note-102))

&nbsp;

[Solaris](https://en.wikipedia.org/wiki/Solaris_(operating_system) "Solaris (operating system)")  
Solaris received support for NVMe in Oracle Solaris 11.2.^([\[103\]](#cite_note-103))

&nbsp;

[VMware](https://en.wikipedia.org/wiki/VMware "VMware")  
Intel has provided an NVMe driver for [VMware](https://en.wikipedia.org/wiki/VMware "VMware"),^([\[104\]](#cite_note-104)) which is included in [vSphere](https://en.wikipedia.org/wiki/VMware_vSphere "VMware vSphere") 6.0 and later builds, supporting various NVMe devices.^([\[105\]](#cite_note-105)) As of vSphere 6 update 1, VMware's VSAN software-defined storage subsystem also supports NVMe devices.^([\[106\]](#cite_note-106))

&nbsp;

[Windows](https://en.wikipedia.org/wiki/Windows "Windows")  
Microsoft added built-in support for NVMe to [Windows 8.1](https://en.wikipedia.org/wiki/Windows_8.1 "Windows 8.1") and [Windows Server 2012 R2](https://en.wikipedia.org/wiki/Windows_Server_2012_R2 "Windows Server 2012 R2"),^([\[75\]](#cite_note-snia-windows-75)[\[107\]](#cite_note-107)) but it is implemented via a NVMe-to-SCSI translation layer.^([\[108\]](#cite_note-108)) NVMe drivers for [Windows 7](https://en.wikipedia.org/wiki/Windows_7 "Windows 7") and [Windows Server 2008 R2](https://en.wikipedia.org/wiki/Windows_Server_2008_R2 "Windows Server 2008 R2") have been added in updates.^([\[109\]](#cite_note-109)) Many vendors have released their own Windows drivers for their devices as well. There are also manually customized installer files available to install a specific vendor's driver to any NVMe card, such as using a Samsung NVMe driver with a non-Samsung NVMe device, which may be needed for additional features, performance, and stability.^([\[110\]](#cite_note-win-raid.com-110))

Support for NVMe HMB was added in Windows 10 Anniversary Update (Version 1607) in 2016.^([\[48\]](#cite_note-anandtech.com-48)) In Microsoft Windows from [Windows 10 1607](https://en.wikipedia.org/wiki/Windows_10_1607 "Windows 10 1607") to [Windows 11 23H2](https://en.wikipedia.org/wiki/Windows_11_23H2 "Windows 11 23H2"), the maximum HMB size is 64 MB. [Windows 11 24H2](https://en.wikipedia.org/wiki/Windows_11_24H2 "Windows 11 24H2") updates the maximum HMB size to 1/64 of system RAM.^([\[111\]](#cite_note-111))

Support for NVMe ZNS and KV was added in [Windows 10 version 21H2](https://en.wikipedia.org/wiki/Windows_10_version_21H2 "Windows 10 version 21H2") and [Windows 11](https://en.wikipedia.org/wiki/Windows_11 "Windows 11") in 2021.^([\[112\]](#cite_note-112)) The [OpenFabrics Alliance](https://en.wikipedia.org/wiki/OpenFabrics_Alliance "OpenFabrics Alliance") maintains an open-source NVMe Windows Driver for Windows 7/8/8.1 and Windows Server 2008R2/2012/2012R2, developed from the baseline code submitted by several promoter companies in the NVMe workgroup, specifically IDT, Intel, and LSI.^([\[113\]](#cite_note-113)) The current release is 1.5 from December 2016.^([\[114\]](#cite_note-114)) The built-in Windows NVMe driver in Windows 8.1, Windows 10 and Windows Server releases before 2025 relies on the old SCSI-based storage stack, which does not provide any [hardware acceleration](https://en.wikipedia.org/wiki/Hardware_acceleration "Hardware acceleration"), requiring vendor-specific drivers.^([\[115\]](#cite_note-115)) Native NVMe support for [Windows Server 2025](https://en.wikipedia.org/wiki/Windows_Server_2025 "Windows Server 2025") was added in 15 December 2025, however it needs to be enabled through a hidden [registry](https://en.wikipedia.org/wiki/Windows_Registry "Windows Registry") setting.^([\[116\]](#cite_note-116)) It's still unofficially available on consumer Windows editions.^([\[117\]](#cite_note-117))

Unofficial drivers exist for old Windows NT^([\[118\]](#cite_note-118)) and Windows 9x.^([\[119\]](#cite_note-119))
