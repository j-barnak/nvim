Fault vs Error
• Fault: The underlying cause of an error, (stuck-at bit or
high-energy particle strike.)
• Error: Incorrect portion of state resulting from a fault
• Error-causing Faults:
• Stuck-at-0 fault in register-dependence CAM
• Particle strike on DRAM capacitor

• Non-error-causing Faults:
• Transient error in branch predictor table
• Permanent error in redundant (spare) DRAM array

What to do about it?
• Do Nothing:
• Eventual slowdown: Phone/PC slow down rapidly, then stop
• Silent data corruption: Corrupt bank transaction, etc…

• Detect the fault:
• Signal an error, stop running the program, replace hardware
(or re-fetch data…)
• Faster the better -> less corrupted data

• Predict the fault:
• Signal a predicted error, stop running, replace hardware
• Hopefully no corrupted data

• Correct the fault:
• Keep using the hardware without glitches
• Need a low-overhead solution

Error Correction: Hamming Codes
• Idea: Balance overhead with detection/recovery
• Key: Need several check-bits + overlapping
• Codeword: D data bits + C check bits

• Hamming Code
• Hamming distance: H(A,B) = # of 1’s in A^B (# of bits that differ)
• codewords A,B H(A,B) ≥ 
• No combination of –1 transforms one codeword into another
• For simple parity:  = 2 (two transforms to confuse codewords)
• Guarantees:
• Errors of  bits (or fewer) can be detected if  =  + 1
• Errors of  bits or fewer can be corrected if  = 2 + 1
• Errors of  bits can be detected and errors of  bits can be
corrected if  =  +  + 1 (where  >= )

14

Algorithm to generate Hamming Code
• Principle 1: any given bit should be included in a unique set of
parity bits!
• Principle 2: arrange parity bits so that they are self describing
• Number the bits starting from 1: bit 1, 2, 3, 4, 5, 6, 7, etc.
• All bit positions that are powers of two (have a single 1 bit in the
binary form of their position) are parity bits: 1, 2, 4, 8, etc. (1, 10,
100, 1000)
• In general each parity bit covers (is parity for) all bits where the
bitwise AND of the parity position and the bit position is non-zero.
• Parity bit 4 covers all bit positions which have the third least significant
bit set: bits 4–7 (0b100,0b101,0b110,0b111), 12–15, 20–23, etc.

(thanks Wikipedia)

SEC Hamming Code
• SEC: single-error correct
• C = log2D + 1
+ Relative overhead decreases as D grows

• Example: D = 4 → C = 3
• d1 d2 d3 d4 c1 c2 c3 → c1 c2 d1 c3 d2 d3 d4
• c1 = d1 ^ d2 ^ d4 , c2 = d1 ^ d3 ^ d4 , c3 = d2 ^ d3 ^ d4
• Syndrome: ci ^ c’i = 0 ? no error : points to flipped-bit

• Working example

• Original data = 0110 → c1 = 1, c2 = 1, c3 = 0
• Flip d2
= 0010 → c’1 = 0, c’2 = 1, c’3 = 1
• Syndrome = 101 (binary 5) → 5th bit? D2
• Flip c2 → c’1 = 1, c’2 = 0, c’3 = 0
• Syndrome = 010 (binary 2) → 2nd bit? c2
16

SECDED Hamming Code
• SECDED: single error correct, double error detect
• C = log2D + 2
• Additional parity bit to detect additional error

• Example: D = 4 → C = 4
• d1 d2 d3 d4 c1 c2 c3 → c1 c2 d1 c3 d2 d3 d4 c4
• c4 = c1 ^ c2 ^ d1 ^ c3 ^ d2 ^ d3 ^ d4
• Syndrome == 0 and c’4 == c4 → no error
• Syndrome != 0 and c’4 != c4 → 1-bit error
• Syndrome != 0 and c’4 == c4 → 2-bit error
• Syndrome == 0 and c’4 != c4 → c4 error

• Many machines today use 64-bit SECDED code
• C = 8 (one additional byte, 12% overhead)
• ChipKill - correct any aligned 4-bit error
• If an entire DRAM chips dies, the system still works!

Reliability: RAID
• Error correction: more important for disk than for memory
• Error correction/detection per block (handled by disk hardware)
• Mechanical disk failures (entire disk lost) most common failure mode
• Many disks means high failure rates
• Entire file system can be lost if files striped across multiple disks

• RAID (redundant array of inexpensive disks)
• Add redundancy
• Similar to DRAM error correction, but…
• Major difference: which disk failed is known
• Even parity can be used to recover from single failures
• Parity disk can be used to reconstruct data faulty disk
• RAID design balances bandwidth and fault-tolerance
• Implemented in hardware (fast, expensive) or software

21

Levels of RAID - Summary
• RAID-0 - no redundancy
• Multiplies read and write bandwidth

• RAID-1 - mirroring
• Pair disks together (write both, read one)
• 2x storage overhead
• Multiples only read bandwidth (not write bandwidth)

• RAID-3 - byte-level parity (dedicated parity disk)
• N+1 disks, calculate parity (write all, read all)
• Good sequential read/write bandwidth, poor random accesses
• If N=8, only 13% overhead

• RAID-4/5 - block-level parity
• Reads only data you need
• Writes require read, calculate parity, write data & parity

DIVA
• Why DIVA works
• Re-execution acts like an in-order stage for parallelization purposes
• Can re-execute dependent insns in parallel!
• How come? “dependence-free checking”
• You have original inputs and outputs of all insns
• No bypass/OOO/renaming etc. required…
• Can use higher “issue width” + longer pipeline + big/robust transistors

• What DIVA accomplishes
+ Detects transient errors in out-of-order stages
+ Can also detect design errors
• Re-execution (in-order) simpler than execution (out-of-order)
• Less likely to contain rare bugs (but will re-execution fix?)

• Problems:
• Redundant execution – more energy
• Highly multiported reg-file, read from reg twice – ouch!
• Doesn’t work well for inorder cores (too much overhead)
