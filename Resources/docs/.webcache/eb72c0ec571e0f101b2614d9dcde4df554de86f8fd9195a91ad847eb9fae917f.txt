# Modules

*class *drgn.Module  
A `Module` represents an executable, library, or other binary file used by a program. It has several subclasses representing specific types of modules.

Modules are uniquely identified by their type, name, and a type-specific value.

Modules have several attributes that are determined automatically whenever possible but may be overridden manually if needed.

Modules can be assigned files that provide debugging and runtime information:

- The “loaded file” is the file containing the executable code, data, etc. used by the program at runtime.

- The “debug file” is the file containing debugging information (e.g., [DWARF](https://dwarfstd.org/)).

  The loaded file and debug file may be the same file, for example, an unstripped binary. They may be different files if the binary was stripped and its debugging information was split into a separate file.

- The debug file may depend on a “supplementary debug file” such as one generated by [dwz(1)](https://manpages.debian.org/dwz.1.html). If so, then the supplementary debug file must be found before the debug file can be used.

prog*: [Final](https://docs.python.org/3/library/typing.html#typing.Final "(in Python v3.14)")\[[Program](#drgn.Program "drgn.Program")\]*  
Program that this module is from.

name*: [Final](https://docs.python.org/3/library/typing.html#typing.Final "(in Python v3.14)")\[[str](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)")\]*  
Name of this module.

Its exact meaning varies by module type.

address_ranges*: [Optional](https://docs.python.org/3/library/typing.html#typing.Optional "(in Python v3.14)")\[[Sequence](https://docs.python.org/3/library/typing.html#typing.Sequence "(in Python v3.14)")\[[Tuple](https://docs.python.org/3/library/typing.html#typing.Tuple "(in Python v3.14)")\[[int](https://docs.python.org/3/library/functions.html#int "(in Python v3.14)"), [int](https://docs.python.org/3/library/functions.html#int "(in Python v3.14)")\]\]\]*  
Address ranges where this module is loaded.

This is a sequence of tuples of the start (inclusive) and end (exclusive) addresses. For each range, the start address is strictly less than the end address. If the module is not loaded in memory, then the sequence is empty. Address ranges may not overlap.

If not known yet, then this is `None`.

[`Program.loaded_modules()`](#drgn.Program.loaded_modules "drgn.Program.loaded_modules") sets this automatically from the program state/core dump when possible. Otherwise, for [`MainModule`](#drgn.MainModule "drgn.MainModule"), [`SharedLibraryModule`](#drgn.SharedLibraryModule "drgn.SharedLibraryModule"), and [`VdsoModule`](#drgn.VdsoModule "drgn.VdsoModule"), it may be set automatically when a file is assigned to the module. It is never set automatically for [`ExtraModule`](#drgn.ExtraModule "drgn.ExtraModule"). It can also be set manually.

Other than Linux kernel loadable modules, most modules have only one address range. See [`address_range`](#drgn.Module.address_range "drgn.Module.address_range").

address_range*: [Optional](https://docs.python.org/3/library/typing.html#typing.Optional "(in Python v3.14)")\[[Tuple](https://docs.python.org/3/library/typing.html#typing.Tuple "(in Python v3.14)")\[[int](https://docs.python.org/3/library/functions.html#int "(in Python v3.14)"), [int](https://docs.python.org/3/library/functions.html#int "(in Python v3.14)")\]\]*  
Address range where this module is loaded.

This is an alias of [`address_ranges[0]`](#drgn.Module.address_ranges "drgn.Module.address_ranges") with a couple of small differences:

- If the module has more than one address range, then reading this raises a [`ValueError`](https://docs.python.org/3/library/exceptions.html#ValueError "(in Python v3.14)").

- If the module is not loaded in memory, then this is `(0,`` ``0)`.

build_id*: [Optional](https://docs.python.org/3/library/typing.html#typing.Optional "(in Python v3.14)")\[[bytes](https://docs.python.org/3/library/stdtypes.html#bytes "(in Python v3.14)")\]*  
Unique byte string (e.g., GNU build ID) identifying files used by this module.

If not known, then this is `None`.

[`Program.loaded_modules()`](#drgn.Program.loaded_modules "drgn.Program.loaded_modules") sets this automatically from the program state/core dump when possible. Otherwise, when a file is assigned to the module, it is set to the file’s build ID if it is not already set. It can also be set manually.

object*: [Object](#drgn.Object "drgn.Object")*  
The object associated with this module.

For Linux kernel loadable modules, this is the `struct`` ``module`` ``*` associated with the kernel module. For other kinds, this is currently an absent object. The object may be set manually.

loaded_file_status*: [ModuleFileStatus](#drgn.ModuleFileStatus "drgn.ModuleFileStatus")*  
Status of the module’s [loaded file](#module-loaded-file).

loaded_file_path*: [Optional](https://docs.python.org/3/library/typing.html#typing.Optional "(in Python v3.14)")\[[str](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)")\]*  
Absolute path of the module’s [loaded file](#module-loaded-file), or `None` if not known.

loaded_file_bias*: [Optional](https://docs.python.org/3/library/typing.html#typing.Optional "(in Python v3.14)")\[[int](https://docs.python.org/3/library/functions.html#int "(in Python v3.14)")\]*  
Difference between the load address in the program and addresses in the [loaded file](#module-loaded-file) itself.

This is often non-zero due to address space layout randomization (ASLR).

It is set automatically based on the module type when the loaded file is added:

- For [`MainModule`](#drgn.MainModule "drgn.MainModule"), it is set based on metadata from the process or core dump (the [auxiliary vector](https://man7.org/linux/man-pages/man3/getauxval.3.html) for userspace programs, the `VMCOREINFO` note for the Linux kernel).

- For [`SharedLibraryModule`](#drgn.SharedLibraryModule "drgn.SharedLibraryModule") and [`VdsoModule`](#drgn.VdsoModule "drgn.VdsoModule"), it is set to [`dynamic_address`](#drgn.SharedLibraryModule.dynamic_address "drgn.SharedLibraryModule.dynamic_address") minus the address of the dynamic section in the file.

- For [`RelocatableModule`](#drgn.RelocatableModule "drgn.RelocatableModule"), it is set to zero. Addresses are adjusted according to [`section_addresses`](#drgn.RelocatableModule.section_addresses "drgn.RelocatableModule.section_addresses") instead.

- For [`ExtraModule`](#drgn.ExtraModule "drgn.ExtraModule"), if [`address_ranges`](#drgn.Module.address_ranges "drgn.Module.address_ranges") is set to a single range before the file is added, then the bias is set to [`address_ranges[0][0]`](#drgn.Module.address_ranges "drgn.Module.address_ranges") (i.e., the module’s start address) minus the file’s start address. If [`address_ranges`](#drgn.Module.address_ranges "drgn.Module.address_ranges") is not set when the file is added, is empty, or comprises more than one range, then the bias is set to zero.

This cannot be set manually.

debug_file_status*: [ModuleFileStatus](#drgn.ModuleFileStatus "drgn.ModuleFileStatus")*  
Status of the module’s [debug file](#module-debug-file).

debug_file_path*: [Optional](https://docs.python.org/3/library/typing.html#typing.Optional "(in Python v3.14)")\[[str](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)")\]*  
Absolute path of the module’s [debug file](#module-debug-file), or `None` if not known.

debug_file_bias*: [Optional](https://docs.python.org/3/library/typing.html#typing.Optional "(in Python v3.14)")\[[int](https://docs.python.org/3/library/functions.html#int "(in Python v3.14)")\]*  
Difference between the load address in the program and addresses in the [debug file](#module-debug-file).

See [`loaded_file_bias`](#drgn.Module.loaded_file_bias "drgn.Module.loaded_file_bias").

supplementary_debug_file_kind*: [Optional](https://docs.python.org/3/library/typing.html#typing.Optional "(in Python v3.14)")\[[SupplementaryFileKind](#drgn.SupplementaryFileKind "drgn.SupplementaryFileKind")\]*  
Kind of the module’s [supplementary debug file](#module-supplementary-debug-file), or `None` if not known or not needed.

supplementary_debug_file_path*: [Optional](https://docs.python.org/3/library/typing.html#typing.Optional "(in Python v3.14)")\[[str](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)")\]*  
Absolute path of the module’s [supplementary debug file](#module-supplementary-debug-file), or `None` if not known or not needed.

wants_loaded_file() → [bool](https://docs.python.org/3/library/functions.html#bool "(in Python v3.14)")  
Return whether this module wants a [loaded file](#module-loaded-file).

This should be preferred over checking [`loaded_file_status`](#drgn.Module.loaded_file_status "drgn.Module.loaded_file_status") directly since this is future-proof against new status types being added. It is currently equivalent to `module.loaded_file_status`` ``==`` ``ModuleFileStatus.WANT`.

wants_debug_file() → [bool](https://docs.python.org/3/library/functions.html#bool "(in Python v3.14)")  
Return whether this module wants a [debug file](#module-debug-file).

This should be preferred over checking [`debug_file_status`](#drgn.Module.debug_file_status "drgn.Module.debug_file_status") directly since this is future-proof against new status types being added. It is currently equivalent to `module.debug_file_status`` ``==`` ``ModuleFileStatus.WANT`` ``or`` ``module.debug_file_status`` ``==`` ``ModuleFileStatus.WANT_SUPPLEMENTARY`.

wanted_supplementary_debug_file() → [WantedSupplementaryFile](#drgn.WantedSupplementaryFile "drgn.WantedSupplementaryFile")  
Return information about the [supplementary debug file](#module-supplementary-debug-file) that this module currently wants.

Raises:  
[**ValueError**](https://docs.python.org/3/library/exceptions.html#ValueError "(in Python v3.14)") – if the module doesn’t currently want a supplementary debug file (i.e., `module.debug_file_status`` ``!=`` ``ModuleFileStatus.WANT_SUPPLEMENTARY`)

try_file(*path: [Path](#drgn.Path "drgn.Path")*, *\**, *fd: [int](https://docs.python.org/3/library/functions.html#int "(in Python v3.14)") = -1*, *force: [bool](https://docs.python.org/3/library/functions.html#bool "(in Python v3.14)") = False*) → [None](https://docs.python.org/3/library/constants.html#None "(in Python v3.14)")  
Try to use the given file for this module.

If the file does not appear to belong to this module, then it is ignored. This currently checks that the file and the module have the same build ID.

If [`loaded_file_status`](#drgn.Module.loaded_file_status "drgn.Module.loaded_file_status") is [`WANT`](#drgn.ModuleFileStatus.WANT "drgn.ModuleFileStatus.WANT") and the file is loadable, then it is used as the [loaded file](#module-loaded-file) and [`loaded_file_status`](#drgn.Module.loaded_file_status "drgn.Module.loaded_file_status") is set to [`HAVE`](#drgn.ModuleFileStatus.HAVE "drgn.ModuleFileStatus.HAVE").

If [`debug_file_status`](#drgn.Module.debug_file_status "drgn.Module.debug_file_status") is [`WANT`](#drgn.ModuleFileStatus.WANT "drgn.ModuleFileStatus.WANT") or [`WANT_SUPPLEMENTARY`](#drgn.ModuleFileStatus.WANT_SUPPLEMENTARY "drgn.ModuleFileStatus.WANT_SUPPLEMENTARY") and the file provides debugging information, then it is used as the [debug file](#module-debug-file) and [`debug_file_status`](#drgn.Module.debug_file_status "drgn.Module.debug_file_status") is set to [`HAVE`](#drgn.ModuleFileStatus.HAVE "drgn.ModuleFileStatus.HAVE"). However, if the file requires a supplementary debug file, then it is not used as the debug file yet and [`debug_file_status`](#drgn.Module.debug_file_status "drgn.Module.debug_file_status") is set to [`WANT_SUPPLEMENTARY`](#drgn.ModuleFileStatus.WANT_SUPPLEMENTARY "drgn.ModuleFileStatus.WANT_SUPPLEMENTARY") instead.

If [`debug_file_status`](#drgn.Module.debug_file_status "drgn.Module.debug_file_status") is [`WANT_SUPPLEMENTARY`](#drgn.ModuleFileStatus.WANT_SUPPLEMENTARY "drgn.ModuleFileStatus.WANT_SUPPLEMENTARY") and the file matches [`wanted_supplementary_debug_file()`](#drgn.Module.wanted_supplementary_debug_file "drgn.Module.wanted_supplementary_debug_file"), then the previously found file is used as the debug file, the given file is used as the [supplementary debug file](#module-supplementary-debug-file), and [`debug_file_status`](#drgn.Module.debug_file_status "drgn.Module.debug_file_status") is set to [`HAVE`](#drgn.ModuleFileStatus.HAVE "drgn.ModuleFileStatus.HAVE").

The file may be used as both the loaded file and debug file if applicable.

Parameters:  
- **path** – Path to file.

- **fd** – If nonnegative, an open file descriptor referring to the file. This always takes ownership of the file descriptor even if the file is not used or on error, so the caller must not close it.

- **force** – If `True`, then don’t check whether the file matches the module.

*class *drgn.MainModule  
Bases: [`Module`](#drgn.Module "drgn.Module")

Main module.

There is only one main module in a program. For userspace programs, it is the executable, and its name is usually the absolute path of the executable. For the Linux kernel, it is the kernel image, a.k.a. `vmlinux`, and its name is “kernel”.

&nbsp;

*class *drgn.SharedLibraryModule  
Bases: [`Module`](#drgn.Module "drgn.Module")

Shared library (a.k.a. dynamic library, dynamic shared object, or `.so`) module.

Shared libraries are uniquely identified by their name (usually the absolute path of the shared object file) and dynamic address.

dynamic_address*: [Final](https://docs.python.org/3/library/typing.html#typing.Final "(in Python v3.14)")\[[int](https://docs.python.org/3/library/functions.html#int "(in Python v3.14)")\]*  
Address of the shared object’s dynamic section.

&nbsp;

*class *drgn.VdsoModule  
Bases: [`Module`](#drgn.Module "drgn.Module")

Virtual dynamic shared object (vDSO) module.

The vDSO is a special shared library automatically loaded into a process by the kernel; see *[vdso(7)](http://man7.org/linux/man-pages/man7/vdso.7.html)*. It is uniquely identified by its name (the `SONAME` field of the shared object file) and dynamic address.

dynamic_address*: [Final](https://docs.python.org/3/library/typing.html#typing.Final "(in Python v3.14)")\[[int](https://docs.python.org/3/library/functions.html#int "(in Python v3.14)")\]*  
Address of the shared object’s dynamic section.

&nbsp;

*class *drgn.RelocatableModule  
Bases: [`Module`](#drgn.Module "drgn.Module")

Relocatable object module.

A relocatable object is an object file requiring a linking step to assign section addresses and adjust the file to reference those addresses.

Linux kernel loadable modules (`.ko` files) are a special kind of relocatable object.

For userspace programs, relocatable objects are usually intermediate products of the compilation process (`.o` files). They are not typically loaded at runtime. However, drgn allows manually defining a relocatable module and assigning its section addresses if needed.

Relocatable modules are uniquely identified by a name and address.

address*: [Final](https://docs.python.org/3/library/typing.html#typing.Final "(in Python v3.14)")\[[int](https://docs.python.org/3/library/functions.html#int "(in Python v3.14)")\]*  
Address identifying the module.

For Linux kernel loadable modules, this is the module base address.

section_addresses*: [MutableMapping](https://docs.python.org/3/library/typing.html#typing.MutableMapping "(in Python v3.14)")\[[str](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)"), [int](https://docs.python.org/3/library/functions.html#int "(in Python v3.14)")\]*  
Mapping from section names to assigned addresses.

Once a file has been assigned to the module, this can no longer be modified.

[`Program.linux_kernel_loadable_module()`](#drgn.Program.linux_kernel_loadable_module "drgn.Program.linux_kernel_loadable_module") and [`Program.loaded_modules()`](#drgn.Program.loaded_modules "drgn.Program.loaded_modules") prepopulate this for Linux kernel loadable modules.

&nbsp;

*class *drgn.ExtraModule  
Bases: [`Module`](#drgn.Module "drgn.Module")

Module with extra debugging information.

For advanced use cases, it may be necessary to manually add debugging information that does not fit into any of the categories above. `ExtraModule` is intended for these use cases. For example, it can be used to add debugging information from a standalone file that is not in use by a particular program.

Extra modules are uniquely identified by a name and ID number. Both the name and ID number are arbitrary.

id*: [Final](https://docs.python.org/3/library/typing.html#typing.Final "(in Python v3.14)")\[[int](https://docs.python.org/3/library/functions.html#int "(in Python v3.14)")\]*  
Arbitrary identification number.

*class *drgn.ModuleFileStatus  
Bases: [`enum.Enum`](https://docs.python.org/3/library/enum.html#enum.Enum "(in Python v3.14)")

Status of a file in a [`Module`](#drgn.Module "drgn.Module").

This is usually used to communicate with debugging information finders; see [`Program.register_debug_info_finder()`](#drgn.Program.register_debug_info_finder "drgn.Program.register_debug_info_finder").

WANT  
File has not been found and should be searched for.

HAVE  
File has already been found and assigned.

DONT_WANT  
File has not been found, but it should not be searched for.

[`Module.try_file()`](#drgn.Module.try_file "drgn.Module.try_file") and debugging information finders are required to honor this and will never change it. However, other operations may reset this to [`WANT`](#drgn.ModuleFileStatus.WANT "drgn.ModuleFileStatus.WANT") when they load debugging information automatically.

DONT_NEED  
File has not been found and is not needed (e.g., because its debugging information is not applicable or is provided through another mechanism).

In contrast to [`DONT_WANT`](#drgn.ModuleFileStatus.DONT_WANT "drgn.ModuleFileStatus.DONT_WANT"), drgn itself will never change this to [`WANT`](#drgn.ModuleFileStatus.WANT "drgn.ModuleFileStatus.WANT").

WANT_SUPPLEMENTARY  
File has been found, but it requires a supplementary file before it can be used. See [`Module.wanted_supplementary_debug_file()`](#drgn.Module.wanted_supplementary_debug_file "drgn.Module.wanted_supplementary_debug_file").

*class *drgn.SupplementaryFileKind  
Bases: [`enum.Enum`](https://docs.python.org/3/library/enum.html#enum.Enum "(in Python v3.14)")

Kind of supplementary file.

Note

DWARF 5 supplementary files are not currently supported but may be in the future.

DWARF package files are not considered supplementary files. They are considered part of the debug file and must have the same path as the debug file plus a “.dwp” extension.

GNU_DEBUGALTLINK  
GNU-style supplementary debug file referred to by a `.gnu_debugaltlink` section.

Its [`checksum`](#drgn.WantedSupplementaryFile.checksum "drgn.WantedSupplementaryFile.checksum") is the file’s GNU build ID.

### Module Lookups/Constructors

For each module type, there is a corresponding method to create a module of that type or find one that was previously created:

    >>> prog.extra_module("foo", 1234)
    Traceback (most recent call last):
      ...
    LookupError: module not found
    >>> prog.extra_module("foo", 1234, create=True)
    prog.extra_module(name='foo', id=0x4d2)
    >>> prog.extra_module("foo", 1234)
    prog.extra_module(name='foo', id=0x4d2)
