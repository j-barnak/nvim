15-411/611                      © 2019-20 Goldstein       15
               Regular Expressions in Flex
             x        match the char x
             \.       match the char .
             "string" match contents of string of chars
             .        match any char except \n
             ^        match beginning of a line
             $        match the end of a line
             [xyz]    match one char x, y, or z
             [^xyz]   match any char except x, y, and z
             [a-z]    match one of a to z


15-411/611                     © 2019-20 Goldstein        16
             Regular Expressions in Flex (cont)
             r*         closure (match 0 or more r's)
             r+         positive closure (match 1 or more r's)
             r?         optional (match 0 or 1 r)
             r1 r2      match r1 then r2 (concatenation)
             r1 | r2    match r1 or r2 (union)
             ( r )      grouping
             r1 \ r2    match r1 when followed by r2
             { name }   match the RE defined by name

                  Section 2: RE/Action Rule

             • A rule has the form:
                  name          { action }
                  re            { action }
               – the name must be defined in section 1
               – the action is any C code


             • If the named RE matches* an input
               character sequence, then the C code is
               executed.                   * Some caveats here

             • Longest match rule.

                  “int”     { return INT; }

             • If rules can match same length input,
               first rule takes priority.

                  “int”        { return INT; }
                  [a-z]+       { return ID; }
                  [0-9]+       { return NUM; }

                        Regular Languages
     • Finite Alphabet, Σ, of symbols.
     • word (or string), a finite sequence of symbols
       from Σ.
     • Language over Σ is a set of words from Σ.
     • Regular Expressions describe Regular Languages.
             – easy to write down, but hard to use directly
     • The languages accepted by Finite Automata are
       also Regular.

             • finite set of states
             • set of edges from states to states labeled

             • initial state
             • set of accepting states

               – Start in initial state, on each character
                 transition goto state using edge labeled for
                 that character.
               – If at end of word we are in accepting state, the
                 word is in language
               – Language accepted are strings that cause FA to

                  Subset Construction
     • NFA: {Σ, Q, δ, q0, F} → DFA: {Σ, S, ∆, s0, F’}

     s0 ←ε-closure(q0)
     while ∃ unmarked s ∈ S:
        mark s
        foreach a ∈ Σ
           t ← ε-closure(Move(s, a))
           if t ∉ S:
              add t to S
               ∆ (s,a) ← t

             • Starts at root of parse tree and recursively
               expands children that match the input
             • In general case, may require backtracking
             • Such a parser uses recursive descent.
             • When a grammar does not require
               backtracking a predictive parser can be
               built.

             • If we have A → α | β, then we want to
               correctly choose either A → α or A → β

               can be first symbol of α, i.e.,

   • We use next k characters in input stream to guide

      • Stack holds the viable prefixes.
      • input stream holds remaining source
      • Four actions:
             – shift: push token from input stream onto stack
             – reduce: right-end of a handle (β of A → β) is at top of
               stack, pop handle (β), push A
             – accept: success
             – error: syntax error discovered

                       Key is recognizing handles efficiently

                   What LR(0) Items Mean
             • [X →  α β γ]
               input is consistent with X → α β γ
             • [X → α  β γ]
               input is consistent with X → α β γ and we
               have already recognized α
             • [X → α β  γ]
               input is consistent with X → α β γ and we
               have already recognized α β
             • [X → α β γ ]
               input is consistent with X → α β γ and we
               can reduce to X

                                 Closure*
             closure(state)
                repeat
                   foreach item A → a•Xb in state
                     foreach production X → w
                        state.add(X → •w)

                              LR(1) Items
      • An LR(1) item is an LR(0) item combined with a
        single terminal (the lookahead)
      • [X → α  β, a] Means
             – α is at top of stack
             – Input string is derivable from βa
      • In other words, when we reduce X → αβ, a had
        better be the look ahead symbol.
      • Or, Only put ‘reduce by X → αβ’ in action[s,a]

                   What LR(1) Items Mean
             • [X →  α β γ, a]
               input is consistent with X → α β γ
             • [X → α  β γ, a]
               input is consistent with X → α β γ and we
               have already recognized α
             • [X → α β  γ, a]
               input is consistent with X → α β γ and we
               have already recognized α β
             • [X → α β γ , a]
               input is consistent with X → α β γ and if
               lookahead symbol is a, then we can reduce
               to X

                           LR(1) Closure
             closure(state)
                repeat
                   foreach item A → a•Xb, t in state
                      foreach production X → w
                        and each terminal t’ in FIRST(bt)
                         state.add(X → •w, t’)
                until state does not change
                return state
