Execution engine based on VEX, Valgrind’s IR.

Responds to the following parameters to the step stack:

- irsb: The PyVEX IRSB object to use for execution. If not provided one will be lifted.

- skip_stmts: The number of statements to skip in processing

- last_stmt: Do not execute any statements after this statement

- whitelist: Only execute statements in this set

- thumb: Whether the block should be force to be lifted in ARM’s THUMB mode.

- extra_stop_points:  
  An extra set of points at which to break basic blocks

- opt_level: The VEX optimization level to use.

- insn_bytes: A string of bytes to use for the block instead of the project.

- size: The maximum size of the block, in bytes.

- num_inst: The maximum number of instructions.

- traceflags: traceflags to be passed to VEX. (default: 0)

class angr.engines.SimSuccessors  
Bases: [`object`](https://docs.python.org/3/library/functions.html#object "(in Python v3.14)")

This class serves as a categorization of all the kinds of result states that can come from a SimEngine run.

Variables:  
- **addr** ([*int*](https://docs.python.org/3/library/functions.html#int "(in Python v3.14)")) – The address at which execution is taking place, as a python int

- **initial_state** – The initial state for which execution produced these successors

- **engine** – The engine that produced these successors

- **sort** ([`str`](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)") \| [`None`](https://docs.python.org/3/library/constants.html#None "(in Python v3.14)")) – A string identifying the type of engine that produced these successors

- **processed** ([*bool*](https://docs.python.org/3/library/functions.html#bool "(in Python v3.14)")) – Whether or not the processing succeeded

- **description** ([*str*](https://docs.python.org/3/library/stdtypes.html#str "(in Python v3.14)")) – A textual description of the execution step

The successor states produced by this run are categorized into several lists:

Variables:  
- **artifacts** ([*dict*](https://docs.python.org/3/library/stdtypes.html#dict "(in Python v3.14)")) – Any analysis byproducts (for example, an IRSB) that were produced during execution

- **successors** ([`list`](https://docs.python.org/3/library/stdtypes.html#list "(in Python v3.14)")\[[`HeavyState`](https://docs.angr.io/en/latest/api/angr.engines.successors.html#angr.engines.successors.HeavyState "angr.engines.successors.HeavyState")\]) – The “normal” successors. IP may be symbolic, but must have reasonable number of solutions

- **unsat_successors** ([`list`](https://docs.python.org/3/library/stdtypes.html#list "(in Python v3.14)")\[[`HeavyState`](https://docs.angr.io/en/latest/api/angr.engines.successors.html#angr.engines.successors.HeavyState "angr.engines.successors.HeavyState")\]) – Any successor which is unsatisfiable after its guard condition is added.

- **all_successors** ([`list`](https://docs.python.org/3/library/stdtypes.html#list "(in Python v3.14)")\[[`HeavyState`](https://docs.angr.io/en/latest/api/angr.engines.successors.html#angr.engines.successors.HeavyState "angr.engines.successors.HeavyState")\]) – successors + unsat_successors

- **flat_successors** ([`list`](https://docs.python.org/3/library/stdtypes.html#list "(in Python v3.14)")\[[`HeavyState`](https://docs.angr.io/en/latest/api/angr.engines.successors.html#angr.engines.successors.HeavyState "angr.engines.successors.HeavyState")\]) – The normal successors, but any symbolic IPs have been concretized. There is one state in this list for each possible value an IP may be concretized to for each successor state.

- **unconstrained_successors** ([`list`](https://docs.python.org/3/library/stdtypes.html#list "(in Python v3.14)")\[[`HeavyState`](https://docs.angr.io/en/latest/api/angr.engines.successors.html#angr.engines.successors.HeavyState "angr.engines.successors.HeavyState")\]) – Any state for which during the flattening process we find too many solutions.

A more detailed description of the successor lists may be found here: [https://docs.angr.io/core-concepts/simulation#simsuccessors](https://docs.angr.io/core-concepts/simulation#simsuccessors)

process_successors(*successors*, *\*\*kwargs*)  
Implement this function to fill out the SimSuccessors object with the results of stepping state.

In order to implement a model where multiple mixins can potentially handle a request, a mixin may implement this method and then perform a super() call if it wants to pass on handling to the next mixin.

Keep in mind python’s method resolution order when composing multiple classes implementing this method. In short: left-to-right, depth-first, but deferring any base classes which are shared by multiple subclasses (the merge point of a diamond pattern in the inheritance graph) until the last point where they would be encountered in this depth-first search. For example, if you have classes A, B(A), C(B), D(A), E(C, D), then the method resolution order will be E, C, B, D, A.

Parameters:  
- **state** – The state to manipulate

- **successors** ([`SimSuccessors`](https://docs.angr.io/en/latest/api/angr.engines.successors.html#angr.engines.successors.SimSuccessors "angr.engines.successors.SimSuccessors")) – The successors object to fill out

- **kwargs** – Any extra arguments. Do not fail if you are passed unexpected arguments.
