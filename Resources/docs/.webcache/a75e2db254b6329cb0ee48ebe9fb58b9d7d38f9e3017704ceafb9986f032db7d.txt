## Introduction

**Please note that rolling your own filesystem IS NOT RECOMMENDED**. You're likely to make it a FAT style filesystem, and please, we don't need another one of those. However, for those of you who wish to defy convention, then we need to stop you making another FAT for sanity's sake. So here is a tutorial on how to avoid a FAT (of course, the design is up to you, so we can't give you a *complete* tutorial on how to make it).

## Use FUSE

The best practice for a new file system is to start with a [FUSE](https://wiki.osdev.org/FUSE "FUSE") driver. This is a simple user space application running on your build machine that allows mounting partition images of your file system. With that, you can easily create files and directories in the image, and later you can re-use significant parts of the code in your kernel when you'll write your native FS implementation. It is much preferable than writing your own image creator.

## Booting from your filesystem

You have 4 options here. Here are your options, in order of difficulty (and reward)

- Don't boot from it. Use a dedicated boot partition (like [EFI System Partition](https://wiki.osdev.org/EFI_System_Partition "EFI System Partition")) and your FS as the root.
- Use [BOOTBOOT](https://wiki.osdev.org/BOOTBOOT "BOOTBOOT") which can load an initial ramdisk from any file system.
- [Roll your own bootloader](https://wiki.osdev.org/Rolling_Your_Own_Bootloader "Rolling Your Own Bootloader")
- Use [GRUB](https://wiki.osdev.org/GRUB "GRUB") by [Writing a GRUB Module](https://wiki.osdev.org/Writing_GRUB_Modules "Writing GRUB Modules"). You didn't expect GRUB to by psychic and magically code itself, did you?
