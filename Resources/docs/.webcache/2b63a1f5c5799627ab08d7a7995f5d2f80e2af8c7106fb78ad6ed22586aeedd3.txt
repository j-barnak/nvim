# Contracts

A *contract* operates at [run time](https://beautifulracket.com/appendix/glossary.html#run-time) and restricts the values that can pass across the boundary between two parts of a program. Contracts are primarily used with [functions](https://beautifulracket.com/explainer/functions.html) to check that input arguments and return values meet certain requirements. This makes it easier to prevent the consequences of bad input, and locate the source of the problem.

For instance, here’s an irresponsible our-div function that allows 0 as a denom argument. Bad input produces a generic error:

(define (our-div num denom)
  (/ num denom))
(our-div 42 0)

Better still is a contract: it offers more compact & readable notation, more detail about the error, and takes care of all the underlying housekeeping. The contract below says that the first argument can be any [number?](http://docs.racket-lang.org/reference/number-types.html#(def._((quote._~23~25kernel)._number~3f))), the second argument must be a number? that is not [zero?](http://docs.racket-lang.org/reference/number-types.html#(def._((quote._~23~25kernel)._zero~3f))), and the return value must be a number?:

(require racket/contract) ; imports contract ingredients
(define/contract (our-div num denom)
  (number? (and/c number? (not/c zero?)) . -\> . number?)
  (/ num denom))
(our-div 42 0)

### [Boundaries](#boundaries)

A function contract can be positioned at one of two boundaries (and in either place, we have to require racket/contract into the module):

1.

    At a module boundary, using [contract-out](http://docs.racket-lang.org/reference/attaching-contracts-to-values.html#(form._((lib._racket/contract/base..rkt)._contract-out))) with [provide](http://docs.racket-lang.org/reference/require.html#(form._((lib._racket/private/base..rkt)._provide))). In this case, only the calls to the function from outside the module will invoke the contract:

    (module divs br
      (require racket/contract)
      (provide
       (contract-out
        \[int-div (integer? integer? . -\> . integer?)\]))
      (define (int-div num denom)
        (/ num denom))

      (with-handlers (\[exn:fail? (λ (e) 'inner-breach)\])
        (displayln (int-div 42 2.5))))

    (require (submod "." divs))
    (with-handlers (\[exn:fail? (λ (e) 'outer-breach)\])
      (displayln (int-div 42 2.5)))

2.

    At the function boundary, using [define/contract](http://docs.racket-lang.org/reference/attaching-contracts-to-values.html#(form._((lib._racket/contract/region..rkt)._define/contract))). Every call to the function will trigger the contract, even within the module. Below, int-div has a contract for [integer?](http://docs.racket-lang.org/reference/number-types.html#(def._((quote._~23~25kernel)._integer~3f))) input and output. When called with a floating-point argument, whether inside or outside the submodule, it will cause an error:  + For demonstration purposes, we’re trapping these errors using [with-handlers](http://docs.racket-lang.org/reference/exns.html#(form._((lib._racket/private/more-scheme..rkt)._with-handlers))).       (with-handlers (\[exn:fail? (λ (e) 'inner-breach)\])
        (displayln (int-div 42 2.5))))

    (require (submod "." divs))
    (with-handlers (\[exn:fail? (λ (e) 'outer-breach)\])
      (displayln (int-div 42 2.5)))

More exotic combinations are possible. For instance, we could make a safe submodule for a given module that exports all the same bindings, but with contracts added. Then the user could choose whether to import that module with or without its contracts active, by choosing to require either the usual module-name or (submod module-name safe).

### [Combinators](#combinators)

A function contract consists of a *[combinator](https://beautifulracket.com/appendix/glossary.html#combinator)* followed by *[predicates](https://beautifulracket.com/appendix/glossary.html#predicate)*—one predicate corresponding to each input argument, then one more corresponding to the return value. For a function with a fixed number of arguments (aka fixed [arity](https://beautifulracket.com/appendix/glossary.html#arity)), use the [-\>](http://docs.racket-lang.org/reference/function-contracts.html#(form._((lib._racket/contract/base..rkt)._-~3e))) combinator:

(define/contract (f str int)
  (-\> string? integer? number?)
  42)

    (define/contract (f str int)
      (-> string? integer? number?)
      42)

![copy to clipboard](https://beautifulracket.com/fonts/feather-v1.1/svg/download.svg)

This contract would be used with a function that takes two arguments—a [string?](http://docs.racket-lang.org/reference/strings.html#(def._((quote._~23~25kernel)._string~3f))) and an [integer?](http://docs.racket-lang.org/reference/number-types.html#(def._((quote._~23~25kernel)._integer~3f)))—and returns a [number?](http://docs.racket-lang.org/reference/number-types.html#(def._((quote._~23~25kernel)._number~3f))). For readability, it’s conventional to write contracts using Racket’s [infix notation](https://beautifulracket.com/appendix/glossary.html#infix-notation), so this contract could be written like so:

(define/contract (f str int)
  (string? integer? . -\> . number?)
  42)

(define/contract (f \#:this str \#:that int)
  (#:this string? \#:that integer? . -\> . number?)

      (#:this string? #:that integer? . -> . number?)

![copy to clipboard](https://beautifulracket.com/fonts/feather-v1.1/svg/download.svg)

If the function has [optional arguments](https://beautifulracket.com/appendix/glossary.html#optional-argument), use the [-\>\*](http://docs.racket-lang.org/reference/function-contracts.html#(form._((lib._racket/contract/base..rkt)._-~3e*))) combinator. The mandatory and optional arguments are grouped into their own parenthesized sublists. So a function with two mandatory string arguments and an optional integer argument would have this contract:

(define/contract (f str str2 \[int 0\])
  ((string? string?) (integer?) . -\>\* . number?)
  42)

### [Predicates](#predicates)

A *predicate* is a function that takes any single value and returns a Boolean. Any predicate can be used within a contract—either predicates from the Racket library, or ones you create (use [any/c](http://docs.racket-lang.org/reference/data-structure-contracts.html#(def._((lib._racket/contract/private/misc..rkt)._any/c))) in a contract to accept any value):

(require racket/contract)
(define/contract (divisible-by-3? x)
  (any/c . -\> . boolean?)
  (zero? (modulo x 3)))

(define/contract (f x)
  (divisible-by-3? . -\> . integer?)
  x)
(f 6) ; 6
(f 3) ; 3
(f 4) ; contract violation (not \`divisible-by-3?\`)

The contract library also provides tools for refining predicates, like [or/c](http://docs.racket-lang.org/reference/data-structure-contracts.html#(def._((lib._racket/contract/base..rkt)._or/c))), [and/c](http://docs.racket-lang.org/reference/data-structure-contracts.html#(def._((lib._racket/contract/base..rkt)._and/c))), and [not/c](http://docs.racket-lang.org/reference/data-structure-contracts.html#(def._((lib._racket/contract/private/misc..rkt)._not/c))):

(require racket/contract)
(define (divisible-by-3? x) (zero? (modulo x 3)))

(define/contract (f x)
  ((and/c divisible-by-3? even?) . -\> . (not/c flonum?))
  x)

(f 6) ; 6
(f 6.0) ; contract violation (not \`(not/c flonum?)\`)
(f 3) ; contract violation (not \`even?\`)
(f 4) ; contract violation (not \`divisible-by-3?\`)

(define/contract (f . xs)
  (() () \#:rest (listof divisible-by-3?) . -\>\* . any/c)
  xs)

### [But there is a price](#but-there-is-a-price)

“If contracts are so great, why don’t we use them all the time?” Because they’re not free.  + *A Lisp programmer knows the value of everything, but the cost of nothing.*
—Alan Perlis (channeling Oscar Wilde) A contract operates at [run time](https://beautifulracket.com/appendix/glossary.html#run-time), so it necessarily imposes a performance cost. Contracts offer the tradeoff—that we often encounter in programming—between safety and speed.

Contracts can impose unreasonable costs in three situations:

1.

    If a function is frequently called, then its contract will be too. The speed of that contract will have an outsize effect on the overall program. (Especially because it’s not uncommon to find that the contract takes more time than the rest of the function.)

    *Possible solution:* write the argument checking by hand. Helper functions like [raise-argument-error](http://docs.racket-lang.org/reference/exns.html#(def._((quote._~23~25kernel)._raise-argument-error))) can create the same type of error a contract would (though slightly less descriptive):

    (define (our-div num denom)
      (unless (and (number? denom) (not (zero? denom)))
        (raise-argument-error
         'our-div
         "nonzero number for denom"
         denom))
      (/ num denom))
    (our-div 42 0)

2.

    A contract is a function that calls a series of other functions to test its arguments. If those functions are themselves slow, then the contract will be too. *Possible solution:* simplify the contract to use faster checks.

3.

    If the data structures that pass through the contract boundary tend to be huge (like giant lists), any contract that checks every element (like [listof](http://docs.racket-lang.org/reference/data-structure-contracts.html#(def._((lib._racket/contract/base..rkt)._listof)))) will be slow. *Possible solution:* package the data into a [structure type](https://beautifulracket.com/appendix/glossary.html#structure-type), which can be tested quickly, because it has its own [predicate](https://beautifulracket.com/appendix/glossary.html#predicate).

Of course, any contract installed at a function boundary (with [define/contract](http://docs.racket-lang.org/reference/attaching-contracts-to-values.html#(form._((lib._racket/contract/region..rkt)._define/contract)))) will likely be called more often than one installed at a module boundary (with [contract-out](http://docs.racket-lang.org/reference/attaching-contracts-to-values.html#(form._((lib._racket/contract/base..rkt)._contract-out)))). Choosing boundaries wisely will improve performance by only using the contract where it’s needed most.

Following that logic, functions that touch the public interface of a program are likely to benefit more from contracts (because they have less control over their input) than functions that only touch the private interface.
