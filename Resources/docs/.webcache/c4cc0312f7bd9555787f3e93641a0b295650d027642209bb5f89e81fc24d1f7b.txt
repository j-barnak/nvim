Expand description

An [`i128`](https://doc.rust-lang.org/std/primitive.i128.html "primitive i128") that is known not to equal zero.

This enables some memory layout optimization. For example, `Option<NonZeroI128>` is the same size as `i128`:

``` rust
assert_eq!(size_of::<Option<core::num::NonZeroI128>>(), size_of::<i128>());
```

## Layout

`NonZeroI128` is guaranteed to have the same layout and bit validity as `i128` with the exception that `0` is not a valid instance. `Option<NonZeroI128>` is guaranteed to be compatible with `i128`, including in FFI.

Thanks to the [null pointer optimization](https://doc.rust-lang.org/std/option/index.html#representation "mod std::option"), `NonZeroI128` and `Option<NonZeroI128>` are guaranteed to have the same size and alignment:

``` rust
use std::num::NonZeroI128;

assert_eq!(size_of::<NonZeroI128>(), size_of::<Option<NonZeroI128>>());
assert_eq!(align_of::<NonZeroI128>(), align_of::<Option<NonZeroI128>>());
```

## Compile-time creation

Since both [`Option::unwrap()`](https://doc.rust-lang.org/std/option/enum.Option.html#method.unwrap "method std::option::Option::unwrap") and [`Option::expect()`](https://doc.rust-lang.org/std/option/enum.Option.html#method.expect "method std::option::Option::expect") are `const`, it is possible to define a new `NonZeroI128` at compile time via:

``` rust
use std::num::NonZeroI128;

const TEN: NonZeroI128 = NonZeroI128::new(10).expect("ten is non-zero");
```
