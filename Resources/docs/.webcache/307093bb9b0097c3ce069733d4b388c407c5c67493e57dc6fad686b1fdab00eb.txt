1.11.0 (const: [unstable](https://github.com/rust-lang/rust/issues/137844 "Tracking issue for const_ref_cell")) · [Source](https://doc.rust-lang.org/src/core/cell.rs.html#1330)

Returns a mutable reference to the underlying data.

Since this method borrows `RefCell` mutably, it is statically guaranteed that no borrows to the underlying data exist. The dynamic checks inherent in [`borrow_mut`](https://doc.rust-lang.org/std/cell/struct.RefCell.html#method.borrow_mut "method std::cell::RefCell::borrow_mut") and most other methods of `RefCell` are therefore unnecessary. Note that this method does not reset the borrowing state if borrows were previously leaked (e.g., via [`forget()`](https://doc.rust-lang.org/std/mem/fn.forget.html "fn std::mem::forget") on a [`Ref`](https://doc.rust-lang.org/std/cell/struct.Ref.html "struct std::cell::Ref") or [`RefMut`](https://doc.rust-lang.org/std/cell/struct.RefMut.html "struct std::cell::RefMut")). For that purpose, consider using the unstable [`undo_leak`](https://doc.rust-lang.org/std/cell/struct.RefCell.html#method.undo_leak "method std::cell::RefCell::undo_leak") method.

This method can only be called if `RefCell` can be mutably borrowed, which in general is only the case directly after the `RefCell` has been created. In these situations, skipping the aforementioned dynamic borrowing checks may yield better ergonomics and runtime-performance.

In most situations where `RefCell` is used, it can’t be borrowed mutably. Use [`borrow_mut`](https://doc.rust-lang.org/std/cell/struct.RefCell.html#method.borrow_mut "method std::cell::RefCell::borrow_mut") to get mutable access to the underlying data then.

##### Examples

``` rust
use std::cell::RefCell;

let mut c = RefCell::new(5);
*c.get_mut() += 1;

assert_eq!(c, RefCell::new(6));
```

[Source](https://doc.rust-lang.org/src/core/cell.rs.html#1357)

🔬This is a nightly-only experimental API. (`cell_leak` [\#69099](https://github.com/rust-lang/rust/issues/69099))

Undo the effect of leaked guards on the borrow state of the `RefCell`.

This call is similar to [`get_mut`](https://doc.rust-lang.org/std/cell/struct.RefCell.html#method.get_mut "method std::cell::RefCell::get_mut") but more specialized. It borrows `RefCell` mutably to ensure no borrows exist and then resets the state tracking shared borrows. This is relevant if some `Ref` or `RefMut` borrows have been leaked.

##### Examples

``` rust
#![feature(cell_leak)]
use std::cell::RefCell;

let mut c = RefCell::new(0);
std::mem::forget(c.borrow_mut());

assert!(c.try_borrow().is_err());
c.undo_leak();
assert!(c.try_borrow().is_ok());
```

1.37.0 (const: [unstable](https://github.com/rust-lang/rust/issues/137844 "Tracking issue for const_ref_cell")) · [Source](https://doc.rust-lang.org/src/core/cell.rs.html#1392)

Immutably borrows the wrapped value, returning an error if the value is currently mutably borrowed.

##### Safety

Unlike `RefCell::borrow`, this method is unsafe because it does not return a `Ref`, thus leaving the borrow flag untouched. Mutably borrowing the `RefCell` while the reference returned by this method is alive is undefined behavior.

##### Examples

``` rust
use std::cell::RefCell;

let c = RefCell::new(5);

{
    let m = c.borrow_mut();
    assert!(unsafe { c.try_borrow_unguarded() }.is_err());
}

{
    let m = c.borrow();
    assert!(unsafe { c.try_borrow_unguarded() }.is_ok());
}
```
