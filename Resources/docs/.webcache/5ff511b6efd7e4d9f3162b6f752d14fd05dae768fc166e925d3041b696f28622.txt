Expand description

A virtual function pointer table (vtable) that specifies the behavior of a [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker").

The pointer passed to all functions inside the vtable is the `data` pointer from the enclosing [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") object.

The functions inside this struct are only intended to be called on the `data` pointer of a properly constructed [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") object from inside the [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") implementation. Calling one of the contained functions using any other `data` pointer will cause undefined behavior.

Note that while this type implements `PartialEq`, comparing function pointers, and hence comparing structs like this that contain function pointers, is unreliable: pointers to the same function can compare inequal (because functions are duplicated in multiple codegen units), and pointers to *different* functions can compare equal (since identical functions can be deduplicated within a codegen unit).

## Thread safety

If the [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") will be used to construct a [`Waker`](https://doc.rust-lang.org/std/task/struct.Waker.html "struct std::task::Waker") then these functions must all be thread-safe (even though [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") is `!`[`Send`](https://doc.rust-lang.org/std/marker/trait.Send.html "trait std::marker::Send")` + !`[`Sync`](https://doc.rust-lang.org/std/marker/trait.Sync.html "trait std::marker::Sync")). This is because [`Waker`](https://doc.rust-lang.org/std/task/struct.Waker.html "struct std::task::Waker") is [`Send`](https://doc.rust-lang.org/std/marker/trait.Send.html "trait std::marker::Send")` + `[`Sync`](https://doc.rust-lang.org/std/marker/trait.Sync.html "trait std::marker::Sync"), and it may be moved to arbitrary threads or invoked by `&` reference. For example, this means that if the `clone` and `drop` functions manage a reference count, they must do so atomically.

However, if the [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") will be used to construct a [`LocalWaker`](https://doc.rust-lang.org/std/task/struct.LocalWaker.html "struct std::task::LocalWaker") instead, then these functions don’t need to be thread safe. This means that `!`[`Send`](https://doc.rust-lang.org/std/marker/trait.Send.html "trait std::marker::Send")` + !`[`Sync`](https://doc.rust-lang.org/std/marker/trait.Sync.html "trait std::marker::Sync") data can be stored in the data pointer, and reference counting does not need any atomic synchronization. This is because [`LocalWaker`](https://doc.rust-lang.org/std/task/struct.LocalWaker.html "struct std::task::LocalWaker") is not thread safe itself, so it cannot be sent across threads.

Creates a new `RawWakerVTable` from the provided `clone`, `wake`, `wake_by_ref`, and `drop` functions.

If the [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") will be used to construct a [`Waker`](https://doc.rust-lang.org/std/task/struct.Waker.html "struct std::task::Waker") then these functions must all be thread-safe (even though [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") is `!`[`Send`](https://doc.rust-lang.org/std/marker/trait.Send.html "trait std::marker::Send")` + !`[`Sync`](https://doc.rust-lang.org/std/marker/trait.Sync.html "trait std::marker::Sync")). This is because [`Waker`](https://doc.rust-lang.org/std/task/struct.Waker.html "struct std::task::Waker") is [`Send`](https://doc.rust-lang.org/std/marker/trait.Send.html "trait std::marker::Send")` + `[`Sync`](https://doc.rust-lang.org/std/marker/trait.Sync.html "trait std::marker::Sync"), and it may be moved to arbitrary threads or invoked by `&` reference. For example, this means that if the `clone` and `drop` functions manage a reference count, they must do so atomically.

However, if the [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") will be used to construct a [`LocalWaker`](https://doc.rust-lang.org/std/task/struct.LocalWaker.html "struct std::task::LocalWaker") instead, then these functions don’t need to be thread safe. This means that `!`[`Send`](https://doc.rust-lang.org/std/marker/trait.Send.html "trait std::marker::Send")` + !`[`Sync`](https://doc.rust-lang.org/std/marker/trait.Sync.html "trait std::marker::Sync") data can be stored in the data pointer, and reference counting does not need any atomic synchronization. ##### `clone`

This function will be called when the [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") gets cloned, e.g. when the [`Waker`](https://doc.rust-lang.org/std/task/struct.Waker.html "struct std::task::Waker")/[`LocalWaker`](https://doc.rust-lang.org/std/task/struct.LocalWaker.html "struct std::task::LocalWaker") in which the [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") is stored gets cloned.

The implementation of this function must retain all resources that are required for this additional instance of a [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") and associated task. Calling `wake` on the resulting [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") should result in a wakeup of the same task that would have been awoken by the original [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker").

##### `wake`

This function will be called when `wake` is called on the [`Waker`](https://doc.rust-lang.org/std/task/struct.Waker.html "struct std::task::Waker"). It must wake up the task associated with this [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker").

The implementation of this function must make sure to release any resources that are associated with this instance of a [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") and associated task.

##### `wake_by_ref`

This function will be called when `wake_by_ref` is called on the [`Waker`](https://doc.rust-lang.org/std/task/struct.Waker.html "struct std::task::Waker"). It must wake up the task associated with this [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker").

This function is similar to `wake`, but must not consume the provided data pointer.

##### `drop`

This function will be called when a [`Waker`](https://doc.rust-lang.org/std/task/struct.Waker.html "struct std::task::Waker")/[`LocalWaker`](https://doc.rust-lang.org/std/task/struct.LocalWaker.html "struct std::task::LocalWaker") gets dropped.

The implementation of this function must make sure to release any resources that are associated with this instance of a [`RawWaker`](https://doc.rust-lang.org/std/task/struct.RawWaker.html "struct std::task::RawWaker") and associated task.
