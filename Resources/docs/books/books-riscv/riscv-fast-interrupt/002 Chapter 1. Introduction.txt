
Chapter 1. Introduction
The set of extensions defined in this specification enhance the existing interrupt specifications. The
Advanced Core Local Interrupt Controller (ACLIC) is a single hart interrupt controller defined for:

 ⚫ Low latency interrupt handling
 ⚫ High throughput interrupt handling
 ⚫ Up to 1023 external interrupts
 ⚫ Low area overhead
 ⚫ Maximized compatibility with AIA

The table below provides a summary of the ACLIC extensions.

Extension Name        Description
Fundamental ACLIC Extensions
Smidctrl              Interrupt domain control interface at Machine level
Ssidctrl              Interrupt domain control interface at Supervisor level
Smnip                 Nested Interrupt Preemption support at Machine level
Ssnip                 Nested Interrupt Preemption support at Supervisor level
Fast Interrupt Extensions for Microcontrollers
Smijt                 Interrupt jump table at Machine level
Ssijt                 Interrupt jump table at Supervisor level
Smehv                 Synchronous exception hardware vectoring at Machine level
Ssehv                 Synchronous exception hardware vectoring at Supervisor level
Smcsps                Conditional stack pointer swap at Machine level
Sscsps                Conditional stack pointer swap at Supervisor level
Smip                  Support for interrupt handler push/pop at Machine level
Ssip                  Support for interrupt handler push/pop at Supervisor level

This specification aims for single-hart systems and no support for the H extension is foreseen.

                  The extensions defined here are orthogonal to the NMI and RNMI mechanisms. Their behavior
                 is unchanged by the extensions of ACLIC.

                  "Fast" interrupt features have become state of the art in microcontrollers in incumbent
                  architectures. Namely, automatic hardware stacking, tailchaining, late arrival, lazy stacking,
                  hardware vectoring, interrupt nesting, and stack separation. These features were introduced to
                  minimize interrupt latency and memory footprint in microcontrollers. These are vital in ultra
                  low-cost MCUs fabricated in less dense process nodes, running at 10s of MHz with only KiB of
                  memory. It is therefore important to make a distinction between these two types of system,
                  hereafter termed "Constrained Microcontrollers" and "High Performance Microcontrollers".
    
                  Constrained Microcontrollers are characterized by lower performance (10s of MHz), lower
                  memory availability (KiB), less dense technology nodes and running bare metal code. For these
                  systems, the cycles and memory saved from fast interrupt features can have a large relative
                  impact on the overall system cost and interrupt latency. Therefore, even features that have
                  minimal cycle impact on interrupt latency and only bare metal code could take advantage of
                  are considered for Constrained Microcontrollers.

                   High Performance Microcontrollers are characterized by high performance (100s of MHz),
                   high memory availability (MiB), denser technology nodes, and running an real-time operating
                   system (RTOS) or real-time hypervisor. For these systems, the cycles and memory saved from
                   fast interrupt features have a relatively small impact on the overall system cost and interrupt
                   latency. Therefore, only features that have a large cycle impact on interrupt latency and that
                   major RTOSes could take advantage of are considered for High Performance Microcontrollers.

                   Both types of microcontrollers are expected to implement some or all of Fundamental ACLIC
                   Extensions. Constrained microcontrollers are expected to implement some or all of Fast
                   Interrupt Extensions for Microcontrollers in addition.
