Chapter 5. Cryptography
RISC-V supports a number of ISA-level extensions aimed at improving performance for cryptographic
operations (scalar and vector). It also includes an ISA-level entropy source, and guidelines for data
independent execution latency.

See Cryptography

Current ISA level cryptographic extensions work at round level. With the data independent execution
latency properties, they can provide some mitigation against some side-channel attacks, such as cache
timing attacks. They may not defend fully against some differential power analysis, for example.

Work is on-going to define ISA-level high assurance cryptography (HAC). This work includes defining full-
round operations to increase side-channel resistance; adding operations supporting post-quantum
cryptography (PQC); and adding ISA-level privilege-based key management.

Cryptographic requirements depend on target ecosystem, as well as on varying regulatory requirements in
different geographic regions. This chapter summarizes commonly used cryptographic guidance for secure
systems, provided as guidance for development of RISC-V specifications and RISC-V based secure systems.

5.1. PQC readiness
Quantum safe cryptography is an evolving area of research[1].

The first three NIST standardized algorithms are ML-KEM (FIPS-203), ML-DSA (FIPS-204), and SLH-DSA
(FIPS-205). ML-KEM defines a key-encapsulation mechanism used to establish a shared secret key over a
public channel. ML-DSA and SLH-DSA defined digital signature schemes.

RISC-V systems and specifications must at least support a migration path towards use of PQC.

ID#                        Requirement
SR_CPT_004                 In applications which require a migration path to PQC algorithms, all immutable components
                           SHOULD support PQC alternatives.
SR_CPT_005                 All mutable components MUST at least have a migration path to quantum safe cryptography.

Immutable components, in particular immutable boot code, cannot be updated. To provide a full migration
path for a system, immutable components need to support PQC alternatives.

Mutable stages can be updated, and can provide a migration path to quantum safe cryptography. For
example, system designers should consider protocols, governance, and storage requirements for upgrading
hardware provisioned assets to PQC versions.

5.2. Cryptographic algorithms and guidelines
Cryptographic recommendations are use-case and region specific, each legal jurisdiction has their own
guidance. Thus, this specification considers such recommendations to be out-of-scope. It is recommended
that a RISC-V platform vendor follows the recommendations for the jurisdictions where their platform will
be sold. The current section points readers to resources where cryptographic recommendations can be
found for most jurisdictions.

The following resources provide general cryptographic guidance applicable to most western jurisdictions:
NIST and CNSA 2.0.

The European Union (EU), through the Cyber Resilience Act (CRA), provides an "allow list" of cryptographic
algorithms pointing to the Agreed Cryptographic Mechanisms 2.0. Since the CRA is not currently enforced,
other jurisdictions within the EU have their own recommendations. For example, France and Germany.

Some legacy use cases may require use of other algorithms, such as SHA-256 or AES-128. In these cases,
wherever possible, an upgrade path should be supported. For example, allocating sufficient storage to
accommodate larger sizes in future updates.

Some use cases, such as cryptographic memory protection, may sometimes use specialized algorithms for
performance in a constrained use case. These are not discussed here but should have similar properties to
the ones listed above, but with different trade-offs.

For Chinese markets[2], equivalent ShangMi (SM) algorithm support is required. In particular:

 ⚫ SM2: Authentication (ECC based)
 ⚫ SM3: Hash function (256-bit)
 ⚫ SM4: Block cipher

RISC-V cryptographic ISA extensions also include support for ShangMi algorithms (SM3 and SM4)

Some Shang-Mi algorithms are also described in ISO specifications.

Other specific markets also require regional cryptographic algorithms, for example Russian Ghost. RISC-V
cryptographic ISA extensions currently do not directly support Russia specific algorithms.
