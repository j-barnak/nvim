                                    Async Functions in Rust
                                    Rust’s async functions rely heavily on closures, special functions capturing variables from their enclosing
                                    scope. These closures are crucial for async functions, allowing them to maintain state between invocations.
                                    For a deeper understanding, refer to the chapter “Closures: From Environment to Execution”, which explains
                                    the fundamental workings of closures in Rust.
                                    Asynchronous programming in Rust primarily uses futures and the async/await syntax, simplifying the
                                    writing of non-blocking, concurrent code. Futures are abstractions for operations that may not have
                                    finished executing, representing potentially ongoing computations. The Future trait in Rust describes
                                    these asynchronous computations. A future holds a value that may not be ready yet.
                                    The async/await construct lets code pause. It hands control back to the runtime. Later, the code resumes
                                    without blocking the thread. This approach allows writing code that appears synchronous while the
                                    compiler automatically transforms it into asynchronous code.

                                        Learn More: Single Threaded Async Executor
                                    In Rust, async functions effectively act as syntactic sugar over futures, representing computations that
                                    might not yet be complete. However, futures and async/await functions do not perform any computation
                                    independently; they require an environment for execution provided by the async executor. An async
                                    executor in Rust takes charge of polling futures to completion, managing their state, and overseeing task
                                    scheduling and execution.
                                    A single-threaded async executor handles the execution of tasks in an asynchronous context using only one
                                    thread. It multiplexes multiple tasks onto the same thread, switching between them as tasks voluntarily
                                    suspend their execution, often due to waiting for an I/O operation or a timer.
lanchonbeef@gmail.com 24 Aug 2025

                                    Part F Closures and Async/Await
                                    Internally, a single-threaded executor operates with an event loop and a task queue. When scheduled for
                                    execution, futures enter the task queue. The executor then launches into the event loop, cycling through
                                    futures from the queue and polling them. If a future is not ready, typically awaiting the completion of an I/O
                                    operation, it hands control back to the executor, allowing the executor to proceed to the next task. Once a
                                    future is ready, the executor resolves it, enabling the caller of the async function to access its result.

                                    Futures and Closures
                                    In Rust, async/await mechanisms build on the concept of closures and Futures. When you write an async
                                    function in Rust, the compiler transforms it into a state machine, where each state represents a particular
                                    “await point” in your function.

                                    environment and returns a Future. Each time the executor polls this Future, it effectively resumes the
                                    closure from where it last left off (the last await point).

                                          Key Takeaways
                                      •     An await in an async function typically results in a poll call on the future. If the future is not ready,
                                            the poll method returns Poll::Pending. The poll method returns Poll::Ready if the future is
                                            ready.
                                      •     The async function itself returns a future that wraps a closure. The poll method of the future calls
                                            the closure.
                                      •     The closure functions as a state machine, with the compiler representing the await points as state
                                            transitions.
                                               –    A compiler-generated closure stores the state.
                                               –    The compiler generates a jump table that maps from the current state to the code handling
                                                    the state.
                                      •     An async function in Rust returning a type T is equivalent to a regular function that returns an
                                            anonymous type implementing Future<Output = T>.
                                      •     In an async function, the closure environment stores the local variables that must persist across
                                            invocations. Too many such local variables can cause the closure environment to be large.
