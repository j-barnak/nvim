
                                                    Chapter 4
                                    Deep Dive into Enums: Layout and Patterns

                                    In this chapter, we will learn about enum representation in memory. We will go under the hood and see
                                    how the Rust compiler generates code for enums and pattern matching. We will also learn to use enums
                                    and pattern matching to write efficient code.
                                    We will look at the following examples:
                                      •    Pattern Matching an Enum
                                      •    Using Null Pointers as Discriminators
                                      •    Discriminator Size in a Small Enum

                                    Pattern Matching an Enum
                                    Enums in Rust are discriminated unions that can hold one of several variants. The enum discriminator
                                    determines the current interpretation of the discriminated union.
                                    The following code shows a simple enum in Rust that represents a generalized Number that can be an
                                    Integer, a Float, or a Complex. Here, Number is a container that can store a 64-bit integer (i64), a 64-bit
                                    floating-point number (f64), or a complex number (stored in a struct with two f64 fields).

                                    The code that follows the enumeration definition introduces a function named double. This function takes
                                    a parameter of type Number and outputs another Number, doubling each field of the input Number
                                    regardless of the specific Number variant from the enum. The match expression is employed within this
                                    function to discern the enum variant and generate the corresponding doubled variant.

                                    pub enum Number {
                                        Integer(i64),
                                        Float(f64),
                                        Complex { real: f64, imaginary: f64 },
                                    }

                                    pub fn double(num: Number) -> Number {
                                        match num {
                                            Number::Integer(n) => Number::Integer(n + n),
                                            Number::Float(n) => Number::Float(n + n),
                                            Number::Complex { real, imaginary } => Number::Complex {

                                                     real: real + real,
                                                     imaginary: imaginary + imaginary,
                                               },
                                          }
                                    }

                                    Memory Layout of a Rust Enum
                                    Before proceeding further, let us look at the enum organization in memory. The size of the enum depends
                                    upon the largest variant. In this example, a Number::Complex requires two 64-bit floats. Hence, the total
                                    memory needed for the variant is 16 bytes. The enum occupies 24 bytes, with an extra 8 bytes dedicated to
                                    storing a 64-bit discriminator that identifies the variant currently saved in the enum.
                                    The following table shows the memory layout of the Number enum.

                                                        Byte offset Integer           Float             Complex
                                                        0           Discriminator (0) Discriminator (1) Discriminator (2)
                                                        8           i64               f64               f64
                                                        16                                              f64

                                         Learn More: Enum Discriminator Size
                                    A 64-bit discriminator seems wasteful here. Due to the padding rules, a smaller discriminator would not
                                    have saved any memory. Rust does switch to a smaller discriminator when doing so will save space.
                                    Rust can also employ the Null pointer optimization to save space. For instance, in an Option<Box<T>>, the
                                    null pointer represents a None, while a pointer to the T value represents Some. No discriminator is
                                    necessary in this scenario. The Option Wrapping a Box Type section discusses this optimization.

                                    Overview of the Generated Code
                                    Before we dig deep into the assembly, let us get an overview of the generated code via the following
                                    flowchart. The code branches based on the enum discriminator and handles the processing of each enum
                                    discriminator separately. It then writes the results and discriminator values at the provided return address.

                                    Deep Dive into the Generated Code
                                    Now that we understand the basic flow, let us analyze the generated assembly code. The generated code
                                    examines the discriminator and then accesses the fields corresponding to selected variants. It doubles the
                                    individual fields associated with the variant and returns the enum with doubled values from the function.
                                    Additionally, the function copies the discriminator field to the returned enum.
                                    In the generated assembly, you will notice that the processing of Number::Complex occurs using vector
                                    instructions. These instructions simultaneously operate on the real and imaginary fields.
                                      •   Input parameters:
                                            –       rdi: The caller specified address where the called function should update the output
                                                 enum
                                            –       rsi: Address of the enum
                                      •   Output parameters:
                                            –       rax: Output enum address (same as rdi passed by the caller)
                                    example::double:

                                    mov       rax, rdi                   ; rax now contains the address

                                                                             ; to the return value

                                    mov        rcx, qword ptr [rsi] ;                     Extract the union discriminator

                                    test       rcx, rcx                      ;     Check if the discriminator is 0
                                                                             ; (Number::Integer)

                                    je         .LBB0_5                       ;            Jump if the discriminator is 0.

                                    cmp        ecx, 1                        ;     Check if the discriminator is 1
                                                                             ; (Number::Float).

                                    jne        .LBB0_3                       ;     Jump if discriminator is 2
                                                                             ; (Number::Complex)

                                         Number::Float match processing (discriminator is 1)

                                    movsd      xmm0, qword ptr [rsi + 8]                  ;     Move the floating-point
                                                                                          ; number in xmm0

                                    addsd      xmm0, xmm0                                 ;     Double the number

                                    movsd      qword ptr [rax + 8], xmm0                  ;     Save the number to the return value

                                    mov        qword ptr [rax], rcx                       ;     Copy the discriminator
                                                                                          ; into the return value

                                    ret                                                   ;     Return the enum address in rax

                                         Number::Integer match processing (discriminator is 0)

                                    .LBB0_5:

                                    mov        rdx, qword ptr [rsi + 8] ;                     Move the integer

                                    add        rdx, rdx                               ;       Double the number

                                    mov        qword ptr [rax + 8], rdx ;                     Write the number to the return value

                                    mov        qword ptr [rax], rcx                   ;       Write the discriminator

                                    ret                                               ;       Return the enum address in rax

                                         Number::Complex match processing (discriminator is 2)

                                    The code loads, doubles, and stores back the 64-bit real and imaginary parts using vector instructions that
                                    execute both operations in parallel.

                                    .LBB0_3:

                                    movupd     xmm0, xmmword ptr [rsi + 8] ;       Read the real and
                                                                           ; imaginary parts into xmm0

                                    addpd     xmm0, xmm0                           ;       Double the real and
                                                                                   ; imaginary parts

                                    movupd    xmmword ptr [rax + 8], xmm0 ;       Update the real and
                                                                          ; imaginary parts

                                    mov       qword ptr [rax], rcx                 ;     Set the discriminator
                                                                                   ; in the return value

                                    ret                                            ;       Return enum address in rax

                                    Using Null Pointers as Discriminators
                                    Let us focus on the Option enum from the standard library. The None variant does not have any fields. The
                                    Some variant contains type T. Here is the definition of the Option enum.

                                    pub enum Option<T> {
                                        None,
                                        Some(T),
                                    }

                                    Rust eliminates the discriminator field when an Option contains a reference type. In such cases, the
                                    Option stores a pointer to the referenced type. If the pointer is NULL, the Option is None. If the pointer is
                                    not NULL, the Option is Some. We will look at two examples to understand how this works.

                                      •     Option Wrapping a Reference Type
                                      •     Option Wrapping a Box Type

                                    Option Wrapping a Reference Type
                                    Let us look at an example where Option wraps a &u64. &u64 is a pointer to a 64-bit integer.

                                    pub fn map_to_number(option: Option<&u64>) -> u64 {
                                        match option {
                                            Some(value) => *value,
                                            None => 0,
                                        }
                                    }

                                    The generated assembly code follows. The code checks if the address in rdi is NULL. If it is NULL, the code
                                    returns 0. If it is not NULL, the code loads the value from the address and returns it.
                                      •   Input:
                                            –      rdi: Option<&u64> address
                                      •   Output:
                                            –      rax: u64 value
                                    example::map_to_number:

                                    ;    Check if the address in rdi is NULL (This corresponds to None)
                                    test    rdi, rdi

                                    ;       Jump to .LBB0_1 if the address is NULL (None)
                                    je         .LBB0_1

                                    ;      If the address is not NULL, load the value from the address in rax
                                    mov       rax, qword ptr [rdi]

                                    ;      Return the value in rax
                                    ret

                                    .LBB0_1:

                                    ;      The address is NULL (None), return 0
                                    xor       eax, eax

                                    ;      Return the value in rax
                                    ret

                                    Option Wrapping a Box Type
                                    Consider the Option<Box<i32>> type, where Box<i32> represents a pointer to a 32-bit integer allocated
                                    on the heap. We will observe how the Box pointer functions as a discriminator to ascertain whether the
                                    Option is None or Some.

                                    The is_none function accepts an Option<Box<i32>> as input and returns true if the input is None and
                                    false otherwise. In this scenario, the function invokes the is_none method for Option.

                                    pub fn is_none(input: Option<Box<i32>>) -> bool {
                                        input.is_none()
                                    }

                                    The following flowchart illustrates the generated assembly for the is_none function. The function checks if
                                    the input is NULL. If it is NULL, the function returns true. The function deallocates the memory and returns
                                    false if it is not NULL.

                                    to note here is that the sete instruction sets the return value to true or false. The sete instruction sets

                                        • Input:
                                            –      rdi: Option<Box<i32>>

                                    example::is_none:
                                    push    rbx
                                    mov     rbx, rdi

                                    ;    This operation tests if the pointer is NULL.
                                    test    rdi, rdi

                                       If the result of the test operation was zero (NULL, indicating None), jump to .LBB1_2, skipping the
                                    dealloc part as there is no memory to deallocate.

                                    je            .LBB1_2

                                       Execute the following block if the pointer is not NULL (indicating Some). The code deallocates the

                                    ; Size to deallocate: 4 bytes (size of i32).
                                    mov     esi, 4

                                    ; Alignment to use: 4 bytes (alignment of i32).
                                    mov     edx, 4

                                    ; Pointer to deallocate: The Box<i32> pointer is stored in rbx.
                                    mov     rdi, rbx

                                    ;    Call the dealloc function to free the memory.
                                    call    qword ptr [rip + __rust_dealloc@GOTPCREL]

                                    sete     al

                                    pop           rbx

                                    ;             Return from the function. The return value is in the rax register,

                                    ; or more specifically, its lowest byte al.
                                    ret

                                    Discriminator Size in a Small Enum
                                    Consider the following example. The enum Point has two variants: Spherical and Cartesian. Note the
                                    type aliases we have defined for the fields. The enum implements the extract_cartesian and
                                    extract_spherical functions that return the fields of the enum variants. This section will look at the
                                    code generated for the extract_cartesian function.

                                    We will compare the code for extract_cartesian and extract_spherical functions when we
                                    experiment with different type aliases that define the fields of Point.

                                    type Coord = i8;
                                    type Distance = i8;
                                    type Angle = i8;

                                    pub enum Point {
                                        Spherical {
                                            r: Distance,
                                            theta: Angle,
                                            phi: Angle,
                                        },
                                        Cartesian {
                                            x: Coord,
                                            y: Coord,
                                            z: Coord,
                                        },
                                    }

                                    impl Point {
                                        pub fn extract_cartesian(&self) -> Option<(Coord, Coord, Coord)> {
                                            if let Point::Cartesian { x, y, z } = self {
                                                Some((*x, *y, *z))
                                            } else {
                                                None
                                            }
                                        }

                                         pub fn extract_spherical(&self) -> Option<(Distance, Angle, Angle)> {
                                             if let Point::Spherical { r, theta, phi } = self {
                                                 Some((*r, *theta, *phi))
                                             } else {
                                                 None
                                             }
                                         }
                                    }

                                    There are only 3 bytes of data in the Spherical or Cartesian variants. The enum discriminator is 1 byte.
                                    The total size of the enum is 4 bytes. The layout of the enum follows.

                                                                   Byte offset Spherical         Cartesian
                                                                   0           Discriminator (0) Discriminator (1)
                                                                   1           r                 x

                                                                  Byte offset Spherical            Cartesian
                                                                  2           theta                y
                                                                  3           phi                  z

                                    The code generated for the extract_cartesian function follows. From the code, we can infer that the
                                    first byte of the enum stores the discriminator.
                                      •   Input:
                                            –      rdi: &self
                                      •   Output:
                                            –      rax: Option<(Coord, Coord, Coord)>
                                    example::Point::extract_cartesian:

                                    ;     If enum discriminator in rdi is 0 => Spherical variant.
                                    ; If it is 1 => Cartesian variant
                                    cmp      byte ptr [rdi], 0
                                    je       .LBB0_1              ; Jump if equal, i.e., Spherical variant.

                                    ; If here, the variant is Cartesian, and we are extracting x, y, and z.

                                    movzx       eax, byte ptr [rdi + 1] ;             Load x into eax.
                                    movzx       ecx, byte ptr [rdi + 2] ;             Load y into ecx.
                                    movzx       edx, byte ptr [rdi + 3] ;             Load z into edx.

                                        Combine the enum discriminator, x, y, and z into one value in eax. Since the Intel architecture follows
                                    the little-endian format, it reverses the contents of registers to align with the Rust enum layout. The
                                    generated code stores the discriminator in the lowest byte of the 32-bit register and places the x, y, and z
                                    values in the next three bytes of the register in reverse order.

                                    shl         edx, 24                        ;           Shift z 24 places left.
                                    shl         ecx, 16                        ;        Shift y 16 places left.
                                    shl         eax, 8                         ;      Shift x 8 places left.

                                    or          eax, ecx                       ;      Combine shifted y into eax.
                                    add         eax, edx                       ;      Add shifted z into eax.

                                    ;        Increment eax by 1 to set the discriminator to 1 (Some).
                                    inc         eax

                                    ret ;         eax holds the return value for Some((x, y, z)).

                                          Handling the None variant is straightforward. The code sets eax to 0 and returns.

                                    .LBB0_1:

                                    xor         eax, eax                 ;      Zero out eax, representing None in Rust.

                                    ret                                  ;      Return, eax holds the return value for None.

                                        Key Takeaways
                                    •    Enums in Rust resemble unions in C, but they are safer because Rust enums maintain knowledge of
                                         the currently stored variant. Rust achieves this by adding a discriminator field to the enum.
                                    •    The size of the enum depends upon the largest variant. Our experiments with the Point enum
                                         demonstrate this.
                                    •    The size of the discriminator depends upon the range of variants in the enum. However, in most
                                         scenarios, the alignment requirements dictate the size of the discriminator.
                                    •    The generated assembly code for enum matching branches based on the discriminator and then
                                         processes the fields of the variant.
                                    •    The Option enum that wraps a reference type can take advantage of the fact that in Rust references
                                         are non-nullable. If the reference is NULL, then the enum is None. Otherwise, the enum is Some and
                                         the reference points to the value stored in the enum. No discriminator is needed in such cases. We
                                         saw this in the Using Null Pointers as Discriminators section.
