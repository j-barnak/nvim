                                    generate. We will look at functions that work with immutable values and mutable references. We will also

                                         Getting Started with Assembly
                                    In this introductory chapter, we will introduce assembly code. If you are new to assembly, don't worry. We
                                    will use comments to help simplify and clarify the code. Additionally, we employ intuitive symbols to
                                    improve understanding of assembly operations and values. For example,        represents a load operation,
                                    and      indicates a store operation.

                                    In the assembly code, we will encounter registers such as rax, rdi, rsi, xmm0, and ymm0. The compiler uses
                                    these registers to pass parameters and return values. In the next chapter, we will learn more about these
                                    registers and briefly tour the x86-64 assembly language.
                                    As part of our learning process, we will utilize Compiler Explorer links like
                                    https://godbolt.org/z/xahcT9oqc to understand the generated assembly better. Visit this link for examples
                                    in this chapter. In the Compiler Explorer window, the left pane contains the Rust code, while the right pane
                                    displays the generated assembly code with instruction opcodes and optional operands. Hovering over an
                                    opcode will describe the instruction, which is valuable for understanding the instruction and its context in
                                    the generated code.

                                        •   The compiler uses registers to pass parameters and return values. The rdi register passes the num
                                            parameter, and the rax register returns the value.
                                        •   The compiler uses the lea instruction to perform the addition. It seems odd to use lea, as typically,
                                            one uses this instruction to calculate addresses. However, adding a constant to a register is more
                                            efficient than the add instruction.

                                    Passing a Mutable Reference to an Integer
                                    Let us look at a function that increments the passed number by 1. The caller passes a mutable reference to a
                                    number.

                                    pub fn increment_i64_mut(num: &mut i64) {
                                        *num += 1;
                                    }

                                    Now, let us look at the generated assembly code.

                                        •     Input: rdi = address of num
                                            –    Side effect: The function increments the value at the address in rdi by 1.
                                    example::increment_i64_mut:

                                    ;       Fetch num from the address in rdi
                                    ;       Increment it by 1
                                    ;       Store the result back to the i64 at the address contained in rdi.

                                    Incrementing a Float
                                    Now, let us repeat the same exercises with floating-point numbers.

                                    Passing Float by Value
                                    Here is a simple function that returns the passed argument after adding 1.0. The function takes a floating-
                                    point number as input and returns a floating-point number as output.

                                    pub fn increment_f64(num: f64) -> f64 {
                                        num + 1.0
                                    }

                                    The assembly for the floating-point version of the function is more complex than the integer version.

                                      •      Input: xmm0 = num
                                      •      Output: xmm0 = num + 1.0
                                    .LCPI2_0:

                                    .quad     0x3ff0000000000000 ; IEEE 754 double float 1.0

                                    example::increment_f64:

                                    ;     Load 1.0 using an address relative to the instruction pointer
                                    ; and add it to the value in xmm0
                                    addsd    xmm0, qword ptr [rip + .LCPI2_0]

                                    ;    Return to the caller
                                    ; The return value is in xmm0
                                    ret

                                    Unlike the integer version, the floating-point version requires memory access to load the constant 1.0 into
                                    a register before adding it to the value in xmm0. The code loads the constant using an address relative to the
                                    instruction pointer (more on this in the next chapter). The compiler represents the constant in the IEEE
                                    754 double-precision floating-point format. Finally, the function returns the result in the xmm0 register.

                                        Learn More: IEEE 754 Double-Precision Floating-Point Format
                                    The IEEE 754 double-precision floating-point format is a binary format that represents floating-point
                                    numbers. It is 64 bits wide and organized as follows:

                                     Sign bit Exponent bits Significand bits
                                     1 bit    11 bits       52 bits

                                    The sign bit determines whether the number is positive or negative, with 0 indicating positive and 1
                                    indicating negative.
                                    The exponent bits represent the floating-point number’s biased exponent. Subtracting the bias value 1023
                                    from the biased exponent yields the actual exponent. This bias adjustment permits a range of exponents
                                    from -1022 to 1023.
                                    The significand bits represent the fractional part of the floating-point number. The first bit is an implicit
                                    leading 1 (not stored in memory). The remaining 52 bits represent the fractional part of the significand.

                                    Passing a Mutable Reference to a Float
                                    Let us look at a function that increments the passed floating-point number by 1. The caller passes a mutable
                                    reference to a f64.

                                    pub fn increment_f64_mut(num: &mut f64) {
                                        *num += 1.0;
                                    }

                                    Here is the assembly generated for the function.

                                      •      Input: rdi = address of num
                                    .LCPI3_0:
                                    .quad   0x3ff0000000000000           ; IEEE 754 double float 1.0

                                    example::increment_f64_mut:

                                    ;     Load the value from the address in rdi into xmm0.
                                    movsd    xmm0, qword ptr [rdi]

                                    ;     Load the constant 1.0 and add the fetched value to xmm0.
                                    addsd    xmm0, qword ptr [rip + .LCPI3_0]

                                    ;     Store the result back to the address pointed to by rdi.
                                    movsd    qword ptr [rdi], xmm0

                                    ;       Return to the caller.
                                    ret

                                    The floating-point version of the function is less compact than its integer counterpart. The first instruction
                                    loads the value from the address in rdi into xmm0. The second instruction loads the constant 1.0 and adds
                                    it to the value in xmm0. The third instruction stores the result in xmm0 back to the address pointed by rdi.

                                    Working with Tuples
                                    What Is a Tuple?
                                    In Rust, a tuple is a collection that can hold multiple values of various types. The individual values within a
                                    tuple are known as elements. Accessing these elements is typically done via pattern matching. An example
                                    demonstrates how to construct tuples and retrieve their elements.

                                    let alice = ("Alice", 30, " ");      // Security researcher Alice
                                    let bob = ("Bob", 35, " ");          // Security researcher Bob
                                    let (name, age, mood) = alice;        // Pattern matching on the tuple
                                    println!("{} is {} years old and is feeling {}.", name, age, mood);
                                    println!("{} is {} years old and is feeling {}.", bob.0, bob.1, bob.2);

                                    A Tuple of Floats
                                    Now, let us look at a function that takes a tuple of floats as input and returns a tuple of floats as output.

                                    pub fn multiply_f32_space_time_tuple(
                                        (x, y, z, t): (f32, f32, f32, f32)
                                    ) -> (f32, f32, f32, f32){
                                        (x*2.0, y*3.0, z*4.0, t*5.0)
                                    }

                                    The memory representation of the tuple follows. The compiler organizes the tuple as a struct with four
                                    fields. Each field is a 32-bit float.

                                    Now, let us look at the assembly generated for the function. The tables have now turned, and the code for
                                    manipulating floating-point tuples is surprisingly more compact than that for the integer case.
                                    The compiler has used SIMD (Single Instruction Multiple Data) instructions to perform four parallel
                                    operations per instruction. A single movups instruction copies all four values from the source tuple to the
                                    xmm0 register. The compiler uses the mulps instruction to multiply the values in xmm0 with the constants
                                    2.0, 3.0, 4.0, and 5.0. The movups instruction copies the values from xmm0 to the returned tuple. Finally,
                                    the function returns to the caller with the address of the returned tuple in rax.

                                      •       Input:
                                            –    rdi = address of the returned tuple
                                            –    rsi = address of source tuple
                                      •       Output:
                                            –    rax = address of the returned tuple

                                    .long      0x40000000 ; IEEE 754 single float 2.0
                                    .long      0x40400000 ; IEEE 754 single float 3.0
                                    .long      0x40800000 ; IEEE 754 single float 4.0
                                    .long      0x40a00000 ; IEEE 754 single float 5.0

                                    ;     Copy the address of the tuple to be returned from rdi to rax
                                    ; This is the return value
                                    mov      rax, rdi

                                         Learn More: Single Instruction Multiple Data (SIMD)
                                    SIMD is a technique that allows a single instruction to perform the same operation on multiple data
                                    elements. A vector register stores the data elements. The vector register is a special-purpose register that
                                    can store multiple data elements. The size of the vector register is dependent on the architecture. For
                                    example, the xmm0 register is 128-bit wide and can hold four 32-bit floats. The ymm0 register is 256 bits
                                    wide and can store eight 32-bit floats. The zmm0 register is 512 bits wide and can store sixteen 32-bit floats.

                                    Apply the settings in the edit box on the top right of the Compiler Explorer window.

                                            Key Takeaways
                                        •    The Rust compiler generates efficient assembly code. The compiler uses different approaches to
                                             optimize integer and floating-point operations.

                                        •    The compiler uses additions, shifts, and address arithmetic instructions (lea) to perform simple
                                             integer multiplications. If larger constants are involved, the compiler uses SIMD instructions to
                                             perform integer multiplications.

                                        •    The generated code will utilize SIMD instructions to enhance performance, as SIMD instructions
                                             enable the parallel execution of multiple operations.

                                        •    Rust represents tuples as structs with multiple fields stored in contiguous memory locations.

                                        •    When returning a large structure or tuple, the compiler passes the address of the returned
                                             structure to the function using a hidden parameter. This approach avoids creating temporary
                                             structures on the stack. Also, note that the called function copies the address of the returned
                                             structure to the rax register as the return value to comply with the x86-64 calling convention.
