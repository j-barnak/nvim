                                    Array Slices
                                    In Rust, array slices provide a view into a contiguous sequence of elements, such as arrays, vectors, or
                                    strings, without taking ownership. This feature is handy for referencing a portion of a data structure
                                    without copying the data.
                                    Slices are dynamically sized, meaning their size is determined at runtime. Each slice is represented by a
                                    two-word object in memory: the first word is a pointer to the data, and the second is the slice’s length. This
                                    design makes slices lightweight and efficient to pass around, as they simply point to existing data rather
                                    than own it.
                                    By leveraging borrowed references, slices adhere to Rust’s strict borrowing rules, which helps maintain
                                    memory safety and concurrency guarantees.

                                    Array Slice Pattern Matching Example
                                    The following code shows a function that takes an array slice as input and pattern matches on the slice to
                                    return the last element of the slice if the slice has a length of 2, 3, or 4 and matches the specified pattern. In
                                    all other cases, the function returns a 0.

                                    pub fn process_array_slice(input: &[i32]) -> i32{
                                        match input {
                                            [42, a] => *a,
                                            [43, 44, a] => *a,
                                            [45, 46, 47, a] => *a,
                                            [..] => 0,
                                        }
                                    }

                                    The input parameter passed to process_array_slice is an array slice. The following diagram shows an
                                    example of an array slice. The first word of the slice is a pointer to the data, and the second word is the
                                    length of the slice.

                                    Array Slice Pattern-Matching Assembly Code

                                    register. The comparisons assess the slice’s length and elements to match the patterns in the Rust code. The
                                    matching legs set an offset in the ecx register to identify the slice entry to return. This offset in ecx ensures
                                    the return of the correct slice element in the matched pattern.

                                    Experiment with Compiler Explorer (https://godbolt.org/z/449fr6Tqs) to see how the generated assembly

                                      •     Two Match Patterns of the Same Length
                                      •     Matching the Tail of a Slice
                                    We will also compare the code generated using pattern matching with conventional if-else checks.

                                    Two Match Patterns of the Same Length
                                    Change the Rust code to match two patterns of the same length. The [43, 44, 48, a] and [43, 44,
                                    47, _] patterns match the same length of array slice with the same first two elements. You will see that
                                    the compiler generates efficient code to check for the first two elements and then checks the third element
                                    to determine which pattern to match.

                                    pub fn process_array_slice(input: &[i32]) -> i32{
                                        match input {
                                            [42, a] => *a,
                                            [43, 44, 48, a] => *a,
                                            [43, 44, 47, _] => 42,
                                            [..] => 0,
                                        }
                                    }

                                    Matching the Tail of a Slice
                                    Change the Rust code to match the tail of a slice. We will match the following patterns:
                                      •     [4, .., 2] pattern matches on a slice that starts with a 4 and ends with a 2.
                                      •     [.., 9, 7] pattern matches on a slice that ends with a 9 and a 7.
                                      •     [..] pattern matches on any other slice.

                                    Here is the Rust code for the experiment.

                                    pub fn process_array_slice(input: &[i32]) -> i32 {
                                        match input {
                                            [4, .., 2] => 42,
                                            [.., 9, 7] => 97,
                                            [..] => 0,
                                        }
                                    }

                                    compiler generates efficient code to check the first and last elements of the slice to determine which
                                    pattern to match.
                                    The assembly code generated in this experiment differs from the assembly code we saw earlier. The key
                                    differences are:
                                      •    Pattern matching on the tail of a slice requires the compiler to generate code to calculate the
                                           address of the last element of the slice.
                                      •    The compiler reorders the code to parallelize memory moves and branch execution.
                                    The input and output registers for the function are:

                                      •       Input:
                                            –    rdi =     array slice data address
                                            –    rsi =     array slice length
                                      •       Output:
                                            –    rax = return value

                                    ;      Initialize return value to 0
                                    xor       eax, eax

                                    ;      Compare the slice length with 2
                                    cmp       rsi, 2

                                    ;      If the slice length is less than 2, take the default case and return 0
                                    jb        .LBB0_5

                                    ;      Compare the first element of the slice with 4
                                    cmp       dword ptr [rdi], 4

                                    ;     Get the last element of the slice.
                                    ; Last_element_address = slice_data_address + (slice_length-1) * element_size
                                    mov      ecx, dword ptr [rdi + 4*rsi - 4]

                                    ;      If the first element is not 4, move on to check the next pattern
                                    jne       .LBB0_3

                                    ; Move 42 into the return value register in case the next pattern match
                                    ; succeeds.
                                    mov     eax, 42

                                    ;      Compare the last element of the slice with 2
                                    cmp       ecx, 2

                                    ;      If the last element is not 2, move on to check the next pattern
                                    jne       .LBB0_3

                                    .LBB0_5:

                                    ;      Return the return value in rax
                                    ret

                                    .LBB0_3:
                                    ;     Set the return value to 0
                                    mov      eax, 0

                                    ;       Compare the last element of the slice with 7
                                    cmp        ecx, 7

                                    ;       If the last element is not 7, return 0 (default case)
                                    jne        .LBB0_5

                                    ;       Set ecx to 0
                                    xor        ecx, ecx

                                    ;       Compare the second to last element of the slice with 9
                                    cmp        dword ptr [rdi + 4*rsi - 8], 9

                                    ; Load the value 97 into the return value register in anticipation
                                    ; of finding a match for the penultimate element.
                                    mov     eax, 97

                                    ;     Conditionally return 97 if the second to the last element
                                    ; is 9 else move ecx into eax and return 0.
                                    cmovne eax, ecx

                                    ;       Return the return value in rax
                                    ret

                                            Key Takeaways
                                        •    The array slice contains a pointer to the slice data and the length of the slice. In our examples, the
                                             compiler passes the pointer to the slice data and slice length via two registers.

                                        •    Rust offers a robust array slice pattern matching mechanism. With it, you can match various aspects
                                             of a slice: its length, first and last elements, and even its tail. This powerful feature ensures
                                             developers can efficiently handle different slice scenarios in their pattern-matching constructs.

                                        •    The compiler generates efficient code for array slice pattern matching. It minimizes the
                                             comparisons required to match a pattern. Array slice pattern matching is a zero-cost abstraction.
                                             We saw this when we compared the assembly code generated with and without pattern matching.

                                        •    Pattern matching can target the tail of a slice, necessitating the compiler to generate code that
                                             calculates the address of the slice’s last element using its length. We saw this in the experiment
                                             where we matched on the tail of a slice.
