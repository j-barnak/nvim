
                                                            Chapter 16
                                                   Optimizing Recursive Functions

                                    This chapter will examine how the Rust compiler optimizes tail call recursive functions by mapping them to
                                    loops. Additionally, we will explore how the compiler eliminates the enum discriminator when it can infer
                                    it.

                                    Tree Structure
                                    We begin by defining a tree structure in Rust, characterized as an enum with two variants: Leaf and Node.
                                    The Leaf variant contains a value of type T, while the Node variant contains a value of type T, a left child of
                                    type Box<Tree<T>>, and a right child of type Box<Tree<T>>.

                                    We also define a sum function that sums the values of all the nodes in the tree. The sum function is a
                                    recursive function that calls itself for the left and right subtrees of a Node variant. We will examine the code
                                    generated for the sum function and see how the Rust compiler optimizes some recursive calls into loops.

                                    pub enum Tree<T> {
                                        Node(T, Box<Tree<T>>, Box<Tree<T>>),
                                        Leaf(T),
                                    }
                                    use Tree::{Leaf, Node};

                                    pub fn sum(tree: &Tree<u64>) -> u64 {
                                        match tree {
                                            Leaf(n) => *n,
                                            Node(n, left, right) => *n + sum(left) + sum(right),
                                        }
                                    }

                                    Tree Representation in Memory
                                    As discussed in the “Deep Dive into Enums: Layout and Patterns” chapter,” Rust usually includes a
                                    discriminator in the memory representation of an enum to keep track of the currently stored variant.
                                    Hence, the Tree enum should also contain a discriminator to track its stored variant. If a discriminator
                                    were present, the memory representation of the Tree object would look like the following diagram.

                                    The generated tree structure is simpler than the preceding diagram. Rust optimizes the code by inferring
                                    the variant from the context and eliminating the need for a discriminator.
                                    In the Tree enum, the Node variant’s right field, a Box<Tree<T>>, acts as a pointer to another Tree
                                    object. The compiler uses this field’s presence or absence to determine the Tree object’s variant:

                                       •     A non-null right field indicates that the Tree object is a Node.
                                       •     A null right field signifies that the Tree object is a Leaf.

                                    Thus, the right field functions as a discriminator and a pointer to the next Tree object.

                                    Flowchart of Partially Tail Call Optimized sum Function
                                    The following flowchart will help you understand the generated assembly code. The Rust compiler
                                    optimizes away the recursive call to the sum function for the right of the Node variant. The sum function is
                                    tail-recursive for the sum (right) call.

                                    Converting the recursive call to a loop is a two-step process. Here is how the compiler thinks about this:
                                      1.   The function’s last call, sum(right), mirrors the structure of the calling function sum(tree). The
                                           compiler can reduce overhead by eliminating the stack frame for this call.
                                      2.   The sum(right) call, targeted for elimination by the compiler, is a recursive call to the same
                                           function. The compiler can transform this tail call into a loop, enhancing performance and
                                           minimizing stack usage.

                                    Annotated Assembly Code for Transforming Recursive Tail Calls
                                    into Loops
                                    Now, let us look at the generated assembly code. Review the memory representation of the Tree object and
                                    the flowchart of the sum function to understand the assembly code better.

                                          •      Input: rdi: &Tree<u64>

                                          •      Output: rax: u64

                                    example::sum:

                                    push        r15                            ; save callee-saved registers
                                    push        r14
                                    push        rbx
                                    mov         r14, rdi                        ; r14 = tree

                                        Verify whether the present entry is a Leaf by examining the right field (offset 16) of the Node for a null
                                    value.

                                    cmp         qword ptr [rdi + 16], 0         ; if tree is a leaf Node
                                    je          .LBB0_1                         ; then return the value

                                    (       ,     ) Since the Tree entry’s right field is not null, we infer that the entry represents a Node.
                                    Therefore, we must process this Node’s left and right fields. To calculate the total sum, add the Node’s value
                                    to the sums of its left and right subtrees and return this result.

                                    xor         ebx, ebx                 ; rbx = 0
                                    mov         r15, qword ptr [rip + example::sum@GOTPCREL] ; r15 = sum

                                       The compiler has converted the right-side recursive call to the sum function into a loop. The loop starts
                                    here and continues until the right field of the Node is a Leaf. The left-side Node visits are recursive.

                                                    sum (right) Loop starts.

                                    .LBB0_3:

                                    mov         rdi, qword ptr [r14 + 8]            ; rdi = left
                                    add         rbx, qword ptr [r14]                ; rbx += node.n

                                             Recursive call for the left side of the Node.

                                    call        r15                                 ; call sum(left)

                                    mov         r14, qword ptr [r14 + 16] ; r14 = right
                                    add         rbx, rax                  ; rbx += sum(left)

                                    cmp         qword ptr [r14 + 16], 0             ; check if right is a Leaf
                                    jne         .LBB0_3                             ; if the right side is a Node, continue

                                                    sum(right) Loop back to the top.

                                    jmp         .LBB0_4                             ; the right side is a Leaf - proceed to
                                                                                    ; return after adding the value

                                          Leaf Node: Return the value of the Leaf node.

                                    .LBB0_1:

                                    xor         ebx, ebx                            ; Set rbx to 0
                                                                                    ; This way, the addition in the next
                                                                                    ; instruction will add to 0.

                                       Return the value from the function. Adding the final node.n is necessary to incorporate the n value
                                    corresponding to the right leaf Node that terminates the loop.

                                    .LBB0_4:

                                    add         rbx, qword ptr [r14]                ; rbx += node.n (right side Leaf)
                                    mov         rax, rbx                            ; rax = rbx

                                    pop         rbx                                 ; restore callee-saved registers
                                    pop         r14
                                    pop         r15
                                    ret

                                           Experiment: TCO for factorial and fibonacci Functions
                                    You can experiment with the code in Compiler Explorer (https://godbolt.org/z/zG46WvTjz). You can also
                                    add the following recursive functions to Compiler Explorer code editor to see how the compiler optimizes
                                    recursive calls in different scenarios.
                                      •      A version of the sum function that uses an accumulator to sum the values of all the nodes in the tree.
                                             The recursive call to sum_acc is a tail call. Compare this with the sum function we saw earlier.

                                             pub fn sum_acc(tree: &Tree<u64>, acc: u64) -> u64 {
                                                 match tree {
                                                     Leaf(n) => *n + acc,
                                                     Node(n, left, right) => sum_acc(right, sum_acc(left, *n)),
                                                 }
                                             }

                                       •     The compiler optimizes the recursive factorial call into a loop.

                                             pub fn factorial(n: u64) -> u64 {
                                                 if n == 0 {
                                                     1
                                                 } else {
                                                     n * factorial(n - 1)
                                                 }
                                             }

                                       •     The compiler optimizes away one of the two recursive calls to the fibonacci function. The
                                             situation here is like the sum function we saw earlier. The compiler optimizes the recursive call to
                                             fibonacci(n - 2) to a loop but does not optimize the recursive call to fibonacci(n - 1) to a
                                             loop.

                                             pub fn fibonacci(n: u32) -> u32 {
                                                 if n == 0 {
                                                     return 0;
                                                 } else if n == 1 {
                                                     return 1;
                                                 } else {
                                                     return fibonacci(n - 1) + fibonacci(n - 2);
                                                 }
                                             }

                                           Key Takeaways
                                       •     The Rust compiler only converts recursive calls into loops when they are tail calls.
                                                –     In the sum function, the compiler optimized the tail call sum(right) into a loop but did not
                                                      optimize the sum(left) call.
                                                –     For the fibonacci function, the compiler converted the fibonacci(n - 2) call into a
                                                      loop, but it did not do the same for the fibonacci(n - 1) call.
                                                –     The factorial function, being tail recursive, saw its factorial(n - 1) call eliminated,
                                                      with the factorial calculation transformed into a loop.
                                       •     The Rust compiler eliminates enum discriminators when it can deduce the enum variant from the
                                             context. This elimination was evident in the Tree example; specifically, the Node variant’s right
                                             field allowed the compiler to deduce the Tree object’s variant.
