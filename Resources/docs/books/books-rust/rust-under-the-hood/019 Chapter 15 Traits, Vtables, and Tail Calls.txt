                                    Trait Object Fat Pointer and the Vtable
                                    As the previous chapter covers, the Rust compiler uses fat pointers to realize trait objects. To revisit this
                                    concept, let us delve into the fat pointer associated with the Draw trait object:

                                    The first pointer points to the data of the concrete type that implements the Draw trait, and the second
                                    pointer points to the vtable (virtual table) for the concrete type. The vtable data structure stores
                                    pointers for concrete type methods, destructor, and alignment and size information. The compiler needs
                                    this information to free the memory allocated for the trait object when it goes out of scope.

                                    Dynamic Dispatch and Tail Call Optimization
                                    The generated assembly code for the draw_dynamic function includes a jump to the vtable address of the
                                    draw function rather than a call. This optimization, known as Tail Call Optimization (TCO), eliminates
                                    creating a new stack frame and return address for the call chain’s last (tail) function.
                                    In this case, the draw function returns directly to the caller of draw_dynamic using the return address that
                                    was already present on the stack. This optimization is possible because the rdi register already points to
                                    the concrete object that implements the Draw trait, satisfying the self-parameter requirement for the
                                    draw function.

                                    Vtable Method Dispatch and Tail Calls
                                    The generated assembly code for the draw_and_report_area_dynamic function is more complex than
                                    draw_dynamic. It first obtains the addresses of the draw and area methods from the vtable using offsets
                                    of 32 and 24, respectively. It then calls the draw method using a call instruction, which creates a new
                                    stack frame and return address.
                                    The code transfers control to the area method using a jump instruction. The compiler can tail call optimize
                                    the area method as it is the last function call in the body of draw_and_report_area_dynamic. The
                                    compiler optimizes away the call by replacing it with a jump, eliminating the need for a new stack frame
                                    and return address. The return value of the area method is also the return value of
                                    draw_and_report_area_dynamic, so the optimization has no impact on the correctness of the code.

                                           Key Takeaways
                                       •     The Rust compiler uses Tail Call Optimization (TCO) to optimize away the last function call in a
                                             function body. This optimization eliminates creating a new stack frame and return address for the
                                             last (tail) function call in a call chain.
                                       •     Reordering functions to prepare the return value in the last called function might improve
                                             performance as tail call optimization will reduce the overhead of a function call.
                                       •     Trait objects are represented as a pair of pointers (aka fat pointer). The first pointer points to the
                                             data, and the second points to the vtable.
                                       •     The compiler typically uses two registers to pass a trait object’s and its vtable addresses.
                                       •     The compiler stores the Vtables in the read-only data section of the binary. It saves the following
                                             information in the vtable:
                                                –     Size and alignment of the concrete type.
                                                –     The address of the destructor.
                                                –     The addresses of the functions that implement the methods of the trait.
                                       •     When a trait object wrapped in a Box goes out of scope, the compiler frees the memory allocated for
                                             the trait object by calling the destructor and the __rust_dealloc function. It obtains the
                                             destructor’s address and the concrete type’s size from the vtable.
                                       •     The compiler can inline functions and remove dynamic dispatch when the type of the trait object is
                                             known at compile time.
