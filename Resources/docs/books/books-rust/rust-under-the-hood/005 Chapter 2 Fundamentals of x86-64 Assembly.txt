                                    x86-64 Registers
                                    General-Purpose Registers
                                    Programs use registers for general data manipulation, storing integers, pointers, and memory addresses.
                                    The following table shows the general-purpose registers available with their typical usage:
                                      •    rax: Accumulator
                                      •    rbx: Base index (for use with arrays)
                                      •    rcx: Counter for loops
                                      •    rdx: Extended precision accumulator (pairs with rax for 128-bit operations)
                                      •    rsi: Source index for string operations
                                      •    rdi: Destination index for string operations
                                      •    r8 to r15: Additional general-purpose registers

                                    Stack Registers
                                    The compiler uses these registers for stack operations:
                                      •    rsp: Stack pointer
                                      •    rbp: Base pointer (often points to a fixed position within the stack)

                                    Instruction Pointer

                                    You will encounter rip-relative addressing in the assembly code. For instance, the instruction lea rcx,
                                    [rip + .LJTI57_0] loads a rip-relative address of the label .LJTI57_0 into rcx. Using rip relative
                                    addressing aims to make the code position-independent, which is necessary for dynamic linking.

                                    Floating-Point and SIMD Registers
                                         •   xmm0 to xmm15: Used for floating point calculations and Single Instruction Multiple Data (SIMD)
                                             operations. These registers are 128 bits wide and store four single-precision floating-point values
                                             or two double-precision floating-point values.
                                         •   ymm0 to ymm15: Used for floating point calculations and SIMD operations. These registers are 256
                                             bits wide and can store eight single-precision floating-point values or four double-precision
                                             floating-point values. You can access the lower 128 bits of these registers as xmm0 to xmm15.

                                    x86-64 Calling Convention
                                    The x86-64 calling convention dictates the methods for calling functions and passing arguments to them.
                                    Its importance lies in determining the generation of assembly code for function calls. It covers the
                                    following:
                                      •     Registers to use for passing arguments to functions.
                                      •     Registers to use for returning values from functions.
                                      •     The distinction between caller-saved and callee-saved registers.
                                      •     The usage of the stack in passing arguments and returning values.
                                    Note that the calling convention is specific to the platform and the compiler. The assembly code presented in
                                    this book adheres to the calling convention used by the Rust compiler on x86-64 Linux (System V AMD64 ABI).

                                    Registers for Passing Arguments
                                    The calling convention specifies the order in which registers pass arguments to functions. The selection
                                    order is important because it determines which registers to use for which arguments.
                                    The following table shows the register selection order for several types of arguments:

                                     Argument Type                       Register selection order
                                     Integer types and pointers          rdi, rsi, rdx, rcx, r8, r9
                                     Floating-point types                xmm0, xmm1, xmm2, xmm3, xmm4, xmm5, xmm6, xmm7

                                    The generated code pushes arguments that do not fit into the available registers onto the stack in reverse
                                    order (right-to-left).
                                    The rdi register also serves as a hidden pointer to return larger values from functions. In such cases, the
                                    caller is responsible for allocating space for the return value and passing the address of the allocated space
                                    in rdi. The callee then stores the return value at the address pointed to by rdi. In such cases, rsi receives
                                    the first argument instead of rdi.

                                    Registers for Returning Values
                                    The calling convention specifies the registers used for returning values from functions. The rules for
                                    selecting the registers are as follows:
                                      •     The called function returns integer types and pointers in rax, with rdx holding the high bits for
                                            128-bit wide return values, such as a pair of 64-bit values.
                                      •     The called function returns floating-point values in xmm0 and in xmm1 if necessary.

                                    For larger return values, the caller uses a hidden pointer as an extra argument to the function. It passes this
                                    pointer in rdi and stores the return value at the address the pointer indicates.

                                    Caller vs. Callee Saved Registers
                                    The calling convention dictates which registers the caller saves and which the callee saves. This distinction
                                    is crucial, as it specifies which registers need saving and restoring during function calls. The following table
                                    lists the caller-saved and callee-saved registers:

                                     Register                             Type        Description
                                     rax, rcx, rdx, rsi, rdi,             Caller-     The calling function must save these registers to preserve
                                     r8, r9, r10, r11, xmm0-15            saved       their values across a function call.

                                     Register                                Type          Description
                                     rbx, rbp, rsp, r12, r13,                Callee-       If a called function (callee) wants to use these registers, it
                                     r14, r15                                saved         must save and restore the original values before
                                                                                           returning.

                                    Function Prologue and Epilogue
                                    In addition to the above, the calling convention outlines the function prologue and epilogue, which execute
                                    at the beginning and end of a function call. The prologue and epilogue set up and restore the stack and
                                    registers for the function call, ensuring their return to their original state before the function returns.
                                         •   The function’s prologue prepares the stack and registers for the function’s operation. Prologue
                                             preparation might involve setting up a base pointer (rbp), saving callee-saved registers, and
                                             allocating space for local variables.
                                         •   The epilogue reverts the state to its original form before the function call. It typically restores the
                                             saved registers and resets the stack pointer (rsp) to its initial value before concluding the function.

                                    x86-64 Instruction Set
                                    The x86-64 instruction set is quite large, and it is beyond the scope of this book to cover it in detail.
                                    However, we will cover some of the most common instructions in the assembly code.

                                    mov Instruction
                                    The mov instruction transfers (or copies) data between registers, memory locations, and constant values.
                                    Although called mov, it does not actually “move” data by removing it from the source; it replicates the
                                    source data to the destination. Here are some examples of mov instructions:

                                     Instruction               Explanation
                                     mov rax, rbx              Copies the value from rbx into rax
                                     mov rax, [rbx]            Loads the value pointed to by rbx into rax
                                     mov [rcx], rdx            Stores the value in rdx into the memory location pointed to by rcx
                                     mov rax, 5                Loads the constant value 5 into rax

                                    lea Instruction
                                    The lea (Load Effective Address) instruction computes the address of a memory operand and loads that
                                    address into a register without referencing memory. In other words, it does not fetch the value stored at
                                    the address but the address itself. The following table shows some examples of lea instructions:

                                     Instruction                                  Explanation
                                     lea rax, [rbx]                               Loads the address in rbx into rax
                                     lea rax, [rbx + 4]                           Loads the address rbx + 4 into rax
                                     lea rax, [rbx + rcx*4]                       Loads the address rbx + (4 * rcx) into rax
                                     lea rax, [rbx + rcx*4 + 8]                   Loads the address rbx + (4 * rcx) + 8 into rax

                                    Note that the compiler often uses lea to perform arithmetic operations on integers. For example, the
                                    following instruction adds rbx and rcx and stores the result in rax:

                                    lea rax, [rbx + rcx]

                                    The compiler picks the lea instruction when it will be more efficient than dedicated addition and
                                    multiplication instructions. For example, the following instruction multiplies rcx by 4, adds the result to
                                    rbx, and stores the result in rax:

                                    lea rax, [rbx + rcx*4]

                                    Impacted Flags
                                    Both cmp and test can affect several flags in the rflags register.

                                      •    ZF (Zero Flag): Set if the result of the operation is zero.
                                      •    SF (Sign Flag): Set if the result of the operation is negative (based on the most significant bit).
                                      •    OF (Overflow Flag): Set if there is a signed overflow because of the operation.
                                      •    CF (Carry Flag): Set if there is an unsigned overflow because of the operation.
                                      •    PF (Parity Flag): Set if the number of set bits in the least significant byte of the result is even.

                                    Unconditional Branches
                                    Unconditional branches jump to a specific location in the code, regardless of the state of the rflags. The
                                    following table shows some of the unconditional jump instructions available in x86-64 assembly:

                                     Instruction       Explanation

                                     jmp rax           Jump to the address stored in rax
                                     call label        Pushes the address of the next instruction onto the stack and then jumps to the address
                                                       specified by label. This mechanism allows the ret instruction to know where to return.
                                     call rax          Like call label, but instead of jumping to a predefined address (label), the program
                                                       jumps to the address in the rax register after pushing the address of the next instruction
                                                       onto the stack.

                                    Stack Operations
                                    In x86-64 assembly, the stack is a fundamental data structure for many tasks, including storing local
                                    variables and saving registers. The x86-64 architecture provides several instructions for stack operations.
                                    The following table shows commonly used stack instructions:

                                     Instruction Explanation
                                     push rax The instruction pushes the value in rax onto the stack by decrementing the rsp (stack
                                                 pointer) by 8 bytes and then storing the value of rax at the new rsp address.
                                     pop rax     The instruction pops the top value from the stack into rax by loading the value pointed to
                                                 by rsp into rax and then increments the rsp by 8 bytes.
                                     pushfq      Pushes the 64-bit rflags register onto the stack.
                                     popfq          Pops the top value from the stack into the rflags register.

                                         Learn More: Aligned vs. Unaligned Instructions
                                    The SIMD instructions in the x86-64 assembly come in two flavors: aligned and unaligned. Aligned
                                    instructions require that the memory addresses of the data they operate on are multiples of the data size.
                                    For instance, a 128-bit aligned instruction requires that the memory address is a multiple of 16 bytes.
                                    Unaligned instructions, however, do not have this restriction and can operate on data at any memory
                                    address.
