                                                        Static vs. Dynamic Dispatch

                                    Traits in Rust are like interfaces in other languages. Traits permit the implementation of a standard
                                    interface for multiple types. Developers can compose their code using traits instead of concrete types.
                                    When calling a method specified by a trait, the compiler generates code to dispatch the call to the concrete
                                    method that implements the trait specification. This chapter will examine how the Rust compiler
                                    implements traits and generates code for static and dynamic dispatch.
                                    Rust supports two types of dispatch:
                                      •    Static dispatch serves as the default mode, employed when the compiler can determine the
                                           concrete type at compile time.
                                      •    Dynamic dispatch comes into play when the concrete type implementing the trait remains
                                           unknown at compile time.

                                    Example: Static vs. Dynamic Dispatch
                                    We will use the following example to illustrate the difference between static and dynamic dispatch.

                                    Dynamic dispatch
                                    The area_pair_dynamic function takes two parameters, a and b; both are dynamic trait objects of type
                                    &dyn Shape<T = f64>. The function uses trait objects without knowing the specific types that implement
                                    the Shape<T> trait. As a result, the code calls the area method on these objects through a function pointer.
                                    How does the compiler generate code for this function? We will dissect the assembly code and the vtable
                                    to understand the machinery behind dynamic dispatch.
                                    For each unique type that implements Shape<T>, the compiler generates a vtable (virtual table)
                                    containing pointers to the trait’s methods as implemented by that type. Each type has its own vtable,
                                    stored in the program’s static data section. The vtable facilitates the runtime dispatch of calls to the
                                    appropriate method.
                                    Instances of the same type share the same vtable, but distinct types have separate vtables. The vtable
                                    includes pointers to the trait method implementations specific to each type. The Rust compiler uses a fat
                                    pointer for &dyn Shape<T = f64>, a tuple containing a pointer to the data and a pointer to the vtable.

                                    The area_pair_dynamic receives a and b as fat pointers. The accompanying diagram shows the memory
                                    layout of a sample Rectangle object, which can serve as either a or b. The leftmost box represents the fat
                                    pointer, with the data pointer pointing to the Rectangle object and the vtable pointer pointing to the
                                    vtable of the Rectangle type.

                                    typically happens when a smart pointer like Box contains a trait object. If the Box gets dropped, it calls the
                                    drop function on the object. The code uses the size and alignment of the concrete type to free memory for
