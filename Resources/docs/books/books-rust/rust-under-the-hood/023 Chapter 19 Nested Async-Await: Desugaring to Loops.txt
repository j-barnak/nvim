                                            Learn More: What Is the              Pin in the Signature of the poll Method?
                                    The Pin type in Rust guarantees that the data at a particular memory location will not move and its
                                    memory will not get invalidated. This guarantee is crucial in asynchronous programming, mainly when
                                    working with Futures.

                                    The definition of the poll method is as follows:

                                    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>

                                    Note that self is wrapped in Pin as a Future might be self-referential, potentially referencing another part
                                    of itself. Moving such a future could invalidate that reference, leading to undefined behavior. The Pin
                                    wrapper prevents this by ensuring that the data inside cannot move, allowing safe referencing. Regarding
                                    the poll method, this setup effectively promises that neither the future nor anything it references will
                                    move during the poll’s duration.

                                    We now understand the high-level flow of the async code. Let us look at the generated assembly code.

                                    Input and Output Registers
                                    This assembly code, generated from a patrol closure, takes two inputs: the closure environment stored in
                                    rdi, and the task context stored in rsi. The output is stored in rax and can be Poll::Pending or
                                    Poll::Ready.

                                    environment to r14 and rbx, respectively. The code then loads the state from the closure environment and
                                    uses a jump table to determine which block of code to execute based on the state.

                                          Experiment: Executing Async Functions on .await
                                    Code
                                    Let us work with the following example in the Rust playground (https://bit.ly/3rI1Hso):

                                    use std::time::Duration;
                                    use tokio::time::sleep;

                                    async fn async_fn() {
                                        println!("Async function execution started.");
                                        sleep(Duration::from_secs(2)).await;
                                        println!("Async function execution finished.");
                                    }

                                    #[tokio::main]
                                    async fn main() {
                                        println!("Main function execution started.");
                                        let future = async_fn(); // Save the future returned by async_fn
                                        println!("Main function before awaiting the async function.");
                                        future.await; // Here we start the execution of async_fn
                                        println!("Main function execution finished.");
                                    }

                                    Run
                                    Use the RUN button to run the code (top-left button in the Rust playground). You should see the following
                                    output:

                                    Main function execution started.
                                    Main function before awaiting the async function.
                                    Async function execution started.
                                    Async function execution finished.
                                    Main function execution finished.

                                    Explanation
                                    This example demonstrates an essential aspect of Rust’s asynchronous programming model: an async
                                    function does not start executing immediately upon being called. Instead, it returns a Future, a value
                                    representing a computation that will be completed in the future.
                                    The key learning points are:
                                      •     Calling an async function returns a Future without executing the function’s body at that moment.

                                      •     The returned Future symbolizes the ongoing computation of the async function, which does not
                                            initiate until you await the Future.

                                           Key Takeaways
                                      •     The compiler generates a state machine for each nested async function. The state machine is a
                                            struct with a state variable and a closure environment. The state variable keeps track of the current
                                            state of the function. The closure environment stores the arguments and local variables of the
                                            function.

                                      •     The closure environment of the outer async function contains the closure environment of the inner
                                            async function. A large number of local variables and arguments can result in a notably larger
                                            closure environment.

                                      •     Even an async function with an infinite loop will return Poll::Pending when a future in the loop
                                            is pending. When the future becomes ready, the executor calls the function again, and the loop
                                            continues when the polled future returns Poll::Ready. The loop continues executing until it
                                            reaches a pending future. At this point, the function returns Poll::Pending. The executor will call
                                            the function again when the future becomes ready.

                         •            The execution of an async function does not commence immediately upon its invocation. Instead, the
                                      function returns a Future, representing a computation that will be completed later. The returned
                                      Future embodies the ongoing computation of the async function, which only begins when you await it.
                                      We saw this behavior in the Rust playground example.
