                                    Exploring Inner and Outer Loops in Function Application
                                    The following code defines a versatile apply_functions function. The role of this function is to accept an
                                    array of functions and apply each to every element of a given input array. As a result, the function produces
                                    a vector containing the outcomes of these operations.

                                    type GenFunction<T> = fn(T) -> T;

                                    fn apply_functions<T: Copy, const N: usize>(
                                        input: &[T],
                                        functions: &[GenFunction<T>; N],
                                    ) -> Vec<T> {
                                        input
                                            .iter()
                                            .map(|&item| functions.iter().fold(item, |acc, &f| f(acc)))
                                            .collect()
                                    }

                                    To better understand the code, we should examine the function signature first.
                                    The function takes a generic type argument, T, and a generic constant, N. It accepts two parameters: a slice
                                    of T and an array of functions, where the functions are of GenFunction<T> type. Finally, the
                                    apply_functions function returns a vector of type T that contains the results of applying each function to
                                    every element in the input array.
                                    There are two levels of iteration at work here:
                                      •    Inner Loop
                                      •    Outer Loop

                                    Part E Strings, Dispatch, and Recursion
                                    Inner Loop
                                    The inner loop iterates over the array of functions. It applies each function to the input item and returns a
                                    single result. The following code excerpt shows the inner loop:

                                    |&item| functions.iter().fold(item, |acc, &f| f(acc))

                                    Iter
                                    The inner loop uses the iter function to iterate over the array of functions. The fold operation will apply
                                    to each function in the array that the iter function returns.

                                    Fold
                                    The inner loop uses the fold function to apply each function to the input item. The fold function takes an
                                    initial value and a closure.
                                    The item is the initial value representing the item from the input array.

                                    |acc, &f| f(acc) is the closure passed to the fold. The closure takes two arguments: acc and &f. acc is
                                    the accumulator representing the result of the previous function application. The closure applies &f to the
                                    input item and returns the result of this application to the accumulator. The generated code applies the
                                    closure to each function in the array of functions.
                                    When the inner loop is complete, the fold function returns the result of applying all the functions to the
                                    input item.

                                    Outer Loop
                                    The outer loop goes through each item in the input array, using the map function to apply the inner loop to
                                    each item. This map function accepts a closure, representing the inner loop and acting on each item in the
                                    input array.

                                    The map function returns the mapped iterator. The outer loop returns a vector of results by calling
                                    collect on the output iterator returned from the map.

                                    Note that the map function is lazy and does not apply the inner loop to each item in the input array until
                                    the call to the collect function.

                                    The following code excerpt demonstrates the application of the outer loop to the input array via the map
                                    function:

                                    input
                                        .iter()
                                        .map(|&item| functions.iter().fold(item, |acc, &f| f(acc)))
                                        .collect()

                                    Optimizing an Array of Functions into a Single Polynomial

                                    apply_array function.

                                     Function        Polynomial Folded polynomial

                                     add_one         x+1        2x + 1
                                     multiply_by_two 2x         4x + 2

                                        Key Takeaways
                                    •    Rust enables the use of higher-order functions, bolstering its capabilities for functional
                                         programming. This feature allows developers to craft concise and expressive code without
                                         compromising speed. We observed that the compiler eliminates abstraction, yielding code as
                                         efficient as manually written for-loops.

                                           –     Our observation extended to the compiler’s ability to inline functions within the
                                                 FUNCTIONS_3 array while optimizing the inlined code by eliminating redundant operations.
                                                 These optimizations extended to the outer and the inner loop.
                                           –     Our study revealed that code written in a functional style matches the most optimized code
                                                 that one can manually write for the same problem. We demonstrated this in the experiment
                                                 comparing functional code with imperative code.
                                           –     Additionally, we noted that developers may write sub-optimal for-loops that perform worse
                                                 than the equivalent functional code. We illustrated this in the experiment comparing
                                                 functional code with imperative code.
                                    •    The Rust compiler generates efficient code for array processing. We saw that the compiler unrolled
                                         the loop and used SIMD instructions to process multiple elements in one iteration.

                                           –    We even observed that the compiler inlined all functions in the functions array and folded
                                                the operations into a single polynomial!
                                    •    Enabling the AVX-512 instruction set generates even more efficient code. With type Num = i16,
                                         the compiler generated AVX-512 instructions to process 16 i16 operations per instruction. The
                                         compiler completely unrolled the 1024 iteration loop!

                                    •    The compiler generates the most efficient code for processing arrays when it knows the array size
                                         at compile time. Compared to the apply_array function, the code generated for the apply_vec
                                         function demonstrated this. The apply_vec function is more complex as the compiler needs to
                                         select the efficient looping strategy at runtime. Also, adding a second vector to the function
                                         increases the complexity of the exception-handling code.
