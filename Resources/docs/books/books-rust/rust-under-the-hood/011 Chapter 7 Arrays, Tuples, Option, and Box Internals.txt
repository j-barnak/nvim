
                                                      Chapter 7
                                      Arrays, Tuples, Option, and Box Internals

                                    We have already seen how Rust handles enums under the hood. We also looked at the code generation for
                                    the Box smart pointer. Here, we put these items together in an example that describes how arrays, tuples,
                                    Option enum, and Box smart pointer allocations operate at the assembly level.

                                    Code Example: Arrays, Tuples, Option, and Box
                                    We will be dissecting the assembly generated for the following Rust code. The code contains the following
                                    functions:
                                      •   make_quad_coordinates is a function that takes an optional named tuple and returns an optional
                                          Box smart pointer containing four coordinates.
                                      •   cross_lines_from_quad_coordinates is a function that takes an optional named tuple and
                                          returns an optional tuple by value.
                                    type Num = f64;

                                    // A named tuple with two fields.
                                    pub struct Coordinate(Num, Num);

                                    // A named tuple that contains two named tuples.
                                    pub struct Line(Coordinate, Coordinate);

                                    // This function takes an optional named tuple and returns an optional
                                    // Box smart pointer containing four coordinates.
                                    pub fn make_quad_coordinates(maybe_coordinate: Option<Coordinate>)
                                                                       -> Option<Box<[Coordinate; 4]>> {
                                        // Check if the Option uses the Some variant. If it does, then extract
                                        // the contents of the tuple into x and y variables. If a None variant
                                        // is used, the function returns. The question mark is syntactic
                                        // sugar for matching and extracting from a Some and returning on None.
                                        let Coordinate(x, y) = maybe_coordinate?;

                                          // Create a new Box smart pointer containing four coordinates.
                                          // Note that this involves memory allocation on the heap.
                                          Some(Box::new([

                                                   Coordinate(x, y),
                                                   Coordinate(-x, -y),
                                                   Coordinate(-x, y),
                                                   Coordinate(x, -y),
                                             ]))
                                    }

                                    // This function takes an optional named tuple and returns an optional tuple
                                    pub fn cross_lines_from_quad_coordinates(
                                        maybe_coordinate: Option<Coordinate>,
                                    ) -> Option<(Line, Line)> {
                                        // Pattern match and extract the contents of the array if the Option
                                        // uses the Some variant. Return None if the Option uses the None
                                        // variant.
                                        let [a, b, c, d] = *make_quad_coordinates(maybe_coordinate)?;

                                             // Form two lines from four coordinates and return them as a tuple.
                                             // The tuple is wrapped in a Some variant.
                                             Some((Line(a, b), Line(c, d)))
                                    }

                                    Let us look at the code and the generated assembly for make_quad_coordinates and
                                    cross_lines_from_quad_coordinates.

                                    make_quad_coordinates: Memory Layout and Code Generation
                                    pub fn make_quad_coordinates(maybe_coordinate: Option<Coordinate>)
                                                                       -> Option<Box<[Coordinate; 4]>> {
                                        let Coordinate(x, y) = maybe_coordinate?;

                                             Some(Box::new([
                                                 Coordinate(x, y),
                                                 Coordinate(-x, -y),
                                                 Coordinate(-x, y),
                                                 Coordinate(x, -y),
                                             ]))
                                    }

                                    When we analyze the generated assembly code, be on the lookout for the following:
                                         •    Since the function returns a Box smart pointer, the assembly code allocates memory on the heap
                                              using the __rust_alloc function.
                                         •    If the heap allocation fails, the function throws an exception using a special instruction (ud2).
                                         •    Typically, Rust enums generate a discriminator value to select the variant. In this case, the Rust
                                              code generator optimizes the Option<Box> implementation by using the NULL pointer as the
                                              discriminator value.

                                    Understanding the Data Layout
                                    We will encounter the following data types in this function:
                                         •    Coordinate - a named tuple with two fields.
                                         •    Line - a named tuple that contains two Coordinate tuples.

                                      •    Box<[Coordinate; 4]> - a Box smart pointer that points to a heap-allocated array of four
                                           coordinates.
                                      •    Option<Coordinate> - an Option enum that may contain a Coordinate tuple.
                                      •    Option<Box<[Coordinate; 4]>> - an Option enum that may contain a Box smart pointer that
                                           points to an array of four Coordinates.

                                    Learning about the memory layout of various data types will aid in understanding the assembly code.

                                    Representation of Option<Coordinate>
                                    The Option<Coordinate> type has a memory layout where byte offset 0 is the discriminator,
                                    distinguishing between the Some and None variants. The Option<Coordinate> stores the Coordinate
                                    tuple in the following two entries.

                                     Byte offset None              Some
                                     0           Discriminator (0) Discriminator (1)
                                     8                             f64
                                     16                            f64

                                    Representation of Option<Box<[Coordinate; 4]>>
                                    There are two memory areas associated with the type Option<Box<[Coordinate; 4]>>:

                                      •    Option<Box> - a 64-bit pointer that points to the heap-allocated array of four Coordinate objects.
                                      •    [Coordinate; 4] - an array of four Coordinate objects. Each Coordinate object is a tuple of
                                           two f64 values.

                                    Let us look at the memory layout of the Option<Box> and [Coordinate; 4] types and then visualize the
                                    memory layout of the Option<Box<[Coordinate; 4]>> type.

                                    Option<Box> on the Stack

                                    The Rust code generator optimizes the Option<Box<>> type to a single pointer on the stack. The pointer is
                                    NULL if the Option variant is None. A non-zero pointer indicates that the Option variant is Some.

                                     Byte offset   None                      Some
                                     0             The Box pointer is NULL   The Box pointer contains a valid address that points to the heap.

                                    [Coordinate; 4] Array on the Heap

                                    The [Coordinate; 4] array is allocated on the heap. The array contains four Coordinate objects. The
                                    memory layout of the array follows. The Box pointer points to the first element of the array.

                                     Byte offset Content
                                     0           Coordinate
                                     16          Coordinate
                                     32            Coordinate
                                     48            Coordinate

                                    Flowchart for make_quad_coordinates
                                    The flowchart for the make_quad_coordinates function illustrates how the function checks the input
                                    Option discriminator early on. The function returns immediately if the Option is None. If the Option is
                                    Some, the function extracts the tuple’s contents and uses the Box smart pointer to allocate memory on the
                                    heap. The function then returns the Box pointer.

                                    Key points to note:
                                         •   The compiler uses vector instructions to load and store two f64 values simultaneously..
                                         •   The function will throw an exception if the Box allocation fails.
                                         •   The compiler uses the NULL pointer as the discriminator for the Option<Box> type, eliminating the
                                             need for a discriminator field.

                                    Before we dive into the assembly code, let us review the IEEE 754 floating-point standard.

                                       Learn More: IEEE 754 and the Sign Bit
                                    The Coordinate tuple comprises two f64 fields, each a 64-bit floating-point number. The representation
                                    of these floating-point numbers adheres to the IEEE 754 floating-point standard, which defines the
                                    following:

                                     Sign   Exponent     Fraction (Mantissa)
                                     bit 63 bit 62 to 52 Bit 51 to 0
                                     1 bit    11 bits       52 bits

                                    The critical point here is that floating-point numbers use a sign bit to define the sign of the number. The
                                    sign bit is the most significant bit. We will see in the assembly code that the generated code flips the sign bit
                                    of the f64 field to negate the number.

                                    Assembly Code for make_quad_coordinates
                                    The following assembly code for the make_quad_coordinates function includes annotations explaining
                                    the code.

                                         •      Input: rdi = Address of Option<Coordinate>

                                         •      Output: rax = Address of Option<Box<[Coordinate; 4]>>

                                    .LCPI0_0:
                                    .quad   0x8000000000000000            ; Constants used for flipping the sign bit..
                                    .quad   0x8000000000000000            ; ..of a 64-bit floating-point number.

                                    example::make_quad_coordinates:

                                    sub        rsp, 24                    ; Reserve space for local variables.

                                    cmp        qword ptr [rdi], 0         ;        Check if discriminator == 0 (None case)
                                    je         .LBB0_1                    ;        If discriminator == 0, jump to exit point.

                                    ;        Processing the Some case of Option

                                    movups     xmm0, xmmword ptr [rdi + 8]                ;       Get the 0ᵗʰ and 1ˢᵗ entry
                                                                                          ; from the Coordinate tuple via a
                                                                                          ; vector load (Note the 8-byte offset
                                                                                          ; is needed to skip the
                                                                                          ; discriminator)

                                    movaps     xmmword ptr [rsp], xmm0                    ;       Save it into the x and y
                                                                                          ; local variables on the stack.

                                           Allocating memory for Option<Box<[Coordinate; 4]>> involves reserving space for 4 array
                                    entries, with each entry requiring 16 bytes for the two f64 values, summing up to 64 bytes. It is important
                                    to note that there is no need for additional space for the Option discriminator; a NULL value (all 0s)
                                    indicates the None condition, while any non-zero heap address represents the Some condition.

                                    mov        edi, 64                                               ; Request 64-byte memory
                                    mov        esi, 8                                                ; Alignment is 8 bytes

                                    call       qword ptr [rip + __rust_alloc@GOTPCREL] ; Request memory allocation.
                                                                                       ; Allocation result in rax.

                                    test       rax, rax                        ;    Check if the memory allocation
                                                                               ; returned an all-zero address (NULL)

                                    je         .LBB0_5                         ;      If yes, jump to error handling code.

                                    movaps     xmm1, xmmword ptr [rsp] ;               Vector load x and y into xmm1

                                    movups     xmmword ptr [rax], xmm1 ;               Copy x and y to the heap

                                    ;          Load constants with the most significant bit set
                                    movaps     xmm0, xmmword ptr [rip + .LCPI0_0]

                                    xorps      xmm0, xmm1                          ; Flip the sign bits of x and y
                                                                                   ; to store -x and -y in xmm0

                                    movups     xmmword ptr [rax + 16], xmm0        ;         Vector copy -x and -y to heap

                                    movlps     qword ptr [rax + 32], xmm0          ;      Copy -x to the heap

                                    shufps     xmm1, xmm1, 78                      ;      Swap the x and y values in xmm1

                                    movups     xmmword ptr [rax + 40], xmm1        ;         Copy y and x to the heap

                                    pshufd     xmm0, xmm0, 238                     ;      Bring -y to lower 64 bits of xmm0

                                    movq       qword ptr [rax + 56], xmm0          ;      Copy -y to the heap

                                    add        rsp, 24                             ; Pop off the locals from the stack

                                    ret                                            ;            Return the result in rax

                                        Processing the None case of Option optimizes Option<Box> in Rust; it signals the None case by
                                    returning an all-zero (NULL) value to the caller, eliminating the need for a discriminator.

                                    .LBB0_1:

                                    xor        eax, eax      ;     Setting the lower 32 bits of rax to 0
                                                             ; Upper bits must be 0 to return an all-zero rax

                                    add        rsp, 24       ; Pop off the local variables

                                    ret                      ;      Return NULL to signal None

                                       Exception processing (memory allocation failed).

                                    .LBB0_5:

                                    mov        edi, 64         ; Size of the failed allocation (64-bit)
                                    mov        esi, 8          ; Alignment of the failed allocation (8-byte)
                                    call       qword ptr [rip + alloc::alloc::handle_alloc_error@GOTPCREL]
                                    ud2                        ;     Raise invalid opcode exception

                                    cross_lines_from_quad_coordinates: Inlining and deep
                                    optimization
                                    Let us look at the cross_lines_from_quad_coordinates function and the generated assembly code.

                                    pub fn cross_lines_from_quad_coordinates(
                                        maybe_coordinate: Option<Coordinate>,
                                    ) -> Option<(Line, Line)> {
                                        let [a, b, c, d] = *make_quad_coordinates(maybe_coordinate)?;
                                        Some((Line(a, b), Line(c, d)))
                                    }

                                    The assembly code for cross_lines_from_quad_coordinates gives us an unexpected result. Typically,
                                    we would think that when the make_quad_coordinates function returns a Box, it involves allocating
                                    memory on the heap. And since the function is supposed to use up the Box, we would also expect it to free
                                    up the heap memory before it finishes. But here is the surprising part: the generated code combines the
                                    make_quad_coordinates function directly into the main code and eliminates the need for the Box. Due to
                                    the inlining of the code, the compiler can skip both the memory allocation and deallocation steps.

                                    Representation of Option<(Line, Line)>
                                    Understanding the representation of Option<Line, Line> will assist in keeping track of the flow of the
                                    assembly code. The memory layout starts with the Option discriminator. A value of 0 indicates the None
                                    case. A value of 1 represents the Some case. The two Line structs follow the Some case. The Line struct is a
                                    tuple of two Coordinate structs. The Coordinate struct is a tuple of two f64 values.

                                     Byte offset None                 Some
                                     0            Discriminator (0) Discriminator (1)
                                     8                              tuple.0 First Coordinate (x): f64
                                     16                             tuple.0 First Coordinate (y): f64
                                     24                             tuple.0 Second Coordinate (x): f64
                                     32                             tuple.0 Second Coordinate (y): f64
                                     40                             tuple.1 First Coordinate (x): f64
                                     48                             tuple.1 First Coordinate (y): f64
                                     56                             tuple.1 Second Coordinate (x): f64
                                     64                             tuple.1 Second Coordinate (y): f64

                                    Flowchart of cross_lines_from_quad_coordinates
                                    By looking at the flowchart of the cross_lines_from_quad_coordinates function, we glimpse the deep
                                    optimization of the generated code. This flowchart reveals the inlined code of the
                                    make_quad_coordinates function, eliminating the Box allocation and deallocation. With the elimination
                                    of the Box, a memory allocation failure exception becomes impossible, leading to the removal of the
                                    exception handling code.
                                    The flowchart for the cross_lines_from_quad_coordinates function is simpler than the one for the
                                    make_quad_coordinates function it is supposed to call!

                                    Assembly Code for cross_lines_from_quad_coordinates
                                    Examine the assembly code using the flowchart blueprint.
                                    Key points to note in the assembly code:
                                      •    The make_quad_coordinates function is inlined.
                                      •    The compiler eliminates the Box allocation and deallocation.
                                      •    The function cannot throw an exception because there is no heap allocation.
                                      •    The caller of cross_lines_from_quad_coordinates is responsible for the memory allocation of
                                           the return value.

                                         •      The generated code uses vectorized instructions to operate simultaneously on two f64s.

                                             Input:

                                         •      rdi = Address of the return struct Option<(Line, Line)>
                                         •      rsi = Address of Option<Coordinate>

                                             Output: rax = Address of the return struct Option<(Line, Line)>

                                    .LCPI1_0:
                                    .quad   0x8000000000000000 ; Constants used for flipping the sign..
                                    .quad   0x8000000000000000 ; .. bits in a 64-bit floating-point number.

                                    example::cross_lines_from_quad_coordinates:

                                    mov               rax, rdi            ; Copy return address to rax

                                    cmp               qword ptr [rsi], 0 ;       Check if discriminator == 0 (None case)
                                    je                .LBB1_1            ;       If the discriminator is 0, jump to exit.

                                       Some variant in maybe_coordinate input. Note that the compiler has inlined the
                                    make_quad_coordinates function.

                                    movups            xmm0, xmmword ptr [rsi + 8]         ;       Vector load x and y from the
                                                                                          ; memory pointed by rsi

                                    movaps            xmm1, xmmword ptr [rip + .LCPI1_0] ;       Load the constant with
                                                                                         ; the most significant bit set

                                    xorps             xmm1, xmm0                          ; Negate x and y by toggling
                                                                                          ; sign bits
                                                                                          ; xmm1 now contains -x and -y.

                                    movups            xmmword ptr [rax + 8], xmm0         ;       Vector store x and y to
                                                                                          ; tuple.0 1st Coordinate(x, y)

                                    movups            xmmword ptr [rax + 24], xmm1        ;       Vector store -x and -y to
                                                                                          ; tuple.0 2nd Coordinate(x, y)

                                    Note that x86-64 byte ordering will write -x to the rax+24 address and -y to the rax+32 address.

                                    movlps            qword ptr [rax + 40], xmm1          ;       tuple.1 1st Coordinate (x):
                                                                                          ; -x written to memory.

                                    shufps            xmm0, xmm0, 78                      ;      Swap the x and y in xmm0

                                    movups            xmmword ptr [rax + 48], xmm0        ;       Vector store y followed by x
                                                                                          ; tuple.1 First Coordinate (y):
                                                                                          ; y written to memory.
                                                                                          ; tuple.1 Second Coordinate (x):
                                                                                          ; x written to memory.

                                    pshufd            xmm0, xmm1, 238                     ;      Bring -y to xmm0 lower 64-bits

                                    movq        qword ptr [rax + 64], xmm0             ; tuple.1 Second Coordinate (y):
                                                                                       ; -y written to memory.

                                    mov         ecx, 1                                 ;    Set the discriminator
                                                                                       ; for Some (32-bit write)

                                    mov         qword ptr [rax], rcx                   ;     Write discriminator to memory
                                                                                       ; (rax is the 64-bit register that
                                                                                       ; contains ecx)

                                    ret                                                ;       Return the result in rax

                                          None variant in maybe_coordinate input.

                                    .LBB1_1:
                                    xor      ecx, ecx                                  ;       None case (Discriminator = 0)

                                    mov         qword ptr [rax], rcx                   ;       Write the None discriminator

                                    ret                                                ;       Return the result in rax

                                             Key Takeaways
                                         •    The Rust compiler employs vector instructions to execute multiple operations in parallel, utilizing
                                              them for both floating-point and integer operations.
                                                 –    The compiler auto-vectorizes the code in the Rust release mode.
                                                 –    The compiler uses AVX-512 instructions when the target CPU is set to skylake-avx512.
                                                      AVX-512 settings enable the use of more modern instructions and wider registers. The
                                                      downside is that the code will not run on older CPUs.
                                         •    Rust’s inlining of functions is deep and can eliminate expensive heap allocations. We saw this in the
                                              cross_lines_from_quad_coordinates function.
                                         •    The compiler represents an Option containing a Box as a 64-bit pointer. The NULL pointer
                                              indicates the None case. A non-NULL pointer indicates the Some case.
                                         •    Rust functions throw exceptions on memory allocation failure. One must be careful when using
                                              smart pointers and types that allocate memory from the heap. We saw the exception handling code
                                              in the make_quad_coordinates function.
