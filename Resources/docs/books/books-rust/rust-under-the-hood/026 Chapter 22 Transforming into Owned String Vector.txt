
                                                       Chapter 22
                                          Transforming into Owned String Vector

                                    Welcome to the penultimate chapter of our book. This chapter extends the discussions from previous
                                    chapters, “Transforming into String Slice Vector” and “Vector Iteration in Assembly”. Our focus now shifts to
                                    vectors of owned strings. We will investigate how the compiler represents a vector of owned strings using
                                    two levels of heap allocation. Additionally, the chapter will address critical aspects like handling overflow
                                    and memory allocation failures in the output vector.

                                    Example Code: Map a Vector of bools to a Vector of Owned
                                    Strings
                                      •    The convert<A,B> function, a generic function that generates no code, takes a vector of type A and
                                           returns a vector of type B. It requires a closure that takes an element of type A and returns an
                                           element of type B. The function converts by calling the map function on the vector iterator.

                                      •    convert_bool_vec_to_owned_string_vec function uses the convert<A,B> function to convert
                                           a vector of bools to a vector of owned strings. The function accepts a vector of bools and returns a
                                           vector of owned strings. It calls the convert<A,B> function with a closure that converts a bool to a
                                           string.

                                    pub fn convert<A,B> (v: Vec<A>, f: impl Fn(A) -> B) -> Vec<B> {
                                        v.into_iter().map(f).collect()
                                    }

                                    pub fn convert_bool_vec_to_owned_string_vec(v: Vec<bool>) -> Vec<String> {
                                        convert(v, |n| (if n {"true"} else {"false"}).to_owned())
                                    }

                                    String Vector Generation Overview
                                    This section will give us a high-level view of the generated code for the
                                    convert_bool_vec_to_owned_string_vec function.

                                    Let us start by looking at the flowchart of the generated code.

                                    Let us look at the critical parts of the flowchart:
                                      •     Overflow and Memory Allocation Failure Handling for the Output Vector
                                      •     Preparing the Output Vector with Owned Strings
                                      •     Removing the If Condition for Checking the Boolean Value in the Input Vector

                                      •      Cleaning up the Input Vector on Exit from the Function

                                    Overflow and Memory Allocation Failure Handling for the Output Vector
                                    The code calculates the output vector’s size by multiplying the string’s size (24 bytes) by the number of
                                    entries. If there is an overflow in the size computation, the code will generate a panic and drop the input
                                    vector.
                                    The compiler generates code to handle the following scenarios:
                                      •      If the size calculation does not overflow, allocate an output vector of the required size.
                                      •      Should the allocation fail, trigger a panic and dispose of the input vector.

                                    Preparing the Output Vector with Owned Strings
                                    Loop through all entries in the input vector. For each entry:
                                      •      Allocate a new owned string.
                                                –    If the allocation fails, generate a panic and drop the input vector and previously allocated
                                                     strings.
                                                –    If the allocation succeeds, copy the string from static "true" or "false" to the heap-
                                                     allocated string memory. Set the capacity and length of the string to the length of the static
                                                     string ("true" or "false").

                                    Removing the If Condition for Checking the Boolean Value in the Input Vector
                                    The generated code removes the check for true or false from the loop body using the following
                                    techniques:
                                      •      Use the conditional move (cmove) to copy a pointer to static "true" or "false" into a register.
                                      •      Compute the length using an XOR between 5 (101 binary) and the bool value (0 or 1).

                                    Cleaning up the Input Vector on Exit from the Function
                                    The compiler generates a call to __rust_dealloc to free the input vector. Note that the function owns the
                                    input vector, so it is responsible for freeing the heap allocation for the input vector.

                                    Memory Cleanup Code
                                    The compiler must handle numerous corner cases and ensure memory cleanup in all scenarios. We will
                                    look at the cleanup code in this section.

                                    Deallocate a String Vector
                                    This function iterates through the vector and frees the string buffer. After the iteration, it deallocates the
                                    vector that held the now-deleted strings.
                                    The drop_in_place function deallocates the memory for a Vec. It does this by deallocating the memory
                                    for each element of the Vec and then deallocating the memory allocated to the Vec itself.

                                    An interesting thing to note here is that the compiler uses tail call optimization to avoid the overhead of the
                                    last __rust_dealloc call. The code jumps to the __rust_dealloc instead of making a call. The return
                                    from the __rust_dealloc function returns to the caller of the drop_in_place function.

                                       Input: rdi contains the address of the output vector.

                                    core::ptr::drop_in_place<Vec<String>>:
                                    push    r15
                                    push    r14
                                    push    r13
                                    push    r12
                                    push    rbx

                                    mov       r14, rdi                               ; rdi contains the address of the
                                                                                     ; vector that needs to be destroyed.

                                    mov       rax, qword ptr [rdi + 16]              ; rax contains the size of vector.
                                    test      rax, rax                               ; Check if vector size is 0.
                                    je        .LBB2_5                                ; Skip dealloc if size is zero.

                                    mov       r12, qword ptr [r14]                   ; r12 = pointer to first element
                                                                                     ; of vector

                                    shl       rax, 3                                 ; rax = size of the vector array in bytes

                                    lea       r15, [rax + 2*rax]                     ; r15 = three times the size of the
                                                                                     ; vector array in bytes.

                                    xor        ebx, ebx                            ; Set ebx to 0 to use it for calculating
                                                                                   ; the byte index of the vector array.

                                       r13 contains the pointer to the deallocation function. The code saves the address in the register to
                                    avoid fetching the address in a loop.

                                    mov        r13, qword ptr [rip + __rust_dealloc@GOTPCREL]

                                    jmp        .LBB2_2                             ; Jump to the deallocation loop.

                                    .LBB2_4:

                                    add        rbx, 24      ; Add the size of the vector array element.
                                    cmp        r15, rbx     ; Check if we have reached the end of the vector array.
                                    je         .LBB2_5      ; Reached the end of the vector array.
                                                            ; Break out from the loop.
                                    .LBB2_2:

                                    mov        rsi, qword ptr [r12 + rbx + 8]           ; Get the length of the string
                                                                                        ; buffer that needs to be
                                                                                        ; deallocated

                                    test       rsi, rsi             ; Check if the length is zero.
                                    je         .LBB2_4              ; Skip deallocation if the length is zero.

                                    mov        rdi, qword ptr [r12 + rbx] ; Get the pointer to the string buffer
                                                                          ; that needs to be deallocated.

                                    mov        edx, 1               ; Set the byte alignment to 1 byte.
                                    call       r13                  ; Call the deallocation function.
                                    jmp        .LBB2_4              ; Continue the loop.

                                    .LBB2_5:

                                    mov        rax, qword ptr [r14 + 8] ; Get the capacity of the vector array.
                                    test       rax, rax        ; Check if the capacity is zero.
                                    je         .LBB2_7         ; Skip deallocation if the capacity is zero.

                                    mov        ecx, 24              ; Set the size of the individual vector array
                                                                    ; elements to 24 bytes.

                                    mul        rcx                  ; Multiply the size of the individual vector array
                                                                    ; elements by the capacity.

                                    test       rax, rax        ; Check if the result is zero.
                                    je         .LBB2_7         ; Skip deallocation if the result is zero.
                                    mov        rdi, qword ptr [r14]    ; Get the vector array pointer.
                                    mov        edx, 8          ; Set the byte alignment to 8 bytes.
                                    mov        rsi, rax        ; Set the size of the vector array to rax.
                                    pop        rbx
                                    pop        r12
                                    pop        r13
                                    pop        r14

                                    pop        r15

                                    ; Tail call optimized deallocation function.
                                    jmp     qword ptr [rip + __rust_dealloc@GOTPCREL]

                                    .LBB2_7:

                                    pop        rbx
                                    pop        r12
                                    pop        r13
                                    pop        r14
                                    pop        r15
                                    ret

                                    Free the into_iter Owned Bool Vector
                                    The code created the Map iterator from a vector of bools and a closure that maps bools to owned strings.
                                    The drop_in_place function deallocates the memory for the Map iterator.

                                    core::ptr::drop_in_place<Map<IntoIter<bool>>:
                                    mov     rsi, qword ptr [rdi + 8] ; Get the capacity of the vector.
                                    test    rsi, rsi                 ; Check if the input vector is empty.
                                    je      .LBB0_1                  ; Skip deallocation if empty.
                                    mov     rdi, qword ptr [rdi]     ; Get a pointer to the input vector's
                                                                     ; data array.

                                       The following three lines set the alignment to 1 byte before the call to the deallocation function.

                                    mov        rdx, rsi ; Copy the input vector length to rdx.

                                    not        rdx         ; Invert the bits of rdx. The objective is to
                                                           ; set the MSB to 1.

                                    shr        rdx, 63     ; Shift the bits of rdx to the right by 63 bits.
                                                           ; This will set the register to 1.

                                       The code passes the following parameters to the deallocation function:

                                      •   rdi = pointer to the input vector’s data array.
                                      •   rsi = length of the input vector. rdx = alignment.
                                    ; Tail call optimized deallocation function.
                                    jmp     qword ptr [rip + __rust_dealloc@GOTPCREL]

                                    .LBB0_1:
                                    ret

                                    In-Place String Operations
                                    Add the following code to Compiler Explorer window. This code in-place converts a vector of strings to
                                    lowercase.

                                    pub fn in_place_string_replace(vec: &mut Vec<String>) {
                                        for text in vec.iter_mut() {
                                            *text = text.to_lowercase();
                                        }
                                    }

                                    To understand the generated assembly, let us look at the function signature of to_lowercase:

                                    fn to_lowercase(&self) -> String

                                    The function accepts a reference to self (a string slice &str) and returns a new String as the lowercase
                                    equivalent of the original string. It calls the to_lowercase function on each vector element within the
                                    in_place_string_replace function. This process returns a new String that the function then copies
                                    into the mutable vector passed to it. Consequently, each loop iteration allocates a new String and places it
                                    in the vector while dropping the original String stored in it.

                                    Here are a few interesting things to note in the generated code:
                                      •    To optimize performance, the compiler copies the address of the to_lowercase function to a
                                           register, thereby avoiding fetching the function’s address in each loop iteration.

                                           mov        r13, qword ptr [rip + alloc::str::<impl str>::to_lowercase@GOTPCREL]

                                      •    Every loop iteration calls __rust_dealloc to deallocate the memory allocated to the original
                                           String.

                                           call       qword ptr [rip + __rust_dealloc@GOTPCREL]

                                      •    The memory allocation for the new string is not seen in the code as the to_lowercase function
                                           handles it.

                                           Key Takeaways
                                      1.    Creating a vector of owned strings from a vector of bools results in two tiers of memory allocations.
                                            The first tier is the allocation of the vector of strings, and the second tier is the allocation of
                                            individual strings.
                                      2.    The program will panic if any of these memory allocations fail.

                                                                                              Chapter 22 Transforming into Owned String Vector
                                    3.   The program will also panic if the input vector’s length has overflowed.
                                    4.   When the program panics, it will free the memory allocated to the input and output vectors.
                                    5.   The compiler generates considerable code for error handling when allocations are involved. This
                                         code has performance and memory implications. For instance, the additional overflow checks may
                                         impact performance in the inner loop of a hot function.
