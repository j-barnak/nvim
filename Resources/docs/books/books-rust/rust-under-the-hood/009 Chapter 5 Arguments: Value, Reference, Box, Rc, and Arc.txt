                                    Method Receives Reference-Counted Smart Pointer Rc to Self
                                    Rust’s Rc (Reference Counted) smart pointer is a powerful tool for managing shared data ownership in a
                                    memory-safe and efficient manner. It allows multiple ownership of a value by keeping track of the number
                                    of references to it. Each time a new reference is created, the reference count increments, and it decrements
                                    when a reference is dropped. The code deallocates the value when the count reaches zero.
                                    Now, consider the magnitude_self_rc method. Here, the method passes an Rc smart pointer to self,
                                    which contains a pointer to the Complex object stored on the heap.

                                    pub fn magnitude_self_rc(self: Rc<Self>) -> f64 {
                                        (self.real.powf(POWER) + self.imaginary.powf(POWER)).sqrt()
                                    }

                                    The magnitude_self_rc method will share ownership to self. Multiple pointers to this object may be
                                    active in the same thread. When the method exits, it will decrement shared reference counts stored along
                                    with the Complex object. If this is the object's only reference, the object will be destroyed and released its
                                    memory to the heap; however, if the reference counts do not drop to zero, the object will continue to exist
                                    even after the method returns.

                                    pointer to self. Creating an Rc allocates a memory block on the heap to store the reference count and the
                                    data. The Rc places the reference counts at the beginning of the memory block and the data after the
                                    reference counts. The Rc smart pointer then points to this memory block on the heap.

                                         Learn More: Strong and Weak References
                                    The Rc (Reference Counted) smart pointer in Rust maintains two types of reference counts: strong and
                                    weak. The strong reference count tracks how many Rc pointers reference the same memory block. The
                                    weak reference count tracks the number of Weak pointers referencing that memory block.

                                    You use a Weak pointer to prevent reference cycles, which occur when two objects reference each other,
                                    creating a cycle that prevents their reference counts from reaching zero. This situation can lead to memory
                                    leaks because the objects will never be deallocated. By using a Weak pointer, you can break this cycle. The
                                    Weak pointer does not increase the strong reference count, allowing the memory block to be deallocated
                                    when no Rc pointers remain, even if Weak pointers still exist.

                                          Learn More:         Atomic Operations
                                    Atomic operations complete in a single step relative to other threads. No other thread can see the operation
                                    in a partly completed state, which makes them particularly useful for building multithreaded systems.
                                    AtomicUsize in Rust is an atomic unsigned integer type that provides atomic operations for use in a lock-
                                    free programming style. It includes several methods to manipulate its value atomically, such as fetch_add,
                                    fetch_sub, fetch_and, fetch_or, fetch_xor, load, and store.

                                    Special CPU instructions that guarantee atomicity typically implement these atomic operations at a low
                                    level.
                                    On the x86-64 architecture, the “lock” prefix with various instructions implements these operations. This
                                    prefix guarantees the atomic execution of the instruction, ensuring that the processor maintains exclusive
                                    access to the memory location until the instruction completes.

                                            Learn More:       Cow - Clone on Write
                                    The Cow type, a smart pointer, wraps either a borrowed or an owned value and helps avoid unnecessary
                                    allocations by providing immutable access. It will only lazily clone the value when mutation or ownership is
                                    required. It is an enum with two variants: Borrowed, which holds a reference to the borrowed value, and
                                    Owned, which stores the owned value. The Cow type also implements the Deref trait, enabling the treatment
                                    of a Cow value as a reference to the value it contains. Additionally, it implements the Borrow trait for both
                                    Borrowed and Owned variants, allowing the treatment of a Cow value as a reference to its held value.

                                    The following code shows the definition of the Cow type.

                                    pub enum Cow<'a, T: ToOwned + ?Sized> {
                                       Borrowed(&'a T),
                                       Owned(<T as ToOwned>::Owned),
                                    }

                                    In this definition:
                                        •      T represents the data type that can be borrowed or owned.
                                        •      ToOwned is a trait that specifies how to create an owned version from a borrowed reference.
                                        •      ?Sized is a trait bound that allows for types that do not have a constant size known at compile
                                               time.
                                        •      'a is a lifetime parameter representing the borrowed reference’s lifetime.

                                    A quaternion extends the concept of complex numbers into a four-dimensional number system. It
                                    comprises one real and three imaginary parts, typically represented as q = w + xi + yj + zk. Here, w,
                                    x, y, and z are real numbers, while i, j, and k are quaternion units.

                                        j: Num,
                                        k: Num,

                                         }

                                    Part C Data Structures and Memory Management
                                    Passing a &T Is Efficient
                                    In most scenarios, passing a reference will be more efficient than passing by value, as the compiler will not
                                    need to copy all the contents to the called function.

                                    Passing a Box<T> Will Result in Object Deallocation
                                    Passing a Box<T>will result in the deallocation of the object. If this is not the desired behavior, pass a &T or
                                    &mut T instead.

                                    Prefer Passing a &T over Rc<T> and Arc<T>
                                    The generated code demonstrates that passing an owned Rc<T> and Arc<T>introduces significant
                                    overhead. In scenarios where you do not expect sharing changes, we recommend passing a reference &T.

                                    The Reddit discussion (https://bit.ly/454rUPY) on the subject defines the following rules for Arc<T>:

                                         •   If a function always needs to own its copy of the Arc, pass Arc<T> directly by value. The caller can
                                             decide whether to clone or move an existing Arc into it.
                                         •   If a function seldom requires copying the Arc, using &Arc<T> can be sensible. This approach avoids
                                             the need for atomic operations in typical cases at the expense of the inability to move the Arc in
                                             rare instances.
                                         •   If the function just wants to read from the T, just pass &T.

                                    Consider the Memory Overhead of Rc and Arc
                                    On a 64-bit machine, Rc and Arc add a 16 byte overhead on the heap.

                                    Consider Cow<T> When You Need to Work with Borrowed or Owned Data
                                    Interchangeably
                                    We recommend using the Cow smart pointer when:

                                         •   You have a data structure that can be borrowed (&T) or owned (T).
                                         •   The data is potentially large or expensive to clone.
                                         •   You need the flexibility to work with borrowed or owned data interchangeably.
                                    By using Cow, you can avoid unnecessary cloning by leveraging the Borrow trait, which allows you to work
                                    with borrowed references when possible and automatically clones the data when necessary.
                                    Keep in mind that using Cow comes with some trade-offs. The choice between borrowing or owning can
                                    introduce runtime overhead. We explored these overheads in the Cow experiment. We saw that the
                                    compiler did check if the Cow object was owned or borrowed at runtime. It cleverly optimized the code to
                                    keep most of the logic independent of the ownership of the Cow object.
