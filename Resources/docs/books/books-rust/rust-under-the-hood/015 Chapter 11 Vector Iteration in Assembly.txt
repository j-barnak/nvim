
                                                                Chapter 11
                                                       Vector Iteration in Assembly

                                    Vectors are the most used collection type in Rust. This chapter will look under the hood to understand the
                                    assembly code generated for a vector iteration. We will see that the length of a vector plays a vital role in
                                    the runtime selection of the loop constructs used in the iteration. Finally, we will Experiment with Compiler
                                    Explorer to see how we can influence loop unrolling and vectorization of the loop.

                                    Vector Memory Layout
                                    Before we go any further, let us look at the memory layout of a vector. The definition of a vector follows.
                                    Vectors in Rust contain:
                                      •    A pointer to a heap vector buffer (buf.ptr).
                                      •    The capacity of the buffer (buf.cap).
                                      •    The length (len) of the vector.

                                    The vector’s buffer is a pointer to an array consisting of elements of type T. The capacity of this array
                                    defines its size, indicating the maximum number of elements it can accommodate without needing to
                                    reallocate the buffer. Meanwhile, the vector’s length specifies the current count of elements contained
                                    within the vector.
                                    The vector struct (Vec) is defined as follows. It contains a pointer to the heap-allocated buffer (buf) and
                                    the vector length (len).

                                    pub struct Vec<T, A: Allocator = Global> {
                                        // Points to the start of the vector data and keeps the capacity information
                                        buf: RawVec<T, A>,
                                        // Vector length
                                        len: usize,
                                    }

                                    The vector buffer is allocated using the RawVec struct. The RawVec struct contains a pointer to the heap-
                                    allocated buffer (ptr) and the buffer’s capacity (cap). The RawVec struct is defined as follows.

                                    struct RawVec<T> {
                                        // Points to the heap address that stores the vector data
                                        ptr: NonNull<T>,

                                          // Capacity of the vector
                                          cap: usize,
                                          _marker: PhantomData<T>,
                                    }

                                    Note: The _marker is 0-sized as it is of the PhantomData<T> type.

                                    The following figure shows the memory layout of a vector. The heap pointer (buf.ptr) points to the start
                                    of the vector buffer. In this example, the vector buffer contains three i64 integers. It has a length (len) of 3
                                    and a capacity (buf.cap) of 8.

                                    Sample Vector Handling Code
                                    Let us explore the Rust to assembly mapping of the Vec struct using a simple function, increment_by, that
                                    increments the elements of a vector by a specified value (num). The sample also includes
                                    increment_example that calls the increment_by function.

                                    // Increment each element of a i64 vector by num. A mutable
                                    // reference to the vector is passed in.
                                    pub fn increment_by(num: i64, list: &mut Vec<i64>) {
                                        // Iterate over the vector and increment each element.
                                        for item in list {
                                            // Note that the item needs to be dereferenced
                                            *item += num;
                                        }
                                    }

                                    pub fn increment_example(inc_by: i64, array: [i64; 4]) -> Vec<i64> {
                                        let mut list = array.to_vec();
                                        increment_by(inc_by, &mut list);
                                        list
                                    }

                                    Assembly Insights: Optimizations for Varying Vector Lengths
                                    The compiler optimizes the generated assembly code for the increment_by function to operate on vectors
                                    of various lengths. This section will examine the code’s overall flow and then delve into the details of code
                                    blocks optimized for different vector lengths. With this knowledge, we can comprehend the assembly code
                                    generated for the increment_by function.

                                    Arbitrary Length Handling Flowchart
                                    The following flowchart of the increment_by function provides a high-level view of handling vectors of
                                    arbitrary length.

                                    The preceding flowchart uses the following code blocks to handle vectors of different lengths.

                                      •     Vector Length Is a Multiple of 8
                                      •     Vector Length Is Equal to 4
                                      •     Vector Length Is Less than 4

                                    Vector Length Is a Multiple of 8
                                    The following code block handles vectors with a length that is a multiple of 8. The compiler unrolls the loop
                                    eight times and loads the vector elements into the SIMD registers. The code then increments the SIMD
                                    registers. Finally, the code stores back the SIMD registers in the vector buffer. Each SIMD instruction
                                    operates on two elements of the vector, so each operation in the loop results in four SIMD operations.

                                    Flowchart for Processing Eight Entries per Loop Iteration

                                    Now that we have looked at the flow for this code block, let us look at the generated assembly.
                                    For vectors with lengths that are a multiple of 8, the code handles eight 64-bit operations per iteration. The
                                    code copies eight 64-bit numbers to the xmm registers using four movdqu instructions. Four paddq
                                    instructions perform the eight additions needed in the loop. Finally, four movdqu instructions copy the
                                    results into the vector buffer.

                                    .LBB0_5:

                                    movdqu     xmm1, xmmword ptr [rcx + rsi]      ;                    Load the 1st & 2nd number
                                    movdqu     xmm2, xmmword ptr [rcx + rsi + 16] ;                    Load the 3rd & 4th number
                                    movdqu     xmm3, xmmword ptr [rcx + rsi + 32] ;                    Load the 5th & 6th number
                                    movdqu     xmm4, xmmword ptr [rcx + rsi + 48] ;                    Load the 7th & 8th number

                                    paddq      xmm1, xmm0                                    ;         Increment 1st & 2nd number
                                    paddq      xmm2, xmm0                                    ;         Increment 3rd & 4th number

                                    movdqu     xmmword ptr [rcx + rsi], xmm1      ;                    Store the 1st & 2nd number
                                    movdqu     xmmword ptr [rcx + rsi + 16], xmm2 ;                    Store the 3rd & 4th number

                                    paddq      xmm3, xmm0                                    ;         Increment 5th & 6th number
                                    paddq      xmm4, xmm0                                    ;         Increment 7th & 8th number

                                    movdqu     xmmword ptr [rcx + rsi + 32], xmm3 ;                    Store the 5th & 6th number
                                    movdqu     xmmword ptr [rcx + rsi + 48], xmm4 ;                    Store the 7th & 8th number

                                    add        rsi, 64                                       ;     Increment the loop index
                                    add        rax, -2                                       ;     Decrement the count as rax
                                                                                             ; keeps track of the number of
                                                                                             ; quad 64-bit numbers to process
                                    jne        .LBB0_5                                       ;     Jump if there are still quad
                                                                                             ; 64-bit numbers to process

                                    test       r10b, 1                                       ;     Check if there are still
                                                                                             ; entries to process
                                    je         .LBB0_8                                       ;     Jump if less than 4 entries
                                                                                             ; need to be processed.

                                          Learn More: Cache Line and Eight Times Unrolling
                                    The 8-times unrolling technique aligns with the cache line size of x86-64 processors. A cache line, the data
                                    transfer unit between the main memory and the processor cache, determines how the processor reads
                                    from and writes to the main memory. On x86-64 systems, the cache line size is 64 bytes. Consequently,
                                    each iteration of the “multiple of 8” loop reads and writes an entire cache line.
                                    Dig deeper into cache organization and cache lines in the Medium post:
                                      •      Why software developers should care about CPU caches (https://medium.com/p/8da04355bb8a)

                                    Vector Length Is Equal to 4
                                    The code block handling vectors of length 4 consists of two vector loads, two vector additions, and two
                                    vector stores, with each vector operation acting on two 64-bit numbers.

                                    Now that we have looked at the flowchart, let us look at the generated assembly code.
                                    Vector instructions perform two 64-bit operations in parallel. The movdqu instruction moves the vector
                                    data from the vector buffer to an xmm register. The paddq instruction adds the specified value to the vector
                                    data. The movdqu instruction moves the vector data back to the vector buffer.

                                    .LBB0_7:

                                    movdqu     xmm1, xmmword ptr [rcx + rsi]      ;       Load two 64-bit numbers
                                                                                  ; from the vector
                                    movdqu     xmm2, xmmword ptr [rcx + rsi + 16] ;      Load two more 64-bit
                                                                                  ; numbers from the vector

                                    paddq      xmm1, xmm0                                   ;       Add the increment value to
                                                                                            ; the first two 64-bit number
                                    paddq      xmm2, xmm0                                   ;       Add the increment value to
                                                                                            ; the 3rd and 4th of 64-bit number

                                    movdqu     xmmword ptr [rcx + rsi], xmm1      ;       Store the result back in
                                                                                  ; the vector (1st and 2nd number)
                                    movdqu     xmmword ptr [rcx + rsi + 16], xmm2 ;       Store the result back in
                                                                                  ; the vector (3rd and 4th number)

                                    Vector Length Is Less than 4
                                    When the vector length is less than 4, the compiler generates a loop that processes one entry per loop
                                    iteration. The flowchart for this code block follows.

                                    For vectors shorter than 4, the generated assembly code loops over each entry in the vector and increments
                                    it by the specified value.

                                    .LBB0_11:

                                    add       qword ptr [rax], rdi ;         Add num to the next
                                                                   ; entry in the vector

                                    add       rax, 8                        ;    Move to the next entry in the vector

                                    cmp       rax, rcx                      ;     Check if at the end of the vector
                                    jne       .LBB0_11                      ;     Jump if the vector's end has
                                                                            ; not been reached.

                                    Assembly Code for Handling Vectors of Arbitrary Length
                                    We have analyzed the specialized assembly blocks for >8, 4, and <4 cases. Let us look at the following code
                                    that handles vectors of arbitrary length. The complete code of the function combines the three code blocks
                                    to handle vectors of arbitrary size. For example, the code will handle a vector of length 39 as follows:

                                     Index Range       Total Entries    Iterations    Operations per Loop                    Assembly Label
                                     0-31              32               4             8 (4 sets of vector operations)        .LBB0_5
                                     32-35             4                1             4 (2 vector operations)                .LBB0_7
                                     36-38             3                1             1 per loop                             .LBB0_11

                                    Let us now look at the assembly code for the increment_by function that handles vectors of arbitrary
                                    length.
                                       •        Input:
                                              –    rsi = address of the vector

                                            –   rdx = increment value
                                    example::increment_by:

                                    mov         r9, qword ptr [rsi + 16] ;              r9 now contains length of vector
                                    test        r9, r9                   ;              Check if the vector is empty
                                    je          .LBB0_12                 ;              Jump to return if the vector is empty

                                    mov         rcx, qword ptr [rsi]               ;     rcx = address of the vector data
                                    lea         rax, [r9 - 1]                      ; rax = index of last entry in vector

                                    movabs      rdx, 2305843009213693951 ; Hex 1FFF_FFFF_FFFF_FFFF (3 MSB cleared)

                                    and         rdx, rax                           ;     rdx = index of the last entry in
                                                                                   ; vector with 3 MSB cleared.

                                    mov         rax, rcx                           ; rax = address of the vector data
                                    cmp         rdx, 3                             ;     Check if the vector length < 4
                                    jb          .LBB0_10                           ;     Jump if the vector length < 4

                                          Handle vectors with 4 or more entries.

                                    inc         rdx                     ;     Add 1 to the last entry index
                                                                        ; to get the length

                                    mov         r8, rdx                 ; r8 = number of items to be processed

                                    and         r8, -4                  ; Mask of the lower 2 bits to get the count
                                                                        ; of entries that are divisible by 4.

                                    movq        xmm0, rdi               ; xmm 0 = Parameter num, the increment value

                                    pshufd      xmm0, xmm0, 68          ;     Make a copy of num to the upper 64 bits to
                                                                        ; facilitate vector addition.
                                                                        ; 68 = 0100 0100 results in copying the lower
                                                                        ; 64 bits to the upper 64 bits.
                                                                        ; A reference with a detailed description
                                                                        ; follows the assembly code.

                                    lea         rax, [r8 - 4]           ; rax = 4 less than the number of items

                                    mov         r10, rax                ; r10 = 4 less than the number of items

                                    shr         r10, 2                  ; Divide r10 by 4 to get the index of the
                                                                        ; last quad 64-bit numbers.

                                    inc         r10                     ;     Add 1 to get the count of
                                                                        ; quad 64-bit numbers

                                    test        rax, rax                ;    Any more sets of 4 entries?
                                    je          .LBB0_3                 ;    Jump if no more sets of 4 entries

                                    mov         rax, r10                ; rax = count of quad 64-bit numbers
                                    and         rax, -2                 ; Mask of the lower 2 bits to get the count of

                                                                  ; quad 64-bit numbers that are divisible by 4.
                                    xor        esi, esi           ;     Set the quad 64-bit numbers index to 0

                                      Process eight 64-bit additions per iteration.

                                    .LBB0_5:
                                    movdqu xmm1, xmmword ptr [rcx + rsi]                      ;       Load 1st & 2nd numbers
                                    movdqu xmm2, xmmword ptr [rcx + rsi + 16]                 ;       Load 3rd & 4th numbers
                                    movdqu xmm3, xmmword ptr [rcx + rsi + 32]                 ;       Load 5th & 6th numbers
                                    movdqu xmm4, xmmword ptr [rcx + rsi + 48]                 ;       Load 7th & 8th numbers

                                    paddq      xmm1, xmm0                                     ;       Increment 1st & 2nd
                                    paddq      xmm2, xmm0                                     ;       Increment 3rd & 4th

                                    movdqu     xmmword ptr [rcx + rsi], xmm1                  ;       Store 1st & 2nd numbers
                                    movdqu     xmmword ptr [rcx + rsi + 16], xmm2             ;       Store 3rd & 4th numbers

                                    paddq      xmm3, xmm0                                     ;       Increment 5th & 6th
                                    paddq      xmm4, xmm0                                     ;       Increment 7th & 8th

                                    movdqu     xmmword ptr [rcx + rsi + 32], xmm3             ;       Store 5th & 6th numbers
                                    movdqu     xmmword ptr [rcx + rsi + 48], xmm4             ;       Store 7th & 8th numbers

                                    add        rsi, 64                                        ;     Move the index to the
                                                                                              ; next set of 8 numbers

                                    add        rax, -2                                        ;     Decrement the count by 2
                                                                                              ; as two quad 64-bit numbers
                                                                                              ; have been processed.

                                    jne        .LBB0_5                                        ;     Jump if there are still
                                                                                              ; quad 64-bit numbers to handle

                                    test       r10b, 1      ;       Check if there are still quad entries to process
                                    je         .LBB0_8      ;       Jump if less than 4 entries need to be processed.

                                      Block processing four 64-bit additions.

                                    .LBB0_7:
                                    movdqu xmm1, xmmword ptr [rcx + rsi]                      ;       Load next two entries
                                    movdqu xmm2, xmmword ptr [rcx + rsi + 16]                 ;       Load next two entries

                                    paddq      xmm1, xmm0                                     ;       Increment first two
                                    paddq      xmm2, xmm0                                     ;       Increment next two

                                    movdqu     xmmword ptr [rcx + rsi], xmm1                  ;       Store first two entries
                                    movdqu     xmmword ptr [rcx + rsi + 16], xmm2             ;       Store next two entries

                                    .LBB0_8:

                                    cmp        rdx, r8                      ;         Check if all entries have been handled

                                    je          .LBB0_12                        ;      Jump if all entries have been handled
                                    lea         rax, [rcx + 8*r8]               ;      rax = address of the last entry

                                    .LBB0_10:

                                    lea         rcx, [rcx + 8*r9]               ;    rcx = address of last entry in vector
                                                                                ; rax points to the first entry in the vector

                                          Process one 64-bit addition per iteration.

                                    .LBB0_11:
                                    add     qword ptr [rax], rdi                ;           Add num to the next entry

                                    add         rax, 8                          ;      Move to the next entry in the vector
                                    cmp         rax, rcx                        ;      Check if at the end of the vector
                                    jne         .LBB0_11                        ;      Jump if vector end has not been reached

                                    .LBB0_12:

                                    ret                                         ;      Return from the function

                                    .LBB0_3:
                                    xor      esi, esi            ;      esi is now 0

                                    test        r10b, 1          ;      Check if a set of quad 64-bit numbers is available

                                    jne         .LBB0_7          ;      Jump if quad 64-bit numbers are available

                                    jmp         .LBB0_8          ;    Jump if less than four 64-bit numbers
                                                                 ; are available

                                          Learn More: pshufd Instruction Shuffling Options
                                    The preceding code block uses pshufd, an instruction that shuffles the four 32-bit numbers in the source
                                    operand and stores the result in the destination operand. For an explanation of the pshufd shuffling
                                    options, refer to a stack exchange article (https://bit.ly/pshufd).

                                    Inlining, Loop Unrolling, and Memory Optimizations
                                    We have looked at the code generated for increment_by. Now, let us examine a call to the function from
                                    the increment_example function that calls increment_by with a vector of length 4.

                                    pub fn increment_example(inc_by: i64, array: [i64; 4]) -> Vec<i64> {
                                        let mut list = array.to_vec();
                                        increment_by(inc_by, &mut list);
                                        list
                                    }

                                    The generated assembly code for increment_example is much simpler than for the increment_by
                                    function. This simplification is evident from the absence of any call to increment_by. The compiler has
                                    inlined the relevant code from the function into increment_example.

                                      •       The compiler figures out that inlining the increment_by function would reduce a function call.

                                      •      Once the compiler decides to inline, it sees that the vector will only be of length 4. The compiler
                                             removes the logic for handling any arbitrary length vector. It optimizes the inlined code for a vector
                                             of length 4.

                                      •      The compiler also unrolls the loop to process four 64-bit additions.

                                    Also, note that the assembly code for increment_example calls __rust_alloc for allocating the vector
                                    data on the heap. If the memory allocation fails, the function throws an exception using the ud2 instruction.

                                    Another point to note is that the compiler must copy the data from the array into the newly created vector.

                                      •       Input:
                                            –    rdi = inc_by
                                            –    rsi = address of array
                                      •       Output:
                                            –    rax = address of vector
                                    .LCPI1_0:
                                    .quad   4                   ; Vector length
                                    .quad   4                   ; Vector capacity

                                    example::increment_example:

                                    push        r15                  ; Save r15 on the stack
                                    push        r14                  ; Save r14 on the stack
                                    push        rbx                  ; Save rbx on the stack

                                    mov         r15, rdx             ; r15 = address of the array
                                    mov         r14, rsi             ; r14 = inc_by
                                    mov         rbx, rdi             ; rbx = address of vector on the stack

                                          Allocate memory for the vector buffer

                                    mov         edi, 32              ; edi = number of 64-bit numbers to process
                                    mov         esi, 8               ; esi = byte alignment is at 8 bytes

                                    call        qword ptr [rip + __rust_alloc@GOTPCREL] ; rax = allocated address

                                    test        rax, rax             ;      Check if the allocation failed
                                    je          .LBB1_1              ;      Jump if the allocation failed

                                          Copy the array to the vector

                                    mov         qword ptr [rbx], rax                      ;      Store address of data buffer

                                    movups      xmm0, xmmword ptr [r15]                   ;         Load first two numbers
                                    movups      xmm1, xmmword ptr [r15 + 16]              ;         Load 3rd & 4th num

                                    movups      xmmword ptr [rax + 16], xmm1              ;         Store 3rd & 4th num
                                    movups      xmmword ptr [rax], xmm0                   ;         Store the first two num

                                    movaps      xmm0, xmmword ptr [rip + .LCPI1_0] ;                       Load length & capacity
                                    movups      xmmword ptr [rbx + 8], xmm0        ;                       Store length & capacity

                                          Increment the vector

                                    movq        xmm0, r14                               ;      Load the increment value

                                    pshufd      xmm0, xmm0, 68                          ;       The increment value is now
                                                                                        ; copied to the lower and upper
                                                                                        ; 64-bits of xmm0

                                    movdqu      xmm1, xmmword ptr [rax]                 ;       Load the first two numbers
                                                                                        ; from the vector

                                    movdqu      xmm2, xmmword ptr [rax + 16]            ;       Load the 3rd and 4th
                                                                                        ; numbers from the vector

                                    paddq       xmm1, xmm0                              ;       Add increment value to
                                                                                        ; the first two 64-bit numbers

                                    movdqu      xmmword ptr [rax], xmm1                 ;       Store the first two numbers
                                                                                        ; in the vector

                                    paddq       xmm2, xmm0                              ;       Add the increment value to
                                                                                        ; the third and fourth 64-bit numbers

                                    movdqu      xmmword ptr [rax + 16], xmm2            ;       Store the 3rd and 4th numbers
                                                                                        ; in the vector

                                          Return the vector

                                    mov         rax, rbx                ; Return the vector in rax
                                    pop         rbx                     ; Restore rbx
                                    pop         r14                     ; Restore r14
                                    pop         r15                     ; Restore r15
                                    ret                                 ;     Return the vector in rax

                                    .LBB1_1:

                                          Allocation failure handler

                                    mov         edi, 32         ; edi = Size of the attempted allocation
                                    mov         esi, 8          ; esi = Alignment is at 8 bytes
                                    call        qword ptr [rip + alloc::alloc::handle_alloc_error@GOTPCREL]
                                    ud2                         ; Use the ud2 instruction to throw an exception

                                           Experiment: Array Length Impact; AVX-512 Optimizations
                                    Let us experiment with the vector iteration example in Compiler Explorer
                                    (https://godbolt.org/z/q7G3nerPd).

                                    Array Length
                                    In the increment_example function, change array: [i64; 4] (line 11) and see how the compiler
                                    handles different array lengths:

                                      •    array: [i64; 128] - The compiler unrolls the loop even for 128 entries!
                                      •    array: [i64; 256] - The compiler generates an efficient loop that performs eight 64-bit
                                           additions in a single loop iteration.
                                      •    array: [i64; 257] - The loop performs 256 operations, and the code executes the remaining
                                           one outside the loop.
                                      •    array: [i64; 2048] - The generated code now uses memcpy to copy data from the input array to
                                           the vector’s data buffer.

                                    AVX-512
                                    Change the compiler options to use the AVX-512 instruction set using the flag setting (change in the edit
                                    box on the top right):

                                    -C opt-level=3 -C target_cpu=skylake-avx512

                                    The compiler generates code that uses the vaddq instruction to perform four 64-bit additions with a single
                                    instruction. Try out some array lengths:
                                      •    array: [i64; 256] - The compiler unrolls the loop even for 256 entries!
                                      •    array: [i64; 512] - The compiler generates an efficient loop that performs 32 64-bit additions
                                           in a single loop iteration. The code performs four operations in parallel using the vaddq instruction.

                                    Change Addition to Multiplication
                                    In the increment_by function, change *item += num to *item *= num (line 7) and see the dramatic
                                    impact on the generated code.
                                      •    The compiler does not optimize for different vector lengths. It generates a single loop that performs
                                           the multiplication.

                                    Impact of Passing an Array Slice
                                    Add the following function to Compiler Explorer code pane:

                                    pub fn increment_example_from_slice(inc_by: i64, array: &[i64]) -> Vec<i64> {
                                        let mut list = Vec::from(array);
                                        increment_by(inc_by, &mut list);
                                        list
                                    }

                                    You will see quite a few differences in the generated code.
                                      •    Because the compiler does not know the array slice’s length at compile time, it must generate code
                                           to handle vectors of arbitrary lengths.

                                      •    To support arbitrary lengths, the vector operations must handle the address overflow scenario,
                                           requiring the generation of code to manage capacity overflow.

                                      •    memcpy copies data from the input array to the vector’s data buffer.

                                          Key Takeaways
                                      •    When the compiler cannot determine the length of a vector at compile time, it generates code that
                                           conducts runtime length checks to select the most efficient code blocks for loop execution. We
                                           observed the compiler using the following code blocks to manage vectors of arbitrary lengths:

                                    Part D Iteration and Optimization
                                               –    A loop that processes eight elements per iteration.
                                               –    A code block dedicated to handling four elements.
                                               –    A loop for managing fewer than four elements.
                                      •     The “8 elements per iteration” loop is the most efficient code block, aligning with the x86-64
                                            architecture’s 64-byte cache line size. The compiler creates code that executes eight 64-bit
                                            additions in each loop iteration, effectively reading and writing a cache line per iteration.
                                      •     When the compiler knows the vector length at compile time, it can generate more efficient code by
                                            eliminating the need for runtime length checks to select the appropriate looping option. It can
                                            unroll the loop for a large number of iterations.
                                      •     When the vector comprises a multiple of 8 or 16 elements, the compiler can produce more efficient
                                            code, eliminating the need to generate code for handling residual elements (i.e., less than 8 or 16).
                                      •     Target a more recent CPU architecture to get more efficient code. The compiler can generate code
                                            that uses the AVX-512 instruction set to perform four 64-bit operations with a single instruction.
                                      •     Functions creating vectors can panic when the allocation fails. The compiler generates code that
                                            panics in such cases. We saw this in the section Inlining, Loop Unrolling, and Memory
                                            Optimizations.
