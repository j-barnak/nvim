B.2 Stack Frame Layout (Stack Contents After Exception Stacking)
Table B.2 describes the layout of a stack frame in the stack memory after an exception
stacking sequence is carried out. This information is useful for extracting stacked data
within the exception handler.

684 Appendix B

                    Table B.2: Stack frame layout after exception stacking

                    Address                  Data
                    (N+36)                   (Previous stacked data)
                    (N+32)                   (Previous stacked data/padding)
                    (N+28)                   Stacked xPSR
                    (N+24)                   Stacked PC (return address)
                    (N+20)                   Stacked LR
                    (N+16)                   Stacked R12
                    (N+12)                   Stacked R3
                    (N+8)                    Stacked R2
                    (N+4)                    Stacked R1
                    New SP (N) ->            Stacked R0

Depending on the Stack Pointer (SP) value before the exception has taken place, the previous
SP can be either the new SP value plus 32 or the new SP value plus 36: If the previous SP was
aligned to a double-word aligned address boundary, then the previous SP is new SP + 32.
Otherwise, a padding word would be allocated before stacking and therefore the previous SP
is new SP + 36.
